# 高频预设与三窗口验证

2026-10-29。默认业务中心1989.5→2179.5 MHz，第二方案1990.5→2180.5 MHz。GUI采用统一预设，仍使用既有实验BPSK业务；不把频率范围一致当作NR NTN协议符合性。

## 软件边界

发送、接收和改频窗口保留浅色布局。发送/回信默认衰减55 dB；计划与实际设备回读分开，编辑不触发收发。在线改频仅接受两个成对预设；交叉组合、浮点本振和任意整段频率不会放行。旧频点仅保留给历史工具与回归。

业务中心减0.5 MHz得到源和转发RX本振；转发TX本振为输出中心减0.5 MHz，接收LO为输出中心加0.25 MHz。真正测控的上行100.5 MHz、回报90.5 MHz不随业务改频改变。GUI只打开各自本地SDR，不打开遥控板或转发板管理口。

## CRC候选计数复核

最初60 dB和55 dB轮次按“CRC拒绝数必须为0”验收，被原始计数中止；随后50 dB轮次在低频基线也出现相同计数。原始结果和失败标志保留。

逐位复核发现，三次停止原因均为AAAA同步字提前2位的重叠候选。其长度误读为136字节，而随后真实33字节帧连续通过CRC。无噪声、无硬件的确定性测试也复现同样现象；因此此前将拒绝数直接解释为电平裕量不足的推断不成立。

解码器现增加拒绝候选位置和帧头重叠标记，原始拒绝计数、有效帧、载波恢复和定时选择保持不变。前三轮16份原始采样重解时，所有已有字段均与原记录一致。界面改称“CRC候选拒绝”，详情列出重叠数量；不将拒绝数量换算为BER或实际坏帧数。故意破坏CRC的独立测试仍被拒绝，且不标为帧头重叠。

修正后的台架验收逐一核对：正例的目标RX2通道每窗至少3个连续的正确循环帧，文本/消息编号一致；首尾完整帧覆盖与采样边界一致；该正例通道的拒绝候选仅限已定位的帧头重叠；样本无削顶。非目标RX1及停发负例必须无有效文本；噪声中随机匹配到、随后CRC拒绝的候选仍保留。该判据在新一轮采样前写入脚本，没有改写早期结果。

## 真实射频遥控阶段的边界

软件已接受两组高频指令，合成测试覆盖ADC_NORMAL回报匹配与拒绝测试来源，但这些是软件测试。本轮业务接线中遥控板J5/J6没有SMA，**高频ADC_NORMAL→UDP→DAC闭环尚未实测**，不能用上述UART_NETTEST记录替代。

下一步将两根反向业务线改接网关TX1A→遥控板ADC1/J5、遥控板DAC1/J6→同一网关RX1A。保留LDSDR TX1→终端RX1A、网线和USB；换线需在上述静音状态下由操作者完成并确认。然后在GUI提交高频指令、核对新鲜射频回报、匹配ACK和独立SPI；保留设置后再换回业务输入验证文本。全系统六线并发仍属后续阶段。
