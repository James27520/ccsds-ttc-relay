# 双向业务同时收发验证

日期：2026-10-31。**现有终端及LDSDR两路业务链能够并行收发；原解调器逐窗表现、USB稳定性和常驻接收GUI尚未验收通过。** 本轮未改GUI、未下载新固件、未移动六根SMA，未接天线。[分项摘要](validation/2026-10-31-duplex.json)的硬件能力字段为通过，整体验收字段保留未通过。

## 工作点与方法

| 项目 | 本轮设置 |
| --- | --- |
| 正向 | 终端1 TX1A → LDSDR RX1/TX1 → 终端2 RX1A |
| 反向 | 终端2 TX1A → LDSDR RX2/TX2 → 终端1 RX2A |
| 两方向业务中心 | 输入1999.5 MHz，输出2189.5 MHz |
| 终端本振 | TX 1999 MHz，RX 2189.75 MHz |
| LDSDR本振实际读回 | RX 1998999998 Hz，TX 2189000000 Hz |
| 采样与调制 | 2.5 MSPS；100 ksym/s实验BPSK文本帧、G1消息编号、CRC16 |
| 终端电平 | TX衰减55 dB，RX手动增益30 dB |
| 转发板电平 | 双路TX衰减50 dB，RX增益30 dB |

每块终端由一个串口会话管理，沿用30秒板端停发保护。转发板由真实射频测控、遥控板ADC解码及UDP命令开启，保留300秒租期，COM13仅作独立状态/SPI核对。两端发送不同的新文本；接收器先独立解码各自的原始IQ，完成后才比较正文和消息编号。

## 结果

| 测试 | 终端1实际接收 | 终端2实际接收 | 判定 |
| --- | --- | --- | --- |
| 先发射，再同时采集 | 80/80窗口有效，223个CRC正确帧 | 80/80窗口有效，223个正确帧 | 双向实收通过，共同收发区间估算约0.895秒 |
| 只停终端1发射 | 8/8窗口有效，23个正确帧 | 8个窗口均无有效帧 | 两方向独立，未将本机发送内容当作接收 |

| 上一行终端2相同IQ的离线频偏细化 | 原结果不变 | 80/80窗口有效，223个正确帧 | 候选通过，尚未接入生产解调器 |

第一轮每端保存1.048576秒完整并行采样。第二轮每端同一RX进程采集41943040个复数样点，名义16.777216秒；TX启动时RX进程编号保持不变，252/254条轮询状态中未发现RX DMA中断，共同TX/RX区间估算约9.582秒。串口配置与保护检查耗时约7.18/7.28秒，不代表以后界面的瞬时发送延迟。

第二轮仅把末尾1.048576秒/每端复制到电脑并逐窗解码，其余采样保留在板端RAM，记录整份160 MiB文件SHA256，不计入解码通过数量。时长按样点数和采样率换算，重叠区间按轮询状态及主机/板端时钟区间估算，不是逐样点时间戳或无DMA溢出的专项证明。

正确帧的正文和消息编号均匹配对端本轮新消息。帧数含循环重复，两轮共4条不同消息，不能据此计算消息交付率或BER。采样削顶分量为0，转发板累计clip保持303，本轮增量0；启动已有的303未清除，其来源仍未解决。

## 未完项与失败记录

原解调器在第二轮终端2第9、14、25、35、43号窗口没有恢复有效帧，原严格测试保持失败。离线候选在平方律频偏估计之后增加−120至+120 Hz、步长20 Hz的有限搜索，用CRC选择结果，不输入已知正文；80个正例窗口均恢复对端消息，另10个无信号窗口保持0帧。候选223帧是原94帧的替代分析，不能相加，接入在线软件前还需专项回归。

终端2 COM18在收尾及停发后的高速下载中曾从Windows设备列表消失，单端取数也复现。恢复后Linux启动ID/IIO身份不变，采样仍在；恢复工具逐块保存并校验完整SHA256，每次重连检查身份、TX关闭和DMA空闲，只重试读取已有数据，不重试发射。USB链路仍未通过，尚未确定是线缆、电脑端口、供电还是驱动问题。

脚本另保留三次失败：状态路径模板错误、最初8.39秒窗口不足、160 MiB哈希超过默认等待时间。分别修正模板、扩大有限采集窗口、将哈希移到停发后进行，未删失败记录，也未放宽原解调器逐窗判据。
