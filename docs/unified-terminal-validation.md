# 统一终端后台与持续接收

日期：2026-10-31。六根SMA接线未动，未写Flash或SD卡。两块地面终端通过同一套生产后台完成双向文本、真实测控占用和业务接收恢复。页面布局及回调经过自动化测试和桌面检查；本轮硬件事务由后台验收脚本调用，不能写成全部通过GUI鼠标操作完成。

下方主体保留统一后台各轮结果和当时行为。晚间补测已通过实际GUI双向文本、真实测控及两条排队文本自动发送，见文末“GUI收发恢复与角色核对”；之前的USB和启动失败记录保留。当前操作以[地面站说明](../sw/ground_station/README.md)为准。

## 本轮改动

- 每块终端只有一个串口持有者。终端1通信、测控共用后台；终端2独立。页面关闭与设备断开分开处理，关闭闲置测控页不会停止业务发送。
- 连接即启动板端接收进程。业务发送保留同一个接收进程，停止发送不会停止接收；没有“切换到发送/接收”或“开始接收”按钮。
- 测控暂时停发、暂停业务接收，使用TX2A/RX1A完成100.5/90.5 MHz事务，随后恢复业务接收。旧文本不会自动重发。取消、失败和关闭时清除旧发送队列。
- 两个通信页面仅负责本地连接、文本发送、实际接收与记录，频率只读。测控页负责远端频率、开启/停止、查询及实际射频回报，不再单独占用设备连接。
- 确认的频率计划同步到同进程终端2。相同计划不重启接收。跨电脑计划同步尚未实现，不把本机共享会话当作两台电脑间的同步服务。

## 接收实现及界限

原先DEBUG串口搬运整段IQ无法承担2.5 MSPS常驻接收。现在`iio_readdev`连续供样给ARM原生解码器，电脑只读取有界的CRC帧列表及统计。保留既有平方律载波恢复、两极性判决和G1格式，没有引入之前试验性的残差频率扫描修补。

冻结的ARM程序为53,852字节，SHA256为`1be62e06dd2469de5e385efd94106464f026f2131573c4c431264311b2153a61`。源码、静态可执行文件、构建参数及摘要位于[stream_rx](../board/terminal/stream_rx/README.md)。支持32字节UTF-8正文，连同G1头共49字节负载。它使用NEON、持续滤波与重叠窗口，跨窗口帧由CRC确认并去重。

两板独立运行基准的稳态采样处理速度跟随2.5 MSPS输入。组合测试中已有统计窗口的累计平均速度下界分别为2.489、2.453 MSPS，包含启动时间；最大窗口解码耗时分别为28.743、30.420毫秒，小于57.344毫秒窗口步长。接收削顶计数均为0。吞吐不足、进度停滞、异常退出、近期幅度超限及发送保护异常都会转为明确错误状态。

原始流没有硬件样点序号，不能据此宣称零丢样、零误码或长时间可靠性。CRC循环帧数也不等于不同消息数量。第一版离线Python解调器的逐窗漏检仍保留在[先前报告](duplex-business-validation.md)，没有把新接收器的结果回填成旧版本通过。
