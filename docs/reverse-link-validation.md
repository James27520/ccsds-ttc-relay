# 反向业务与第二通道验证

本阶段沿用已验证的正向业务、有限租期转发固件及实验文本协议。先验证原接收板的发射能力和原发送板的第二接收通道，再将LDSDR第二路接入中间。临时直连用于隔离端点故障，不是最终六线系统中的一条链路。

## 当前资源核对

2026-10-29，两块地面SDR在各自当前启动会话中均读回`adi,2rx-2tx-mode-enable=1`，RX与TX都提供四个scan元素。RX为`le:S12/16>>0`，TX为`le:s16/16>>0`，索引0～3。四个数字元素分别构成两路I/Q，不是四套独立射频收发机。软件身份不用于推断实物芯片的精确料号或全部可用频段。

厂商7010_AD9363_SDR原理图第15页将JP1/JP2/JP3/JP4分别接到TX1A/RX1A/TX2A/RX2A；LDSDR原理图第4页将RX2/TX2接到芯片RX2A/TX2A。部分中间网络仍名为RX1BN/TX1BN，须沿线检查到芯片，不能据名字把物理第二路认作第一路的B端口。

LDSDR保持原RAM镜像，未加载新PL。只读JTAG核验得到`0x43C00010=2`，`0x2C～0x3C`均为0；只能说明当前读回，不证明本地某个工程就是活动位流来源。

相邻旧`relay_udp_work/IoT-NTN-FPGA-Relay/rtl/relay_dq.v`含RX2→TX2数据路径，但两路共用mode、增益和NCO。另一份`LDSDR_010`工程含独立第二路寄存器及历史实现产物，其第二路默认值为`0x2001`，与上述实板读回不同。现有有限租期PS只写第一路mode寄存器；若以后迁移到独立第二路PL，必须同时扩展安全启动、静音、到期、故障与回报，不能直接替换位流后宣称两路均受保护。

## 四scan采集工具

新增[rf_channel_probe.py](../sw/tools/rf_channel_probe.py)，复用现有串口会话绑定、长度/SHA校验、波特率恢复和文本解码器。每次采集32768个四元素样点，共262144字节；严格按`I1,Q1,I2,Q2`拆成两份131072字节的I/Q。两路分别盲解码，不根据已知发送内容或信号强弱挑选通道。

工具只开放当前端点测试的RX LO 901.75 MHz及经转发测试的1000.75 MHz，固定2.5 MSPS、3 MHz带宽，双路手动增益0/20/30 dB。配置和采样前后检查当前设备身份、实际频率与通道格式、TX关闭和DMA空闲；异常清理只操作本次记录的PID及启动时间，不停止未知进程、不启发TX。调用者负责取得端口锁。

13项离线测试覆盖通道/符号位拆分、非法格式与配置、已有发射和DMA拒绝、配置漂移、下载时TX变化及本次采集进程清理。运行：

```powershell
python -B -m unittest sw.tools.test_rf_channel_probe -v
```

## 直连端点实测

2026-10-29，用户将终端TX1A直连网关RX2A后，使用当前Linux启动会话测试。发射本振读回900999998 Hz、波形偏移500 kHz；网关RX本振901750000 Hz、双路手动增益30 dB。LDSDR全程静音，遥控板执行计数未变。

| 条件 | RX1正确帧 | RX2正确帧 | RX2 RMS（码值） |
| --- | ---: | ---: | ---: |
| 开始前停发 | 0 | 0 | 2.105 |
| 65 dB衰减，反向端点验证 | 0 | 3 | 4.902 |
| 65 dB衰减，终端返回 ACK 29 | 0 | 3 | 4.897 |
| 结束后停发 | 0 | 0 | 2.102 |

两条文本和各自消息编号一致，RX2估计载波约901.499874 MHz，所有采样无削顶。四份原始四元素采样独立重解码得到6个CRC正确帧，收尾四板停发/静音。每份样点窗口为13.1072 ms，不作为连续误码率或整段帧交付率的证据；RX1对照也不是校准过的射频隔离度测量。

首轮70 dB衰减虽在RX2恢复3帧，但RX2/RX1原始RMS差仅4.959 dB，未达到该轮预设的6 dB判据，因此保留为失败轮次。第二轮以65 dB重新测试，差值8.636 dB并通过；没有降低判据或将首轮计入通过统计。

详见[机器可读摘要](validation/2026-10-29-reverse-endpoint.json)。完整证据位于本机`D:\RelayTools\releases\reverse_endpoint_20261029.zip`，SHA256为`48561ed8e9106cbce3c34b2ccc386a45e75d6929a598ed132415cd125f0e7ce0`。包含两轮原始采样、命令记录、发送清单、独立重解码及源文件快照；未改写固件或启动介质。

该结果只确认当前工作点的终端TX1A和网关RX2A。随后接入LDSDR的验证如下。

## LDSDR第二路实测

用户确认接成终端TX1A→LDSDR RX2、LDSDR TX2→网关RX2A。第三根LDSDR TX1→终端RX1A保留，但终端没有运行接收DMA；原正向输入线被借用，遥控板J5/J6均不接同轴。沿用原RAM固件和本振，不加载新PL或PS。

源端中心约901.5 MHz，发射衰减60 dB；LDSDR实际RX/TX本振900999998/1000000000 Hz，开启时双路接收增益30 dB、发射衰减50 dB。网关RX实际本振1000749998 Hz、双路增益30 dB。所有接收数据均来自网关四元素采集，盲解两路后再比较发送内容和编号。

| 条件 | RX1正确帧 | RX2正确帧 | RX2 RMS（码值） |
| --- | ---: | ---: | ---: |
| 初始停发、转发静音 | 0 | 0 | 2.092 |
| 反向经过转发板 | 0 | 3 | 2.651 |
| 电脑2返回 29号确认 | 0 | 3 | 2.631 |
| 源停止、转发仍开启 | 0 | 0 | 2.427 |
| 源保持发射、远端执行停止 | 0 | 0 | 2.099 |
| 收尾全部停发/静音 | 0 | 0 | 2.078 |

两条文本共6个CRC正确帧，编号分别为`e329cafe:0000`、`e329cafe:0010`；实际估计输出载波1000.499859/1000.499862 MHz，与预期1000.5 MHz相符。6份原始四元素采样独立重解码一致，接收样本无削顶；7个阶段及独立收尾审计的PL削顶计数均为55363007。源端保持发射的负例在采样前后均读到TX LO开启，排除了因源端限时停发而误判远端停止有效。

5笔开启/停止均经遥控板`UART_NETTEST`→UDP→匹配ACK，并核对LDSDR SPI的双路增益、衰减与实际本振；本轮没有ADC空口指令。源端每次保留30秒板端保护，转发开启租期120秒，均主动停止收尾。停止操作包含数字mode、双路增益及衰减的组合变化，本轮不单独归因于某一个寄存器。

详见[第二路转发摘要](validation/2026-10-29-reverse-relay.json)。完整证据位于本机`D:\RelayTools\releases\reverse_relay_20261029.zip`，SHA256为`3c7bfc2bc7076601bf1dd3628041d324533657b6b51348f01681fa6af35b821e`。原始记录中准备阶段TX为89 dB，摘要另从启发日志核对发射时实际60 dB，两个阶段分别记录。

本轮确认单一反向业务方向可通过LDSDR第二路，不是双向业务同时运行、独立第二路控制或六线并发验收。现有V2业务GUI仍使用正向通道，反向操作尚需接入界面。

## 六线方案中的后续路径

反向业务为：终端TX1A → LDSDR RX2 → 第二路转发 → LDSDR TX2 → 网关RX2A，共两根同轴，当前工作点已通过上述实测。两块端点板仍分别是前期的“独立接收板”和“原发送板”。正向能力、临时直连和经过LDSDR第二路的结果分别记录，不互相替代。

同一SDR的两路RX共用RX LO，两路TX共用TX LO，参见[ADI AD9361数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/AD9361.pdf)。因此第二路也服从同一个接收本振与发射本振；新增接口不能直接解决100.5 MHz测控与901.5 MHz业务的同时发射冲突。六根线定义功能连接，固定接线后的分时方案、第二路独立控制和完整并发仍须按[系统计划](six-link-system-plan.md)逐项完成。
