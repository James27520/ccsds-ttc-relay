# 远端启停、状态回报与超时静音验证

日期：2026-10-29。本轮新增遥控启停和查询协议、LDSDR 有限租期固件、遥控板处理与 ATM2 回报、地面站操作和状态显示。软件回归、RAM 加载、真实板间 UDP 及发送准备削顶隔离完成后，已继续通过新增查询、开启和停止操作的 **ADC_NORMAL → UDP → DAC → GUI 有线射频闭环**。业务输入仍未接回，新固件完整文本收发另行验收。

## 实现与兼容

线格式见[协议约定](remote-relay-control.md)。旧 8 字节改频正文和金标准向量保留，新增 `21/22/23` 分别表示开启、停止、查询。开启只核对当前 LO，不暗中改频；空口配置固定为 mode1、两路增益 30 dB、衰减 50 dB、300 秒租期。停止恢复 mode2、两路增益 0 dB、衰减 89 dB。查询只读，不续租。

板间新增 34 字节命令和 50 字节 ACK；ATM2 增加实际模式、双路电平、剩余租期、转发板 uptime 和故障标记。所有显示值来自匹配回报，未收到有效回报不能用请求值填充。负 ACK 保留失败证据，成功计数不增长。旧 TM1 文本输出只呈现成功 ACK，遇到新协议失败记录时输出无效空 ACK，完整失败详情保留在 ATM2。

新 LDSDR 固件在执行旧改频命令前取消租期并静音，执行后仍保持 mode2；与旧固定镜像“恢复原模式”的行为不同。新固件拒绝绕过租期的 CLI 开启和电平写入。启停、查询仍由独立遥控命令触发，改频成功不等于业务已开启。电脑1控制窗口只连接本地发送板，业务窗口不使用隐藏的板端管理串口。

相同事务重传不重新执行、不续租；序号冲突、旧序号和回卷拒绝。板端以 64 位时钟检查租期，到期先关闭 PL 输出，再设衰减和增益并核对。静音失败锁存，禁止再开启。当前实现是有界裸机轮询，不是独立硬件看门狗；CPU 停止或外设调用卡死时的保护不在已验证范围。协议也没有认证或掉电持久防重放。

本节经遥控板诊断命令 `remotenettest` 发出，来源明确为 `UART_NETTEST`，不是 ADC_NORMAL。两板以网线直连；独立 SPI 核验另由台架执行，不是 GUI 隐藏操作。两板保持实际本振约 `900999998 / 1000000000 Hz`。

| --- | --- |
| 查询 | 回报 mode2，RX1/RX2 增益 0/0 dB，TX1/TX2 衰减 89/89 dB，剩余 0 |
| 开启，10 秒租期 | ACK 剩余 9999 ms；mode1，双路增益 30 dB、衰减 50 dB；独立 SPI 一致 |

## 削顶隔离与修复

PL 的累积 `clip` 计数包含数字处理链，不能直接解释为 ADC 输入满量程。此次保持源端 TX LO 关闭、DMA 空闲、DDS 清零、89 dB 衰减，只比较射频属性读取和写入对远端计数的影响。

1. 16 步隔离包含接收增益 0/30 dB、只读跳过与强制写入相同 LO/采样率/带宽/端口。8 个只读跳过步骤均无增量；增益 0 时强制写入也无增量；增益 30 时强制写入相同 2.5 MSPS 引起 `+432591`。该轮完整通过并清理。
2. 实际切换采样率、带宽时，增益 30 下继续出现增量，0 dB 下没有；本轮切换 LO 未见增量。切换实验最后的清理调用遇到只读接口写入门禁，整轮保留为失败记录；之后独立四板核验确认静音及参数恢复。不能删除失败记录后称为整轮通过。
3. 发送准备现先真实读回 LO、采样率、带宽和端口，相符时不重复写入；需要变更时仍走已校验的写入和停发检查。实板以 mode1、增益 30 dB、衰减 50 dB 做一次文本波形准备和上传，未开启源端发射；耗时 `6.450 s`，`clip` 前后均为 `55363007`，增量 0，清理通过。

结果支持“重复配置与启动瞬态有关”，尚无示波器或频谱仪证据定位模拟瞬态。修复已验证相同工作点的准备流程，**不表示所有切换瞬态消失**。实际改变采样率/带宽仍应先让转发板静音；新固件启用后的完整业务收发及频率切换回归待后续验证。

## 真实射频启停与状态回报

发送板 TX1A → 遥控板 ADC1/J5、遥控板 J6 → 同一发送板 RX1A，保留 LDSDR TX1 → 独立接收板 RX1A 及遥控板到 LDSDR 的网线。LDSDR RX1 此时未接业务源。未重载固件或重启板卡，沿用上述 RAM 镜像和实际 901/1000 MHz 本振。

通过实际 GUI 按钮生成和发送，控制窗口仅连接发送板 COM19。台架负责有限遥控接收服务的准备、结束与独立只读核验；未以管理串口替代射频启停，也未下发新频率。查询特意携带不同的 900/1001 MHz 关联值，实际回报仍为 900999998/1000000000 Hz，确认查询不调谐。

查询、开启、主动停止分别恢复 8、7–8、8 个 CRC 正确 ATM2 回报帧；每笔只有一个快照，重复帧不算重复操作。解码、发送、ACK 三阶段均标为 ADC_NORMAL，事务、操作和 UDP 序号匹配。开启回报为 mode1、双路增益30 dB、衰减50 dB、初始剩余299999 ms；主动停止为 mode2、双路0/89 dB、剩余0。开启和停止另经独立 SPI 读回一致。

中断期间遥控板600秒接收服务已结束，后续一次开启采样没有有效回报。GUI显示“等待超时·结果未知”，原始IQ和失败结果均保留；独立核验显示转发板已到期静音，不能把该次发送记为成功。恢复接收服务和显式重连后，使用新序号完成上述启停复测。

再次由真实射频开启300秒租期，ACK初值299998 ms。此后未发控制包，仅以 `status/rfdiag` 只读观察：26份记录中剩余时间持续下降，最后一次转发状态剩余5694 ms，下一次读回已为mode2、双路0/89 dB、剩余0，独立SPI一致。两次查询相隔约10.73秒，不是射频关断延迟测量。GUI的保守快照计时到期后显示“状态快照已过期·待查询”，没有把旧mode1快照当作当前正在转发。

上述计时观察中的PL累积clip均为55363007，增量0；LDSDR业务输入断开，因此不能用它替代业务启动削顶验收。正常CPU轮询下的超时保护通过，不扩展为CPU停机或物理拔网线试验。

另修正超时/取消/错误后左侧提示仍显示“正在执行”的问题，并取消将内部序号写成会话指令条数。相关73项UI与业务UI回归通过；该文字修正在下一次启动生效，不改变已经采集的硬件证据。
