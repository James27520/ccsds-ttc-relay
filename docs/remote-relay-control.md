# 遥控转发与状态回报

本扩展保留原改频帧（首字节 `01`）、26 字节 RF_SET 和 ATM1。新增命令保持 8 字节空口正文，因此不改变 ADC 解调、卷积码或同步字。CRC 均为现有 CRC16-CCITT-FALSE。

## 空口命令

正文布局仍为 `<BHHB` + 大端 CRC16：操作版本、输入 LO MHz、输出 LO MHz、空口序号。

| 首字节 | 操作 | 行为 |
| --- | --- | --- |
| 01 | 改频 | 保留旧协议；新转发固件执行改频前取消租期并静音，完成后保持静音 |
| 21 | 开启转发 | 检查现有 LO 与请求相符；mode=1、两路 RX 增益 30 dB、两路 TX 衰减 50 dB，租期 300000 ms |
| 22 | 停止转发 | mode=2、两路 TX 衰减 89 dB、两路 RX 增益 0 dB；取消租期，不改 LO |
| 23 | 查询状态 | 只读，不改频、不改变电平、不续租 |

频率仍为 70..6000 的整数 MHz。停止和查询携带频率仅用于请求关联，不能把它们解释为调谐命令。开启采用当前有线台架已验证电平；本版不开放任意射频功率输入。序号由软件分配。

## 板间 UDP 扩展

沿用端口 5005。多字节字段为大端。命令恰好 34 字节，ACK 恰好 50 字节；CCSDS 长度字段等于总字节数减 7；分组序列字段为 `0xc000 | seq14`。CRC 覆盖除末尾 CRC 外的全部字节。新格式错误不得回退到旧命令执行。

| 命令偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | APID 0120 |
| 2 | 2 | 分组序列 |
| 4 | 2 | 长度 001b |
| 6 | 1 | 协议版本 1 |
| 7 | 1 | 操作 21 / 22 / 23 |
| 8 | 1 | 开启为 mode 1；其他为 0 |
| 9 | 1 | 开启 RX 增益 0..30 dB；其他为 0 |
| 10 | 1 | 开启 TX 衰减 50..89 dB；其他为 0 |
| 11 | 1 | 保留 0 |
| 12 | 4 | 开启租期 2000..300000 ms；其他为 0 |
| 16 | 8 | 请求 RX LO Hz |
| 24 | 8 | 请求 TX LO Hz |
| 32 | 2 | CRC16 |

| ACK 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | APID 0220 |
| 2 | 2 | 对应分组序列 |
| 4 | 2 | 长度 002b |
| 6 | 1 | 协议版本 1 |
| 7 | 1 | 对应操作 |
| 8 | 1 | flags：bit0 所有硬件回读有效；bit1 租期生效；bit2 曾到期；bit3 静音故障锁存 |
| 9 | 1 | 实际 mode 0..3 |
| 10,11 | 各 1 | 实际 RX1 / RX2 增益 dB |
| 12,16 | 各 4 | 实际 TX1 / TX2 衰减 mdB |
| 20 | 4 | 剩余租期 ms |
| 24 | 4 | 转发板 uptime ms（低 32 位） |
| 28,36 | 各 8 | 实际 RX / TX LO Hz |
| 44 | 4 | 有符号 rc |
| 48 | 2 | CRC16 |

返回码：0 成功，-1 格式或范围错误，-2 序号过期，-3 同序号内容冲突，-4 硬件操作/回读失败，-5 开启时频率不符，-6 原开启租期已结束，-7 故障锁存拒绝开启。无有效回读时 bit0 必须清零，未知值不能显示为已验证值。

每次转发板启动后，新协议序号严格递增，不在同一次启动内回卷；最近一次完全相同的包可重取实际状态，不能重执行或续租。最近一次开启在租期结束/取消后重发返回 -6；同序号不同内容返回 -3；更旧序号返回 -2。满 16383 后须重新初始化双方，不可宣称具备掉电持久防重放或身份认证。非法 CRC 不进入序号状态。收到有效新序号的失败事务也消耗该序号。

转发板自身计时，PC 关闭、UDP 丢包和状态查询均不续租。到期先将 PL 输出置静音，再设置双路 89 dB 衰减和 0 dB 增益并核对；失败锁存后禁止开启。旧 RF_SET 在执行前也取消租期并静音。新固件不允许旧 CLI 将 mode 改为非静音而绕过租期。轮询路径需有界，状态查询及串口持续输入不得饿死到期处理。

## ATM2 射频回报

新操作使用 112 字节 payload：magic `ATM2`，版本 2。0..91 与 ATM1 的计数和三阶段记录位置一致，但 byte6 / byte7 / byte55 分别保存 decoded / send / ack 的操作版本。保留 ATM1 的严格 96 字节解析和旧格式。

byte92 mode，93 RX1 增益，94 RX2 增益，95 flags；96..99 TX1 衰减 mdB，100..103 TX2 衰减 mdB，104..107 剩余租期 ms，108..111 转发板 uptime ms。均来自匹配 UDP ACK，不得由请求值补填。ACK 负返回码可以作为已关联的失败回报发送，不能增加成功计数或显示为执行成功。

外层仍为 `aaaa | len8 | payload | crc16(payload)`。ATM2 每帧 117 字节，四次重复加前后各 8 字节训练为 484 字节，100 kbit/s 持续 38.72 ms；服务的突发结束保护按实际长度计算。

GUI 将回报显示为带采集时间的状态快照；查询不等于持续监控。开启成功必须同时匹配操作、序号、实际 LO、mode、两路电平以及有效且未结束的租期。剩余时间只作保守估计，不得将过期快照继续显示成当前正在转发。停止必须确认 mode=2、双路 89 dB、增益 0；查询按真实快照展示，不伪造目标值。

## 验证边界

编解码、故障注入、重复/冲突/到期测试、RAM 构建与加载，以及真实板间 UDP 短租期测试已通过。后续另经 GUI 实际按钮完成 ADC_NORMAL 上行和 DAC 下行的查询、开启、停止验收，模式与双路电平另有独立 SPI 读回，见[本轮验证](remote-relay-validation.md#真实射频启停与状态回报)。仍是有线测控闭环，业务输入需换线接回；不代表业务与遥控并发、CPU停机保护或持久化启动。
