# 六线系统功能划分与分阶段实施计划

本计划把六根同轴按功能登记为：正向业务两根、反向业务两根、独立测控上行一根、独立测控下行一根。六根线只定义物理连接需求，不证明六路能够同时工作。当前桌面站支持正向两线有线文本业务，另已实现USB DEBUG管理状态回传；ADC指令与DAC回报已完成[同一事务的顺序闭环验证](telecontrol-roundtrip-validation.md)。反向业务、独立指令源接入及全系统并发仍待实现或验收。

正向第一版桌面站已经通过控制器回归和两个独立GUI进程的实板测试，见[桌面站验收](ground-station-validation.md)。2026-10-29新增[板端自主服务与第二版改频GUI](telecontrol-autonomous-validation.md)，以及[第二版文本业务GUI实测](business-v2-validation.md)：业务窗口各自只连接本地SDR，改频窗口与文本发送显式交接同一设备。板端服务仍有限时；六线全系统仍按下列阶段逐项实现。USB管理连接不计入六根RF同轴。

## 端口登记

下表的功能代号仅用于本计划，不对应旧框图编号。实际接线先沿用当前板卡丝印；所有尚未核对或未测试的端口明确标为候选。

| 功能代号 | 信号方向与用途 | 当前端口登记 | 当前状态 |
| --- | --- | --- | --- |
| FWD-IN | 网关/发送端 → 转发载荷，正向业务输入 | 发送板 `TX1A` → LDSDR `RX1` | 现有已测物理连接；本阶段 GUI 使用 |
| FWD-OUT | 转发载荷 → 终端/接收端，正向业务输出 | LDSDR `TX1` → 独立接收板 `RX1A` | 现有已测物理连接；本阶段 GUI 使用 |
| REV-IN | 终端 → 转发载荷，反向业务输入 | 终端 SDR 候选 TX 口 → LDSDR 候选 `RX2` | 候选，丝印、第二通道格式与 RF 能力待核对和单独测试 |
| REV-OUT | 转发载荷 → 网关，反向业务输出 | LDSDR 候选 `TX2` → 网关 SDR 候选 RX 口 | 候选，通道映射与 RF 性能未验 |
| TC-UP | 独立指令源/网关 → 遥控板，测控上行 | 独立 RF 源或网关候选 TX 口 → Z7ADDALite `ADC1/J5` | ADC1/J5 有既有分时输入证据；独立六线接入及并发未实现 |
| TM-DOWN | 遥控板 → 网关，测控下行 | Z7ADDALite DAC1/J6 → 原发送板空闲 RX1A/JP2 | 单路实收及GUI单次采集通过；采用当前启动会话绑定，永久角色身份与并发未验，见[GUI采集报告](telemetry-live-validation.md) |

正向链记录以 `TX1A → RX1`、`TX1 → RX1A` 为准，不把旧图中的逻辑编号直接套到现有实物。反向链中的 RX2/TX2 是待验证候选名称；存在接口丝印或原理图连接不等于固件已正确启用第二通道。

DEBUG USB串口与板间管理网络属于控制、诊断连接，不计入六根RF同轴。当前V2发送GUI只连接本地发送板，接收GUI只连接自己的接收板。LDSDR先在台架准备转发模式和电平，GUI不打开它的管理口，也不重写其本振。此前通过两个DEBUG端口准备转发板的是保留的第一版工具。

第一版发送端的“测控状态”弹窗可额外选择ADDA DEBUG串口，每2秒只读查询并校验TM1 CRC。V2三窗口不包含此管理接口。最近解码、UDP发送尝试与匹配ACK各自显示来源、事件和序号；`ADC_NORMAL` 与测试来源明确区分，不能把测试记录写成真实ADC指令执行成功。

独立 SPI 按钮借用主控制器已有 LDSDR worker 查询，ACK 携带值不自动填入独立 SPI 卡片。界面保留更新时间，超过 `6 秒`标记历史过期；关闭时等待控制器清理。此功能只实现 **USB DEBUG 状态回传，不是 DAC 射频下行**，见[测控状态说明](telemetry-status.md)。

## 本阶段正向工作点

| 项目 | 当前软件准备值或限制 |
| --- | --- |
| 业务波形 | 实验 BPSK，100 ksym/s，外层 CRC16 |
| 应用正文 | G1 信封：session + sequence + `1–32` UTF-8 字节正文 |
| 发送板 | 中心计划 `900.5/901.5 MHz`，静音应用TX LO `900/901 MHz`并回读，调制偏移 `+500 kHz`；衰减申请值 `50–89 dB` |
| LDSDR | V2实测保留遥控设置的RX LO `900 MHz`、TX LO `1001 MHz`；台架另准备mode1、gain30、atten50，GUI不写转发板 |
| 独立接收板 | 本地预期RF `1000.5/1001.5 MHz`分别对应RX LO `1000.75/1001.75 MHz`，V2增益固定30 dB |
| 频率计划 | 修改后显式应用，只配置本地SDR；真实当前遥控回报仅更新发送窗口待应用计划，不自动发射，接收端独立选择目标 |
| 停止 | V2只停止本地收发并保留历史；转发板由台架单独静音 |
| 发送保护 | V2每次最多30秒，不续期；停发后读回本地状态 |

发送、接收程序可先在一台电脑演示，再把接收端迁到另一台电脑。接收程序只能使用自己采到的IQ解码，不能读取发送窗口文本。两端各选择自己的板卡；第一版双管理串口行为不用于V2展示。

`32768` 个复数样本在 `2.5 MSPS` 下只覆盖 `13.1072 ms`。当前上传和下载临时使用 `921600` 波特 raw 二进制传输，并核对长度及 SHA；完成或取消后恢复 `115200` 波特控制台。旧 `115200` legacy 路径保留为显式兼容入口，不在高速失败时静默降级。

第一版高速路径实测capture处理 `2.87–2.91秒`；本轮V2增加会话连续性检查后约 `3.2秒`，仍是有采样空档的分段观测。界面中的频谱、CRC统计与采样时间均来自返回快照；不把它写成连续实时链路、全时段无漏帧或BER为零。新文本提交到接收的时间与capture处理时间分别见[本轮报告](business-v2-validation.md)。

## 远端转发启用尚未纳入遥控协议

2026-10-29复查现有调用链：空口8字节正文只携带版本、RX/TX本振和序号；ADDA生成的26字节RF_SET虽然包含增益和衰减，但不包含转发模式。LDSDR的 `relay_apply_rf_command()` 在改频前静音，成功后恢复原模式，因此原先是mode2时不会自动变成mode1。当前自动测控服务只允许gain0/atten89，成功ACK及ATM1回报也没有模式或电平读回字段。**改频成功不能用作“业务转发已启用”的证据。**

后续升级应保留旧指令语义，以显式新版本/新APID请求受限业务配置；先静音、设置及实际读回频率和两路电平，最后才启用转发。新的回报必须携带指令类型、实际模式、电平及有效期，旧固件应拒绝新命令。需增加转发板自身的超时静音和重复命令处理：丢ACK后的重传不能无限延长发射时间，超时后的旧请求不能重新启用。当前PC发送端的30秒保护只约束本地发送板，ADDA的600秒服务也不会在退出时自动静音LDSDR。

这些是下一项固件升级的验收条件，尚未实现。第二版GUI不通过隐藏的调试串口补做远端操作；在升级完成前，转发模式和电平仍由明确的台架准备步骤完成。新旧协议兼容、部分寄存器写失败、读回不符、丢ACK、超时、重传和断网均需独立验证后才能替代此步骤。

## 并发前必须解决的频率资源问题

同一 SDR 的多个 TX 通道共用 TX LO，多个 RX 通道共用 RX LO；TX LO 与 RX LO 可以分别设置，但不能因此把每个物理端口当成独立可调频的收发机。尤其不能直接假设网关的一块 SDR 可同时发出 `100.5 MHz` 测控信号和 `900 MHz` 工作点附近的业务信号。

应先列出每台 SDR 在并发场景下的 TX/RX 中心频率、每个通道的基带偏移、采样率、有效带宽及所需滤波。`100.5 MHz` 测控和 `900.5 MHz` 业务相距很远，不能仅通过把波形分配给同一芯片的两个 TX 端口就认为问题已经解决。

可研究的实现方向包括：调整测控与业务频率规划、增加外部变频器、使用独立 RF 收发设备，或明确采用分时工作。选定方案后还要核对反向业务与测控下行的共用 RX LO、带宽和端口资源。分时方案应标注切换与采样空档，不能称为六线全并发。

独立接收板的TX能力、第二RF通道和扩展频段表现尚不能由正向接收结果推断。冻结`r4c`的DAC路径仍关闭；新增下行候选已经完成PL时序和板端控制验证，名义90.5MHz、100ksym/s、单次33.6ms，详见[数字阶段验证](telemetry-downlink-validation.md)。后续[SMA实际接收](telemetry-rf-validation.md)通过12个CRC正确帧；它只证明当前单路下行工作点，不解决多通道共用本振与并发问题。

## 分阶段实施与验收入口

| 阶段 | 必须形成的结果 | 进入下一阶段前的证据 |
| --- | --- | --- |
| 1. 正向两线桌面演示 | 独立发送/接收进程；真实输入文本、消息编号与快照；正常启停和异常清理 | [桌面站验收](ground-station-validation.md)、[高速采样回传验证](station-speed-telemetry-validation.md)；第二台电脑现场迁移尚待测试 |
| 2. 第二通道与反向业务 | 逐项核对候选端口，完成终端→LDSDR→网关的单向反向业务 | 第二通道格式、I/Q 映射、LO、输入幅度及反向独立解码证据；不得借用正向结论 |
| 3. 独立测控上下行 | 确认独立指令源方案；验证新PL的DAC/SMA遥测回传 | ADC指令→ACK→DAC返回的板端自主服务及整笔GUI操作已实测；独立源、持久化启动和并发仍待完成 |
| 4. 频率与资源联动 | 确定各板 TX/RX LO、基带频偏、带宽、端口占用与时序 | 书面资源表及选定的变频、独立 RF 或分时方案；消除共用 LO 冲突 |
| 5. 六线系统验收 | 按选定方案验证双向业务与双向测控 | 每条功能链的独立内容关联、频率回读、启停、失联保护与持续观测证据；有空档时按空档报告 |

阶段1的V2 GUI验收覆盖启动不自动发射、本地设备身份、申请值与实际回读区分、独立恢复文本及消息编号、重复帧标记、限时停发和窗口设备交接。软件测试、mock UI、当前有线实板结果和未来六线验收分别记录；本轮没有验证第二台电脑迁移或六线并发。
