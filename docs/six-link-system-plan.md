# 六线系统功能划分与分阶段实施计划

本计划把六根同轴按功能登记为：正向业务两根、反向业务两根、独立测控上行一根、独立测控下行一根。六根线只定义物理连接需求，不证明六路能够同时工作。当前桌面站支持正向两线有线文本业务，另已实现USB DEBUG管理状态回传；ADC测控上行和DAC测控下行均已有各自的实际接收证据。反向业务、独立指令源接入、测控双向联动及全系统并发仍待实现或验收。

本轮正向桌面站已经通过控制器回归和两个独立 GUI 进程的实板测试，见[桌面站验收](ground-station-validation.md)。高速采样回传与 USB 测控状态回传的新增结果见[提速及测控状态验证](station-speed-telemetry-validation.md)。USB 管理连接不计入六根 RF 同轴，六线全系统仍按下列阶段逐项实现。

## 端口登记

下表的功能代号仅用于本计划，不对应旧框图编号。实际接线先沿用当前板卡丝印；所有尚未核对或未测试的端口明确标为候选。

| 功能代号 | 信号方向与用途 | 当前端口登记 | 当前状态 |
| --- | --- | --- | --- |
| FWD-IN | 网关/发送端 → 转发载荷，正向业务输入 | 发送板 `TX1A` → LDSDR `RX1` | 现有已测物理连接；本阶段 GUI 使用 |
| FWD-OUT | 转发载荷 → 终端/接收端，正向业务输出 | LDSDR `TX1` → 独立接收板 `RX1A` | 现有已测物理连接；本阶段 GUI 使用 |
| REV-IN | 终端 → 转发载荷，反向业务输入 | 终端 SDR 候选 TX 口 → LDSDR 候选 `RX2` | 候选，丝印、第二通道格式与 RF 能力待核对和单独测试 |
| REV-OUT | 转发载荷 → 网关，反向业务输出 | LDSDR 候选 `TX2` → 网关 SDR 候选 RX 口 | 候选，通道映射与 RF 性能未验 |
| TC-UP | 独立指令源/网关 → 遥控板，测控上行 | 独立 RF 源或网关候选 TX 口 → Z7ADDALite `ADC1/J5` | ADC1/J5 有既有分时输入证据；独立六线接入及并发未实现 |
| TM-DOWN | 遥控板 → 网关，测控下行 | Z7ADDALite DAC1/J6 → 原发送板空闲 RX1A/JP2 | 单路实收及GUI单次采集通过；采用当前启动会话绑定，永久角色身份与并发未验，见[GUI采集报告](telemetry-live-validation.md) |

正向链记录以 `TX1A → RX1`、`TX1 → RX1A` 为准，不把旧图中的逻辑编号直接套到现有实物。反向链中的 RX2/TX2 是待验证候选名称；存在接口丝印或原理图连接不等于固件已正确启用第二通道。

DEBUG USB 串口与板间管理网络属于控制、诊断连接，不计入六根 RF 同轴。当前发送 GUI 通过两个 DEBUG 串口本地准备发送板和 LDSDR；接收 GUI 通过自己的 DEBUG 串口读取采样。该流程不等于 `TC-UP` 经真实 ADC 输入触发了转发频率修改。

发送端新增“测控状态”弹窗，可额外选择 ADDA DEBUG 串口，每 `2 秒`只读查询并校验 TM1 CRC。最近解码、UDP 发送尝试与匹配 ACK 各自显示来源、事件和序号；`ADC_NORMAL` 与 `ADC_TEST`、`SYNTHETIC`、`UART_NETTEST` 明确区分。来源与事件应逐阶段核对，不能把测试记录写成真实 ADC 指令执行成功。

独立 SPI 按钮借用主控制器已有 LDSDR worker 查询，ACK 携带值不自动填入独立 SPI 卡片。界面保留更新时间，超过 `6 秒`标记历史过期；关闭时等待控制器清理。此功能只实现 **USB DEBUG 状态回传，不是 DAC 射频下行**，见[测控状态说明](telemetry-status.md)。

## 本阶段正向工作点

| 项目 | 当前软件准备值或限制 |
| --- | --- |
| 业务波形 | 实验 BPSK，100 ksym/s，外层 CRC16 |
| 应用正文 | G1 信封：session + sequence + `1–32` UTF-8 字节正文 |
| 发送板 | TX LO 固定 `900 MHz`，调制偏移 `+500 kHz`；衰减申请值 `50–89 dB` |
| LDSDR | 本地准备 RX LO `900 MHz`、TX LO `1000 MHz`，默认输出 RF 名义值 `1000.5 MHz` |
| 独立接收板 | RX LO `1000.75 MHz`，默认预期 RF `1000.5 MHz`，增益 `0–30 dB` |
| 可选接收先验 | `1001.5 MHz`；不会自动更改当前 GUI 固定的 LDSDR TX LO |
| 停止 | 正常 stop 联动静音发送板与转发板，保留本机历史 |
| 发送保护 | 发送板约 45 秒续租停发 guard，控制器运行期间续租 |

两独立桌面进程可先在一台电脑演示，再把接收端迁到另一台电脑。接收程序只能使用自己采到的 I/Q 解码，不能读取发送窗口文本。发送侧需要发送板 DEBUG 与 LDSDR DEBUG 两个不同端口，接收侧只需要接收板 DEBUG。

`32768` 个复数样本在 `2.5 MSPS` 下只覆盖 `13.1072 ms`。当前上传和下载临时使用 `921600` 波特 raw 二进制传输，并核对长度及 SHA；完成或取消后恢复 `115200` 波特控制台。旧 `115200` legacy 路径保留为显式兼容入口，不在高速失败时静默降级。

本轮完整 capture 周期实测 `2.87–2.91 秒`，旧流程约 `24 秒`，但接收仍是有采样空档的分段观测。界面中的实测频谱、CRC 统计与最后有效帧时间均来自返回快照；不把它写成连续实时链路、全时段无漏帧或 BER 为零。新文本提交到接收显示的端到端总时间由[新增验证报告](station-speed-telemetry-validation.md)另行记录，不以 capture 周期代替。

## 并发前必须解决的频率资源问题

同一 SDR 的多个 TX 通道共用 TX LO，多个 RX 通道共用 RX LO；TX LO 与 RX LO 可以分别设置，但不能因此把每个物理端口当成独立可调频的收发机。尤其不能直接假设网关的一块 SDR 可同时发出 `100.5 MHz` 测控信号和 `900 MHz` 工作点附近的业务信号。

应先列出每台 SDR 在并发场景下的 TX/RX 中心频率、每个通道的基带偏移、采样率、有效带宽及所需滤波。`100.5 MHz` 测控和 `900.5 MHz` 业务相距很远，不能仅通过把波形分配给同一芯片的两个 TX 端口就认为问题已经解决。

可研究的实现方向包括：调整测控与业务频率规划、增加外部变频器、使用独立 RF 收发设备，或明确采用分时工作。选定方案后还要核对反向业务与测控下行的共用 RX LO、带宽和端口资源。分时方案应标注切换与采样空档，不能称为六线全并发。

独立接收板的TX能力、第二RF通道和扩展频段表现尚不能由正向接收结果推断。冻结`r4c`的DAC路径仍关闭；新增下行候选已经完成PL时序和板端控制验证，名义90.5MHz、100ksym/s、单次33.6ms，详见[数字阶段验证](telemetry-downlink-validation.md)。后续[SMA实际接收](telemetry-rf-validation.md)通过12个CRC正确帧；它只证明当前单路下行工作点，不解决多通道共用本振与并发问题。

## 分阶段实施与验收入口

| 阶段 | 必须形成的结果 | 进入下一阶段前的证据 |
| --- | --- | --- |
| 1. 正向两线桌面演示 | 独立发送/接收进程；真实输入文本、消息编号与快照；正常启停和异常清理 | [桌面站验收](ground-station-validation.md)、[高速采样回传验证](station-speed-telemetry-validation.md)；第二台电脑现场迁移尚待测试 |
| 2. 第二通道与反向业务 | 逐项核对候选端口，完成终端→LDSDR→网关的单向反向业务 | 第二通道格式、I/Q 映射、LO、输入幅度及反向独立解码证据；不得借用正向结论 |
| 3. 独立测控上下行 | 确认独立指令源方案；验证新PL的DAC/SMA遥测回传 | USB TM1、ADC指令、DAC实收和GUI单次采集已分别验收；真实ADC指令→ACK/SPI→DAC返回的同一事务联动尚待验证 |
| 4. 频率与资源联动 | 确定各板 TX/RX LO、基带频偏、带宽、端口占用与时序 | 书面资源表及选定的变频、独立 RF 或分时方案；消除共用 LO 冲突 |
| 5. 六线系统验收 | 按选定方案验证双向业务与双向测控 | 每条功能链的独立内容关联、频率回读、启停、失联保护与持续观测证据；有空档时按空档报告 |

阶段 1 的新 GUI 验收至少应覆盖：启动不自动发射、三个 DEBUG 身份对应正确、申请值与实际回读区分、接收程序独立恢复文本及消息编号、重复帧标记、停止后的静音回读、关闭等待与历史证据保留。软件单元测试、fake UI 测试、当前有线实板结果和未来六线验收应分别记录。
