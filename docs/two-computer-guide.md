# 双电脑联调操作说明

电脑1由卢使用，连接终端1并负责测控；电脑2由队友使用，只连接终端2。两端运行同一份仓库代码，各自启动自己的窗口，业务数据通过板卡和六根SMA传输。

## 电脑2操作交接

1. **更新。** 先断开终端2并关闭旧窗口。在这台电脑的仓库根目录确认分支为 `main`，执行 `git pull --ff-only origin main`。若没有 Git 副本，从仓库下载完整 ZIP，解压后进入能看见 `start_terminal2.bat` 的那一层。
2. **准备环境。** 首次使用，或解压到了一个新目录，双击 **`setup_station.bat`**。在原目录更新且已配好环境的，只需双击 **`check_station.bat`**。这次语音播报使用 Windows 本机语音，无须安装额外语音包才能运行程序。
3. **打开界面。** 将终端2的 **DEBUG** 数据口接电脑2，保持独立供电和现有 SMA 接线。双击 **`start_terminal2.bat`**，应只打开「终端2 · 双向通信」。页面直接从「终端2」标题开始，连接栏有「语音播报」勾选框。
4. **连接。** 点「刷新」，选择本机实际枚举的终端2串口。本轮本机发送中心填 **1989.500 MHz**，接收中心填 **2179.500 MHz**，再点「连接」。若已连接后才改数值，点「应用本机频率」，核对两处「已应用」读数。
5. **互发。** 等电脑1确认转发已开启。电脑1先发 `T1-CHECK-01`，在电脑2「来自终端1」看到原文后，再用「发送文本」回发 `T2-REPLY-01`。请电脑1核对实收原文，复测时换一个新编号。
6. **核对语音。** 勾选时，新收到的有效文本会播报「收到新文本」，本地发出后会播报「发送成功」。后者只确认电脑2发出。取消勾选即可静音；没有可用中文语音时使用 Windows 提示音。

此次使用下表的四个入口。旧版、兼容、单独测控及预览 BAT 已删除；测控从终端1窗口打开。

## 电脑2 OBS 单窗口录制

电脑2智能体按下列步骤在本机操作。成片只录「终端2 · 双向通信」的客户区，规格与电脑1统一为 **1920 × 1080，30 fps**。准备录屏时可以先不连接板卡。

1. **打开通信窗口。** 如果「终端2 · 双向通信」已经打开，直接使用。否则在仓库根目录双击 `start_terminal2.bat`。保持窗口展开。
2. **选场景和来源。** 打开 OBS，选中用于本次录屏的场景。如果当前场景已经有在用的其他画面，新建一个「终端2录屏」场景。最终只保留一个可见的画面来源。在「来源」点 **＋ → 窗口采集**；已有窗口采集源时，直接打开它的属性。按完整标题选择 **「终端2 · 双向通信」**（进程名可能是 `python.exe` 或 `pythonw.exe`）。将「窗口匹配优先级」设为「窗口标题必须匹配」，若有「无边框模式」（客户区）选项则勾选，预览出现终端2界面后点「确定」。如果预览是黑屏，先确认窗口没有最小化，再试「Windows 10 (1903或更新版本)」采集方式。[OBS 窗口采集说明](https://obsproject.com/kb/window-capture-sources)
3. **设分辨率和帧率。** 在「设置 → 视频」中，将「基础（画布）分辨率」和「输出（缩放）分辨率」都设为 `1920x1080`，「常用帧率」选 **30**，点「应用」。若录制输出另设了「重新缩放输出」，将其关闭，避免录制文件变成其他分辨率。
4. **把画面居中。** 选中窗口采集源，右键选「变换 → 比例适配屏幕」（默认快捷键 `Ctrl+F`），再选「变换 → 屏幕居中」。检查两侧留边对称，顶部频率、左右收发框和底部通信记录都在画布内，然后锁定该来源。窗口和画布宽高比不同时，保留等宽留边。[OBS 来源与变换说明](https://obsproject.com/kb/sources-guide)
5. **试录并回放。** 将录制目录设为本机的 `D_电脑2录屏` 素材文件夹，格式选 MKV。需要收录界面语音时开启桌面音频；口播单独录制时将麦克风静音。点「开始录制」，让终端2窗口出现一次可见变化（例如展开再收起「设备与参数」），约 5–10 秒后点「停止录制」。打开刚生成的文件，确认窗口在变化、画面居中且文字完整。可用媒体信息检查分辨率和帧率；本机已有 `ffprobe` 时也可运行：

   ```powershell
   ffprobe -v error -select_streams v:0 -show_entries stream=width,height,avg_frame_rate -of default=nw=1 "试录文件的完整路径.mkv"
   ```

   预期读数为 `width=1920`、`height=1080`、`avg_frame_rate=30/1`。请回报**场景名、所选窗口标题、实际文件规格、试录文件路径**。正式拍摄时，电脑2连续录下收到电脑1文本、输入回复和点击「发送文本」的过程，供后期与电脑1原片对齐。

## 文件在哪，分别打开什么

建议队友保存到 `D:\NTN\ccsds-ttc-relay`；没有D盘可用自己的其他普通文件夹。此路径是建议，不是程序硬编码要求。

| 文件（均在仓库根目录） | 谁用 | 用途 |
| --- | --- | --- |
| `setup_station.bat` | 两台电脑首次准备时 | 在本机建立`.venv`、安装固定版本依赖、检查接收程序；不连接板卡 |
| `check_station.bat` | 两台电脑 | 检查Python、界面依赖、程序摘要，列出当前USB串口；不配置硬件 |
| `start_terminal1.bat` | 电脑1 | 只开终端1双向通信；点击窗口右上“测控 →”打开共享连接的测控页 |
| `start_terminal2.bat` | 电脑2 | 只开终端2双向通信，不提供测控窗口 |

电脑1应从通信页打开测控，保持同一个进程和后台，避免另启动第二套终端1争用串口。

例如，队友的窗口入口是 `D:\NTN\ccsds-ttc-relay\start_terminal2.bat`；详细说明是 `D:\NTN\ccsds-ttc-relay\docs\two-computer-guide.md`。从GitHub下载ZIP时先完整解压，外层文件夹可能名为`ccsds-ttc-relay-main`，进入能看见上述BAT的那一层后再运行。

## 新电脑准备

- Python安装包使用[官方Windows下载页](https://www.python.org/downloads/windows/)。建议64位3.13，安装pip和Tcl/Tk；启动器也支持可用的64位Python 3.11及以上。`setup_station.bat`会优先尝试`py -3.13`，再尝试`py -3`或`python`。
- 当前部署依赖固定为NumPy 2.4.1和pyserial 3.5；首次安装需要网络。不要把电脑1的`.venv`复制过来，它包含原电脑的解释器路径。在新电脑运行安装脚本重新建立即可；现有损坏环境需先关闭程序，将本仓库`.venv`改名保存后再安装，脚本不会替你删除它。
- 安装报TLS/SSL或代理连接失败时，先检查本机代理是否可用，再重新运行安装脚本。本轮干净安装曾因本机失效代理失败，关闭该安装进程的代理后从官方PyPI安装成功；无需关闭证书校验，也不用修改系统安全设置。
- DEBUG是USB串口，使用[FTDI官方VCP驱动](https://ftdichip.com/drivers/vcp-drivers/)。Windows已能显示USB Serial Port时不必重复装；设备管理器有黄色感叹号或没有COM口时再检查驱动和数据线。只给驱动安装程序所需的管理员权限，GUI日常用普通权限运行。
- **电脑2不需要Vivado、SDK、ARM交叉编译器或本机libiio。** 仓库含`board/terminal/stream_rx/bin/stream_rx_armv7`和构建清单，连接时会校验后部署到板端RAM。板子仍必须运行配套Linux/IIO固件；电脑端安装不等于给板子刷系统。
- `check_station.bat`可在板子未接时先检查软件。没有USB设备只会提示；缺依赖或接收程序不完整则禁止启动，避免进到界面后才失败。
- 若用Git更新，先关闭本机项目窗口，`git pull --ff-only`后再运行安装脚本和检查。两台电脑使用同一提交；可用`git rev-parse --short HEAD`互相核对。不要覆盖队友未提交的改动。

## USB迁移与设备识别

COM号由每台Windows分配，电脑1上的COM17到电脑2可能变成COM3、COM8等。**程序实时枚举当前电脑端口，没有固定COM17/COM19；不用修改源码或注册表。**

本次双电脑接线按实物核对。历史单电脑调试时的角色分配可能与本次不同。

| 实物 | 当前已记录的USB序号 | 核对方法 |
| --- | --- | --- |
| 终端1（电脑1） | `000000000069B` | 已在电脑1按实物及射频回报核实 |
| 终端2（电脑2） | 以电脑2当次枚举为准 | RX1A 接 LDSDR TX1 的那块板；用 `check_station.bat` 或「刷新」识别其 DEBUG 串口 |

新电脑不带本机`CCSDSGroundStation/device_labels.json`，所以首次显示“未识别 USB 串口 · COMx · 序号 …”是正常的。展开“设备与参数”还能查看说明和在线核验结果。连接会核对当前USB、Linux启动编号和IIO设备；角色名称由你打开的终端入口决定，不能靠选择“终端2”把任意串口当作正确板卡。

若有多个同号或无序号设备，先保持其他USB设备不变，通过插拔**待迁移的终端2 DEBUG线**观察新增的端口。不要把电脑1的端口号或历史标签文件整体复制过去。已连接时端口变化应重新选择并显式连接，程序不会静默转接到另一设备。

## 从当前单电脑状态迁移

1. 本电脑两端先停止发送；电脑1测控执行“停止转发”并等到真实静音回报。不要在测控执行中拔线。
2. 本电脑终端2窗口点击“断开”，等待清理完成，再关闭终端2窗口，释放其串口。终端1保留在电脑1。
3. **只移动终端2 DEBUG线的电脑端**，从电脑1插到电脑2。终端2就是RX1A接转发板TX1、TX1A接转发板RX2的那块。保持其独立供电，不动SMA；若DEBUG同时承担供电，要先确认供电方式，不能把断电当成无影响的USB迁移。
4. 遥控板和转发板的调试USB可继续留电脑1用于维护，但两边业务GUI都不依赖打开这两个管理串口。原“遥控板↔转发板”网线保持直连。
5. 电脑2运行检查和终端2入口。双电脑正常收发不需要两台电脑互设IP、不需要电脑间网线或共享文件夹；安装依赖时才需要互联网。

只迁移USB不会改变板端已有固件。**完全断电后不能假定四板自动恢复到当前验证状态**：GUI不负责自动刷机或从U-Boot恢复。若报启动引导、IIO缺失或板端无响应，先交由电脑1维护端核对启动，不要反复发送业务或覆盖SD卡。

## 两个人按顺序操作

先统一频率。以下是两组已在台架验证的业务中心；终端2的TX/RX方向不要反填。

| 阶段 | 电脑1本机发送 / 接收中心 | 电脑2本机发送 / 接收中心 | 电脑1测控业务输入 / 输出 |
| --- | --- | --- | --- |
| 初始联调 | 1989.500 / 2179.500 MHz | 1989.500 / 2179.500 MHz | 1989.500 / 2179.500 MHz |
| 换频展示 | 1995.123 / 2185.456 MHz | 1995.123 / 2185.456 MHz | 1995.123 / 2185.456 MHz |

1. 两人打开各自入口，在通信页填本机发送/接收中心，选择本地板卡并连接。连接后自动接收；已连接后改频须点“应用本机频率”，等读回完成。填写的是中心频率，不是自行换算后的TX/RX本振。
2. 电脑2告知“已连接、频率已应用”。电脑1从终端1页进入测控，先“设置频率→生成指令→发送指令”，等真实回报，再“开启转发→生成指令→发送指令”，等业务恢复。准备完成后再开启，避免两人安装软件时消耗五分钟有效期。
3. 电脑1发`电脑1测试01`，电脑2观察实际收到相同文字；电脑2发`电脑2回复01`，电脑1观察实收。正文限32个UTF-8字节，一般10个以内汉字可用。发送页“已发送”不是对端确认，两边以实际接收区为准。
4. 可双方同时提交新文本，或各发多条不同的短文本。无队列时通常约6秒可见；双方忙及FIFO排队会更久，连续三条的第三条可能约22–24秒，不要在等待时反复点发送造成重复任务。
5. 换频前两人先停止发送，口头约定下一组频率；分别应用各自本机频率。电脑1再在测控页设置同一业务输入/输出并开启。**测控只改转发板，不会通知或自动改电脑2的本机频率。** 两人都完成后再发新的验证文字。
6. 测控期间终端1暂停业务，终端1新提交文字可排队；成功开启且恢复后顺序发送，失败/取消则待手动重试。电脑2没有跨电脑测控状态通知，此时先停止新的业务发送，待电脑1通知恢复；其旧消息不会自动补发。
7. 转发开启五分钟后会静音，电脑1显示到期提示；没有自动续期。电脑2因没有测控回报来源，其转发板状态显示未知是正常的，不代表本地USB断开。需要继续时，由电脑1查询或按已设置频率重新开启，通知电脑2后再发送。
8. 结束时两端停止发送；电脑1测控停止转发并确认回报；两端断开、关闭程序，再拔USB或断电。

## 原六根SMA保持不变

| 线 | 方向 |
| --- | --- |
| 1 | 终端1 TX1A/JP1 → LDSDR RX1 |
| 2 | LDSDR TX1 → 终端2 RX1A/JP2 |
| 3 | 终端2 TX1A/JP1 → LDSDR RX2 |
| 4 | LDSDR TX2 → 终端1 RX2A/JP4 |
| 5 | 终端1 TX2A/JP3 → 遥控板 ADC1/J5 |
| 6 | 遥控板 DAC1/J6 → 终端1 RX1A/JP2 |

## 常见问题与回报

| 现象 | 先检查什么 |
| --- | --- |
| 双击没窗口或缺numpy/serial | 完整解压仓库，运行`setup_station.bat`，再`check_station.bat`；不要复制旧`.venv` |
| 安装依赖报TLS/SSL、代理错误 | 检查网络和本机代理后重试；不要按报错把证书校验关闭 |
| USB列表没有板卡 | DEBUG口、可靠数据线、独立供电、FTDI VCP驱动；先看设备管理器，不是先修改COM号 |
| 拒绝访问、端口被占用 | 关闭串口助手、重复GUI和其他占用该板卡的程序；先正常断开，不要用管理员权限互相抢串口 |
| U-Boot或Linux未运行 | 板卡启动问题，不是GUI频率问题；保留报错给电脑1维护端处理 |
| 已发送但另一边无文字 | 核对两端本机中心、转发板实际设置/开启状态、是否到期、接收通道及SMA；不要将本地发送记录当实收 |
| 电脑2需要核对转发状态 | 由电脑1在测控页查询。电脑2只回读本机频率 |
| 更新代码后接收程序摘要不符 | 下载完整同一版本，重新检查；不要单独混用旧二进制或用环境变量绕过校验 |

每台电脑的日志分别在 `%USERPROFILE%\CCSDSGroundStation\sessions\`，可把该路径粘贴到资源管理器地址栏。出问题时给出：两台代码版本、当前COM及USB序号、频率、动作时间、错误原文，并各自保留对应会话目录里的`events.jsonl`。测控的`control/command_xxxx/`还包含原始回报和核验结果。不要只给发送成功截图。
