# 测控与文本收发耗时优化

本轮使用原六根 SMA 接线和已运行的四板固件，修改地面站程序。保留“设置频率”“开启转发”“停止转发”“查询状态”的含义，不增加自动续期，不自动改动另一终端的频率。发送记录的“已发送”仍只确认本地发射；业务实收依据对端射频解码所得的内容、消息编号和 CRC。

## 修改前的证据

11月1日17:10会话中，两笔射频测控分别耗时66.187、66.209秒；包含暂停与恢复业务，约94秒。一次测控执行了14次完整 `iio_info`，每次约2.6秒；1 MiB回报采样经调试串口下载约12.64秒。

17:14:30提交 `hello`，17:14:54对端得到正确文本。期间先等待业务恢复，再执行发送准备。另一条普通文本从提交到本地启动确认耗时19.144秒。两者均不能作为纯射频传播时延。

17:23的反向文本没有实收；两端接收处理仍约2.5 MSPS，无队列满或接收恢复记录。但最后一次开启回报在17:14，已超过300秒开启期限。该判断来自日志时间和固件计时逻辑，没有把当时未采集的转发板状态当作实测。

## 实现

- 连接时完整识别设备；当前会话内检查USB、Linux启动身份和IIO映射。重启或身份变化仍拒绝继续操作。
- 合并静音写入与回读、业务启动前提检查，复用带进程启动时间和通道掩码核验的短接收检查。静音写入中的单项失败不能跳过其他停发操作。
- 接收程序在同一会话内按SHA-256验证后复用；缓存内容改变立即报错。每次恢复仍重新建立并核验接收进程。
- 小脚本使用有长度上限和摘要核验的串口命令上传，避免对小文件反复切换串口速率。
- 测控上行重复发送由8秒缩为4秒；回报保留131072组原始I/Q，即52.4288毫秒、512 KiB，并继续执行削顶检查、CRC、事务关联与实际频率检查。
- 明确保留旧回报窗口隔离。首次连接仍有30秒隔离边界；有效回报采集时间为上一事务ACK的上界，下一次上行不得早于该上界加固件3秒延迟及20秒回报窗口。连续指令的等待单独记录，不依赖程序运行缓慢来避免串入旧回报。
- 文本发送准备与启动之间轮询接收结果；不在二进制串口传输中并发读串口。新日志分别记录排队、准备、启动核验和恢复耗时。
- 界面不显示剩余秒或倒计时。依据匹配回报建立有效期上界，到期后提示“转发有效期已过，当前状态待查询”，不会因保守剩余下界耗尽而提前宣告到期；提示可能比板端实际到期晚数秒。真实静音快照与推算过期分别表达。共享提示仅限同一应用获得的测控证据，独立电脑无来源时显示未知。
- 新测控事务实际提交时撤销旧状态；失败、取消或无模式回报时显示未知。匹配的负ACK如果真实报告静音，可显示静音快照，但该指令仍明确标记远端拒绝。

## 开发阶段实板复测

最终实现的首轮完整复测采用 `n256_khz_v1`，业务中心1989.5→2179.5 MHz。三个测控操作均通过真实上行、遥控板解码、UDP执行和DAC射频回报，分别取得4、3、3个匹配的CRC正确帧。

| 操作 | 至射频回报核验 | 至业务接收恢复 |
| --- | ---: | ---: |
| 新连接后设置频率 | 36.16秒 | 41.48秒 |
| 紧接着开启转发 | 23.63秒 | 29.04秒 |
| 业务测试后停止转发 | 17.37秒 | 22.57秒 |

首次操作包含约19秒尚未消耗完的连接隔离时间。紧接开启包含约6秒旧回报隔离。它们不等于无排队、无隔离条件下的执行耗时。

三组双方同时发送共6条独特中文消息全部由对端实际接收，内容、编号和CRC一致。首对提交至显示为6.01/6.23秒；紧接着提交的两对为7.63–8.02秒，包含队列和最短发射驻留时间。普通发送执行本身约5.3秒。结果显著优于原约19秒发送准备，但尚未达到所有短文本5秒内显示的目标；32字节文本、USB抖动和排队均可能更慢。

此前另完成一轮旧编码兼容测试：三次射频测控和6条双向文本通过。这轮仅作兼容与开发阶段证据，不与最终耗时混合统计。

## 独立整体验收

采用生产终端后台驱动原六线硬件，界面状态另用真实时间的Tk进程核对。业务中心分别为1989.500→2179.500 MHz和1995.123→2185.456 MHz；每组都独立设置两个本地终端和远端转发板。

- 12笔完整射频测控回报逐份从原始I/Q独立重解，11笔正常成功，1笔预期频率不符拒绝（rc=-5），每笔有3–4个匹配CRC帧。拒绝没有被计作操作成功。
- 18条独特中文消息均由对端实际解出，编号、内容和CRC一致，包含双向连续发送、测控期间排队、真实到期后重新开启及手动重试。
- 取消后的文本保留待重试；真实拒绝后的文本也保留待重试。后续成功开启不会自动重发旧文本，只有手动重试后才发送。
- 真实等待五分钟期间，两端分别完成258/253次接收轮询，没有自动续期或重发。随后真实RF状态查询确认转发板mode=2、双路RX增益0 dB、TX衰减89 dB、剩余有效期0；重新开启后双向新文本通过。
- 最终界面不显示剩余秒数，真实时间计时在有效期上界后约0.096秒出现到期提示。主验收进程早先加载的下界计时版本被修正，其提前提示记录不作为最终通过证据；最终界面由独立Tk进程使用同一真实回报验证。补充实板轮次加载最终代码，核对了新上界字段和八个DDS电平的完整静音读回。

| 指标 | 独立实测结果 | 口径 |
| --- | ---: | --- |
| 测控至业务恢复 | 常规22.70–29.48秒 | 含接收暂停、回报核验和恢复；连续操作可能包含旧回报等待 |
| 新连接首次测控至恢复 | 40.94–41.72秒 | 含首次旧回报隔离，不与常规执行混计 |
| 文本发送执行 | 5.39–6.11秒，中位5.55秒 | 不含等待前序任务的队列时间 |
| 无排队文本至对端CRC结果 | 6.26–6.32秒 | 本轮3个无排队样本，不能外推成所有情况下的上限 |
| 双向连续批次首条至CRC结果 | 6.26–11.72秒 | 对端同时准备发射时，串口结果轮询会延后 |
| 一次提交3条的第三条至CRC结果 | 约22–24秒 | 包含前两条执行和最短2秒驻留；不是单条解调耗时 |

独立定向主机测试去重136项通过；界面实现阶段125项回归通过，二者有重叠，不相加统计。另以全部125000个周期起点穷举短采样窗的帧覆盖，最少3个完整帧；这是模拟几何检查，不能算作新增实板事务。

最终恢复默认业务中心1989.5→2179.5 MHz，再通过RF停止转发。两终端发射本振关闭，TX/RX DMA均为0，八个DDS电平均为0；转发板实际本振RX=1989000000、TX=2178999998 Hz，mode=2、RX增益0 dB、TX衰减89 dB。历史削顶计数303→303，本轮增量0。所有控制线程退出、串口与设备租约释放。下次演示仍需明确执行“开启转发”。

结构化摘要和原始证据摘要见[本轮验收数据](20261101_control_latency.json)。本地完整日志保存在 `D:/RelayTools/work/control_latency_20261101/acceptance/`；原始I/Q未加入源码仓库。

## 回归与界限

从修改前真实回报采样中取17个不同起点的131072样本窗口重解，每个窗口恢复3–4个匹配帧，全部CRC通过、无削顶。这是历史采样重放，不计作新增射频事务。

新增主机测试覆盖快速核验中的重启/USB变化、缓存篡改、静音读回不完整、接收进程身份与DMA变化、快速连续事务的旧回报隔离，以及界面到期与状态来源。生成的接收检查脚本通过实际POSIX shell执行的合成文件测试。

第一轮完整主机回归共444项，仍有两个既有最小窗口布局子项断言失败：通信记录区实际高度68像素，旧断言要求大于80像素；旧版本同样失败，本轮未修改该布局要求。

没有增加业务对端ACK、无限期发射或自动续期。没有新增采样序号，因此不宣称零丢样。USB物理失联、掉电启动和第三方固件不属于本轮耗时优化的通过范围。
