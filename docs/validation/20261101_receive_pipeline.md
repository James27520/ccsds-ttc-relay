# 双向终端接收性能与恢复

本次接收性能与分级恢复验收通过，结构化结果见[验收摘要](20261101_receive_pipeline.json)。范围为固定六线、1989.5→2179.5 MHz业务台架及列出的异常分支；不扩展为全频段、零丢样或全系统验收。

## 问题复现

终端2在每秒处理250万组IQ的配置下，曾因一个约229.5万组/秒的统计区间被整端断开。2026-11-01分别测了仅采样、同一真实IQ离线解码、在线采样解码、有限发射、后台轮询。

| 条件 | 终端1 | 终端2 |
| --- | ---: | ---: |
| 仅采样，含启动尾部的10秒计时 | 2.483 MSPS | 2.483 MSPS |
| 真实IQ离线解码，两次 | 3.414–3.475 MSPS | 3.241–3.246 MSPS |
| 在线接收，无主机轮询 | 2.476 MSPS | 2.471 MSPS |
| 在线接收及有限发射，无主机轮询 | 2.475 MSPS | 2.467 MSPS |
| 原后台逐秒轮询，60秒稳态 | 2.50005 MSPS | 2.29004 MSPS |
| 终端2原后台轮询及有限发射 | — | 2.26583 MSPS |

两板CPU均约666.67 MHz；终端1两核在线，终端2由`maxcpus=1`限制为单核。原RX轮询每次11条串口命令，约0.64秒；TX检查另有11次往返，包含完整`iio_info`。单核上的系统/串口检查和DSP竞争是本次主要瓶颈；不能据此判断芯片本身算力不够。原始诊断保存在本机`D:/RelayTools/work/rx_performance_20261101/`，未作为源码上传。

## 修改

- RX每轮合并为一个会话脚本；保留USB、启动身份、进程PID/启动时间、扫描通道、DMA和租约核验。
- TX周期检查改用当前启动身份和合并状态读取，去掉重复`iio_info`。配置、启停仍核验身份。
- 采集线程与DSP之间使用固定2 MiB缓冲，记录积压、高水位、满缓冲事件、各段耗时和CPU统计。离线文件不丢弃；在线满缓冲明确报连续性风险。
- 短时变慢先显示性能下降；持续12秒不足、进度停滞或缓冲满时重建RX。120秒内最多两次自动重建，之后保留连接并等待手动恢复。身份及输入完整性异常仍停止连接。
- 中断后重建DSP状态；保留已收记录和去重历史，不重发旧文本，待发记录需手动重试。

## 验收界限

需分别记录离线解码余量、实际轮询与双向发射中的吞吐和积压、短时负载告警、持续异常的有界恢复、恢复后新消息及历史去重、至少30分钟运行。有效业务内容必须来自真实RF接收，不能以底噪采样速率替代通信验收。原始采样没有硬件连续序号，`loss_measured=false`；即使吞吐正常也不能声称已经证明零丢样。

首轮修改后的终端2仍保持单核，60秒纯RX稳态2.50118 MSPS，队列无满缓冲事件。加入实际发射后仍只有2.26588 MSPS，缓冲持续满，未将该结果判为通过。

随后仅在当前启动内启用Linux已列为present/possible的CPU1（此前由maxcpus=1限制），不改启动参数或存储固件。修改后的20秒RX+有限TX+完整后台轮询为2.49978 MSPS，满缓冲事件0，轮询约0.19秒；长时及故障复核另列如下。

## 审查后补改

- 手动恢复清空自动恢复预算，不占用120秒内的两次自动恢复机会。
- 原生进程最终发布并关闭统计文件、刷新输出后调用`_Exit`，避免libc退出时等待仍阻塞于`fread`的输入线程持有的stdin锁。采集、队列和DSP稳态路径不变。新版本主机回归增加“写入一个无效完整IQ块后仍保持stdin打开”，要求3秒内返回输入错误；已通过。
- 软件最终完整回归执行431项，原有`test_key_workspaces_visible_at_minimum_size`在终端1、终端2各有一个历史记录区域高度断言失败（68像素，要求大于80）；与本次吞吐故障无关，未作为通过项。相关后端、界面、健康状态和快照专项83项通过，包含在私有proc/sys文件夹执行真实POSIX快照脚本的测试。
- 快照先读取并核对完整统计，再输出成功标记；接收进程在身份检查之后、读取统计之前退出时，返回可恢复的`unavailable`。PID复用或仍存在但读取失败仍归为身份异常，不因补偿恢复而放宽身份检查。
- 发送准备期间或本地TX刚启动后，若本会话RX进程退出，也按相同预算恢复。当前发送结果未确认，保留为手动重试；停止已开始的TX，旧文本不重发。
- 进程退出后继续核对其已发布的最终状态：`input_error=true`、空文件或损坏报告仍报输入/完整性错误，不能被进程已退出这一表象掩盖。明确没有状态文件或正常退出状态，才按接收中断恢复。

## 第一轮长测未通过及修正

约19分50秒前，20组、40条双向中文消息均在对端CRC及内容复核通过；两端处理速度约2.500 MSPS，背压、自然RX恢复、削顶均为0。随后终端1出现TX守护到期竞态，整端断开，本轮不能记为30分钟通过。

精确时序为：快照读取`enabled`，deadline为70293，uptime为70292.99；48毫秒后读取守护进程`/proc/23132/stat`时，它已完成正常停发并退出。后续读回`stopped`、TX DMA 0。原因是跨两次读取的正常到期被误判为进程故障。

修正后区分PID消失和PID复用：复用仍拒绝；消失、到期及正在停止的状态需要在有界时间内重新确认`guard_state=stopped`、TX LO关闭、TX DMA关闭三项，才能按正常停发处理。未确认停发仍按异常处理。该实测时序及状态文件短暂写入边界已加入回归测试。

## 第二轮30分钟实测

固定六根SMA连接不变，业务中心1989.5→2179.5 MHz，使用生产终端后台，两个接收进程连续运行1800.084秒。每分钟两端各提交一条带新编号的中文文本，本地TX每次受30秒保护，到期停发；这不是连续满占空比发射测试。转发板的300秒租期由诊断UART/UDP续期，本轮不计为新的射频测控协议验收。

| --- | ---: | ---: |
| 稳态处理速度 | 2.500028 MSPS | 2.500022 MSPS |
| 最低统计区间速度 | 2.490837 MSPS | 2.490580 MSPS |
| 发出／对端实收独立消息 | 30／30 | 30／30 |

60条消息的编号、中文正文及CRC均在对端匹配；没有把主机发送记录用作接收答案。两个接收进程没有重建，缓冲未持续增长。CRC候选拒绝仍有记录（终端1为3472，终端2为2170），不可将该数直接解释为消息丢包率或BER。

最终ARM原生程序在同一真实ADC采样上各离线解码两次：终端1为3.3451／3.3410 MSPS，终端2为3.3336／3.3390 MSPS，均超过3.0 MSPS验收目标；这是纯解码余量，在线吞吐以上表为准。最终二进制SHA256为`0e998d8377e72bc34188274e2ca6be15b4b30e4e7d02a11da445c0d7d346100d`。

长测全程使用最终原生程序和TX到期修正。审查中补充的快照退出分类、忙态RX恢复及最终错误状态读取属于异常路径，另由长测后启动的新进程验证，不将早先长测追认成这些故障分支已被触发。

## 实板故障与恢复

长测释放设备后，用最终源码新建两个终端后台。在终端2的当前会话中核实PID及启动时间后，对所持有的reader发送TERM；未改变USB、接线、板卡固件或ADC格式。

| 注入条件 | 观察到的结果 |
| --- | --- |
| 快照已检查身份、尚未读取进程统计时退出 | 返回完整`unavailable`，无部分成功快照；19.19秒内重建RX，连接保留 |
| 第二次reader退出 | 17.24秒内重建RX；自动恢复次数为2 |
| 120秒内第三次退出 | 5.14秒内停止本端TX/RX并进入暂停；连接、历史保留，不继续自动重建 |
| 显式手动恢复 | 自动恢复预算归零；随后一组双向新中文消息实收 |
| 生产发送准备期间reader退出 | 当前消息标为待手动重试；约29.06秒内恢复接收，连接保留；随后另一组双向新消息实收 |

该阶段基线与恢复后共6条独立消息均通过RF、CRC、编号及正文核对，接收记录没有重复添加。旧TX和待重试文本均未自动重发。短时下降／持续不足的阈值使用此前真实吞吐轨迹回放核对，没有现场注入额外CPU竞争；实际进程退出恢复与轨迹回放分别计证据。

原生退出错误另在ARM上以隔离FIFO复现：本轮初版双线程候选在输入线程持有stdin锁时无法及时退出，最终版本在SIGTERM或无效S12输入后均在1秒观察窗口内结束。将这些真实最终状态用于退出原因分类回放，正常停止可恢复，无效输入及损坏报告保持明确失败；这不等同于故意破坏真实ADC配置。

故障测试准备中曾被上传防覆盖及重复诊断序号保护拒绝，拒绝记录保留；使用新的临时文件和未使用序号后完成上述测试，没有关闭产品保护。原始证据保存在本机`D:/RelayTools/work/rx_pipeline_acceptance_20261101/`，第一轮失败、准备失败与最终通过目录分开保存。

## 收尾与覆盖限制

实际RF事件另行回放到生产Tk页面，核对发送／接收历史无重复、暂停时禁止发送并显示恢复按钮；这是界面事件回放，不作为新的GUI人工点击实测。CPU1在前置实板试验已启用，长测时两核均在线；连接时自动启用的条件分支以单元测试核对，没有为了复测该分支而重新断电。

结束时两端TX本振关闭、TX/RX DMA均为0，转发板mode2、TX衰减89 dB、RX增益0 dB。遥控板恢复`network on`及`service standby`，确认监听启用、pending=0、DAC空闲；没有重发旧遥控或增加UDP执行序号。全部后台线程退出，四个串口释放。再次演示需重新打开终端窗口、连接本地板卡，并通过测控开启远端转发；接线保持不变。

测控整体约92秒的操作耗时、USB连接长期可靠性、掉电自启动及无丢样证明仍需分别处理。本次没有通过降低采样率、更改业务帧协议或放宽设备身份检查取得通过。
