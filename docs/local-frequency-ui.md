# 本地终端调频与转发板测控

2026-11-01。三个窗口分别承担两个本地终端和一个远端转发板的配置。此前同进程自动跟随远端频率的行为已取消，避免把单机界面联动误解为跨电脑空口协商。

| 窗口 | 可编辑参数 | 作用对象 |
| --- | --- | --- |
| 终端1 · 双向通信 | 本机发送中心、本机接收中心 | 电脑1所连接的终端1 |
| 终端2 · 双向通信 | 本机发送中心、本机接收中心 | 电脑2所连接的终端2 |
| 终端1 · 转发板测控 | 转发输入中心、转发输出中心；开启、停止、查询 | 经遥控板/UDP控制的LDSDR |

通信页统一编辑中心频率，发送1980.100–2009.900 MHz、接收2170.100–2199.900 MHz，步进0.001 MHz。未扩展硬件或协议范围。输入框是草稿，下方“已应用”来自本机本振回读换算，TX中心=TX LO+0.5 MHz，RX中心=RX LO−0.25 MHz；不是频谱测量。接收正文下的载频估计来自实际采样解调。

连接前可以编辑频率，连接时应用本机草稿并启动接收。连接后修改参数须点击“应用本机频率”；未应用或精度/范围无效时禁止发送。应用新频率先停TX、释放旧RX，再配置并恢复接收；旧已发文本不重发，未发文本保留待手动重试。提交阶段拒绝时保留原连接与已应用参数；实际配置过程中发生硬件错误则清理并断开，不显示应用成功。测控占用期间不能应用本机频率，结束后恢复原本地业务配置。

两个终端独立管理草稿和后台，没有跨页面自动改频，也不传递文本或解码结果。测控射频回报仍严格检查CRC、序号、操作与频率；回报只描述远端。测控期间的新文本仍可排队，但自动发送还要求远端回报频率与本机业务计划相符。

## 操作例

使用1985.123→2180.456 MHz时，两个终端都设置发送中心1985.123、接收中心2180.456，并分别应用。测控窗口设置转发输入1985.123、输出2180.456，收到“设置频率”成功回报后再发送“开启转发”。随后两端收发新文本。改频或开启成功不等于对端收到文本。

测控使用终端1的固定100.5/90.5 MHz收发资源，期间暂歇其业务。遥控板处理指令并经网线控制LDSDR；两台电脑各自通过本地USB配置自己的终端。六根SMA接线不变。跨电脑自动频率协商、掉电自启动和硬件稳定性不由本轮界面修改解决。

## 验证范围

本轮仅运行离线测试和界面预览，不占用用户正在测试的板卡。检查重点为本地调频隔离、远端回报不改本地配置、精度与范围拒绝、测控后恢复原计划、改频不重发旧队列，以及频率不匹配时保留测控队列。实板收发与两电脑迁移需要后续验收。

离线回归：172项通过。覆盖`test_terminal_ui`、`test_ui_unified`、`test_terminal_backend`、`test_frequency_khz`、`test_ui_v2`、`test_ui_v2_business`和`test_terminal_radio`；板卡接口均使用替身，包括1040×800最小窗口下接收统计和操作按钮的可见性检查。
