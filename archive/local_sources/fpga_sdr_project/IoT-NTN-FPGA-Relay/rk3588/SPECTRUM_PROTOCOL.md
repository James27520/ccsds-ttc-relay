# 频谱遥测协议（PL → RK3588）

> 用于方案 A：**PL 做 FFT + 功率谱 + 多帧平均**，只把 1 KB 的频谱传下来。

## 为什么不让 3588 拿原始 IQ

| 项 | 数值 |
|---|---|
| 30.72 MSPS 复数 IQ（int8） | **61 MB/s** |
| 30.72 MSPS 复数 IQ（int16） | **123 MB/s** |
| UART 115200 | **11.5 kB/s** |
| UART 3 Mbaud（上限） | 300 kB/s |

**差 200～1000 倍。串口搬不动 IQ，所以 PL 必须先做数据缩减。**

1024 点频谱 = 1 KB/帧 → **11 帧/秒**，足够连续信道监测。

## 帧格式（小端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | 同步头 | `0xA5 0x5A` |
| 2 | 1 | 版本 | `0x01` |
| 3 | 1 | 标志 | bit0=ADC 饱和；bit1=已平均 |
| 4 | 2 | 点数 N | 1024 |
| 6 | 4 | 采样率 | 30720000 |
| 10 | 4 | 中心频偏 | int32，Hz，相对 RX_LO |
| 14 | 4 | 帧计数 | uint32，会回绕 |
| 18 | 2 | 平均次数 | uint16，1=未平均 |
| 20 | 2 | 噪声底 | int16，dBFS×256（补码） |
| 22 | 2 | 峰值 | int16，dBFS×256 |
| 24 | N | 频谱数据 | uint8，值 = round(dBFS + 128) |
| 24+N | 2 | CRC-16/CCITT | poly 0x1021, init 0xFFFF，覆盖 0..24+N-1 |

**总长 = 26 + N 字节。N=1024 时 1050 字节 → 91 ms @115200。**

### 频谱值编码

```
编码值 = clamp(round(dBFS + 128), 0, 255)

0   -> -128 dBFS   （极弱）
68  ->  -60 dBFS   （典型噪声底）
128 ->    0 dBFS   （ADC 满量程）
```

量化步进 1 dB，最大误差 0.5 dB——对频谱显示和信道检测足够。

数据顺序为 **fftshift 后的顺序**：`f = -fs/2 ... +fs/2`，
第 i 个 bin 对应 `f = (-N/2 + i) × (fs/N) + 中心频偏`。

## PL 侧实现要点

1. **取数点**：从 `adc_data_d1/q1`（RX1 空口信号）取，这才是"频谱监测"的本意。
   若要看转发后的信号，改成取 `dac_data_d1/q1` 并加一个寄存器选择。
2. **加窗**：Blackman-Harris 或 Hann，系数存 ROM（1024×12bit = 1 个 BRAM）。
   不加窗会有 −13 dB 的旁瓣，弱信号会被强信号的旁瓣淹没。
3. **FFT**：Xilinx FFT IP，1024 点，12 位输入，pipelined streaming。
   当前资源占用 DSP 20/80、BRAM 4.5/60，加 FFT 约 +12 DSP、+6 BRAM，**够用**。
4. **功率谱**：`P = I² + Q²`，累加到 32 位。多帧平均就是累加 N 帧后右移。
5. **转 dB**：`10·log10(P)` 用查找表（P 取对数后线性插值）或 CORDIC。
   256 项表 + 线性插值精度约 0.3 dB，够用。
6. **缓冲**：1024×8bit 双口 BRAM，PS 通过 AXI 读。
7. **AXI 寄存器**（在 `axi_ctrl` 上扩展）：
   ```
   0x30 spectrum_ctrl     bit0 启动, bit1 连续模式, bit[2:17] 平均帧数
   0x34 spectrum_status   bit0 就绪, bit1 忙, bit2 ADC饱和, bit[16:31] 帧计数低16位
   0x38 spectrum_addr    读地址（0..1023），读该地址触发递增
   0x3C spectrum_data    读出的频谱字节（低8位）
   0x40 spectrum_noise   噪声底 (dBFS×256, 补码)
   0x44 spectrum_peak    峰值
   ```

## 3588 侧（已实现）

| 文件 | 作用 |
|---|---|
| `spectrum.py` | 帧编解码、CRC、流式解析、合成数据 |
| `channel_detect.py` | 噪声底估计、CFAR、形态学、聚类、跨帧跟踪 |
| `spectrum_tool.py` | 命令行：`demo` / `recv` / `watch` / `png` / `bench` |

**性能实测（RK3588 @1.8GHz，numpy 向量化）：**

| 环节 | 耗时 |
|---|---|
| 1024 点 FFT | 16.9 µs |
| 功率谱 | 6.7 µs |
| **CFAR 检测** | **474 µs** |
| **合计** | **498 µs** |

**UART 每帧要 91 ms，CPU 只要 0.5 ms → CPU 只占 0.5% 预算，GPU 不需要。**

> 检测算法原本有 Python 循环导致 4.4 ms/帧，向量化后降到 0.5 ms（8.8 倍）。
> 这说明**先量再优化**：如果一开始就上 GPU，会为一个根本不存在的瓶颈付出巨大复杂度。
