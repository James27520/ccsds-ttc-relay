## 一、先把结论说清楚

**这个系统分三层，RK3588 是"大脑"，不是"搬运工"。**

| 层 | 谁来做 | 时间尺度 | 干错了会怎样 |
|---|---|---|---|
| **数据面** | **PL（FPGA）** | **硬实时**，81 ns | 丢样、转发中断 |
| **控制面** | **PS（ARM）** | 毫秒级 | 参数写错 |
| **感知面** | **★ RK3588** | **软实时**，10 ms~秒级 | 检测漏报/虚警 |

**一句话分工：**

> **PL 保证"不停"，PS 保证"听指挥"，RK3588 负责"看懂"。**

### ③ 自主决策（还没做）

有了检测结果，3588 可以做闭环：

```
检测到干扰  ──► 自动换频（改 DDC/DUC）
链路质量下降 ──► 调整增益 / 切换模式
检测到多普勒 ──► 计算补偿量并下发
```

**这是"星上自主"的关键**——不用等地面指令，响应快得多。

### ④ 数据面处理（待网线通路打通）

```
PL 采样 → AXI-DMA → DDR → 裸机以太网 92.3 MB/s → 3588 → FFT/检测
```

**带宽已实测 92.3 MB/s，够传 30.72 MSPS 的 int8 IQ（需 61.4 MB/s）。**

### ⑤ 遥测生成（部分）

把处理结果包装成 CCSDS 遥测帧发给地面：

| APID | 内容 | 状态 |
|---|---|---|
| `0x200` STATUS_TM | 计数器 + 参数 | ✅ |
| `0x201` SPECTRUM_TM | 时间戳 + fs + 频点 | ✅ |
| 待加 | 信道列表、干扰告警、态势统计 | ⬜ |

### ⑥ GPU 加速 —— **实测暂时不需要**

**RK3588 真机基准：**

| 环节 | 耗时 |
|---|---|
| 1024 点 FFT | 51.7 µs |
| 功率谱 | 22.8 µs |
| CFAR 检测 | 977.8 µs |
| **单帧合计** | **1052 µs → 950 帧/秒** |

**对比约束：**

| 通路 | 每帧耗时 |
|---|---|
| **CPU 处理** | **0.5 ~ 1 ms** |
| **UART 115200 传输** | **91 ms** |
| **以太网 92.3 MB/s 传频谱** | **0.01 ms** |
| **以太网传 30.72MSPS int8 IQ** | 需要 61.4 MB/s 持续带宽 |

**结论：**

- **走 UART**：CPU 只用 1% 预算 → **GPU 完全不需要**
- **走以太网传 IQ**：CPU 要做全带宽 FFT（30.72 MSPS 持续），这才可能成为瓶颈 → **那时 GPU 才有意义**

> **这就是"先量再优化"的价值。** 我原来的 CFAR 有 Python 循环，4.4 ms/帧；
> 向量化后 0.5 ms（8.8 倍）。如果一开始就上 GPU，会为一个不存在的瓶颈付出巨大复杂度。

**GPU（Mali-G610，OpenCL 齐全）该用在哪：**
- 全带宽持续 FFT（30.72 MSPS 流）
- 多帧相干积累
- 大规模并行搜索（多频点、多波束）
- 调制识别 / 神经网络推理（板子还有 NPU）

### 第 1 步 —— **PS7 使能 ENET0 + 重建 BSP**（唯一风险点）

**为什么必须先做这个：** 它决定走网线还是退回串口。

| 子步骤 | 内容 |
|---|---|
| 1.1 | Vivado 里使能 PS7 的 ENET0，选对 RGMII MIO（对照原理图第 2 页） |
| 1.2 | 重新生成硬件平台 |
| 1.3 | **重建 BSP 让 `xemacps` 驱动生成出来**（这一步有历史失败记录，但 `emacps` 比 `sdps` 常见） |
| 1.4 | 写个最小测试：发一个裸以太网帧，3588 用 `AF_PACKET` 抓 |

**通过标准：** 3588 能收到 LDSDR 发的帧。

### 第 2 步 —— PL 加 AXI-DMA

| 内容 |
|---|
| 从 `relay_path` 输出或 `phy_rx` 输出接 AXI4-Stream |
| 加 Xilinx AXI DMA（S2MM），写入 DDR |
| 加寄存器控制（启动/长度/完成） |

**注意：** 取数点要可选——
- 取 `adc_data_*` = 看**空口**（频谱监测的本意）
- 取 `dac_data_*` = 看**转发后**（验证转发正确性）

### 第 3 步 —— PS 裸机以太网发送

| 内容 |
|---|
| **raw Ethernet 帧**（EtherType 实验值），不写 IP 栈 |
| 从 DMA 缓冲读 IQ，分包发送 |
| 3588 用 `AF_PACKET` 收 |

**为什么不用 TCP/IP：** 点对点链路不需要，裸帧更简单、更快、更可预测。

### 第 4 步 —— 3588 收 IQ 做全带宽 FFT

| 内容 |
|---|
| `AF_PACKET` 收帧 → numpy FFT → CFAR |
| **复用已有的 `channel_detect.py`，完全不用改** |
| 评估 CPU 是否够 → 不够再上 GPU（OpenCL） |

### 第 5 步 —— 控制命令也走网线

一条网线搞定控制和数据，USB 彻底空出来做 JTAG。
