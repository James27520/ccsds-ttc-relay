# SD 卡上电自启动（U-Boot `uEnv.txt` 方案）

> **本文档是踩了两次坑之后的最终方案。** 前面失败的路线记录在文末「走过的弯路」，请勿重复。

---

## 一、目标

让板子**上电就自动跑转发器**，不需要电脑、不需要 JTAG、不需要任何手动命令。

---

## 二、为什么不能自造 BOOT.bin（第一次失败）

Zynq 的 SD 启动镜像 `BOOT.bin` 结构是：

```
BOOT.bin
├── [bootloader] fsbl.elf     第一阶段引导
├── ad9361_top.bit            PL 码流
└── 9361.elf                  PS 应用
```

**关键机制：SD 启动时 BootROM 只把 FSBL 装进 OCM（192 KB），剩下的码流和应用是 FSBL 自己去 SD 卡上读的。**

而这个工程的 PS7 配置里 **SD 控制器是关闭的**：

```
XPAR_XSDPS_0_DEVICE_ID : 没有      ← FSBL 的 BSP 里根本没有 SD 驱动
PCW_SD0_PERIPHERAL_ENABLE = 0
```

于是自造的 FSBL 读不了卡 → **卡死在 OCM 里**（JTAG 抓到 PC=0x638，信箱没有被写入），板子连 Linux 都进不去。

要修就得改 BD 的 PS7 配置、重新生成硬件平台、重建 BSP——**而在 SDK 2018.3 的命令行里让 BSP 带上 `sdps` 驱动非常折腾**（`createbsp` 不生成驱动头文件、`setlib` 不生效、`regenbsp` 清掉手工补的文件）。

---

## 三、最终方案：复用原厂引导链，只改一行文本

原厂 `BOOT.bin` 里的 FSBL 和 U-Boot **本来就有完整的 SD 支持**（板子就是靠它启动 Linux 的）。
我们要做的只是让 U-Boot 在启动 Linux 之前，先把我们的码流和应用拉起来。

### 3.1 U-Boot 的启动链

原厂 `uEnv.txt` 里（从 SD 卡读出的文本，7,585 字节）：

```
bootcmd=run $modeboot
modeboot=sdboot
sdboot=if mmcinfo; then run uenvboot; echo Copying Linux from SD to RAM... && load mmc 0 ... && bootm ...; fi
uenvboot=if run loadbootenv; then echo Loaded environment from ${bootenv}; run importbootenv; fi; if test -n $uenvcmd; then echo Running uenvcmd ...; run uenvcmd; fi
preboot=if test $modeboot = sdboot && env run sd_uEnvtxt_existence_test; then if env run loadbootenv; then env run importbootenv; fi; fi
```

**关键点：`uenvboot` 会检查 `uenvcmd` 变量，如果有就执行它。** 这就是官方留的自定义启动钩子。

而且**我们的应用是死循环**（`while(1) { cli_poll(); }`），所以 `uenvcmd` 执行后 U-Boot 永远回不去，Linux 自然不会启动。

### 3.2 在 `uEnv.txt` 末尾加两行

```
relayboot=echo RELAY_START; load mmc 0 0x1000000 relay.bit; fpga loadb 0 0x1000000 2083846; load mmc 0 0x2000000 relay.elf; bootelf 0x2000000
uenvcmd=run relayboot
```

| 命令 | 作用 |
|---|---|
| `load mmc 0 0x1000000 relay.bit` | 把码流读进 DDR |
| `fpga loadb 0 0x1000000 2083846` | 烧进 PL（参数是**字节数，必须写死**，见下） |
| `load mmc 0 0x2000000 relay.elf` | 把应用读进 DDR |
| `bootelf 0x2000000` | 跳转执行 |

### 3.3 SD 卡上需要有的文件

| 文件 | 大小 | 说明 |
|---|---|---|
| `BOOT.bin` | 1,488,916 | **原厂镜像，不要动** |
| `relay.bit` | 2,083,846 | 我们的 PL 码流 |
| `relay.elf` | 796,408 | 我们的 PS 应用 |
| `uEnv.txt` | ~8,005 | 加了 `relayboot` + `uenvcmd` |
| `uImage` / `devicetree.dtb` / `uramdisk.image.gz` | — | 原厂 Linux，保留不动（回退用） |

## 四、⚠️ 三个必踩的坑

### 坑 1：`uenvcmd` 的值不能含 `${filesize}` / `||` / `===`

原厂写的是 **`if test -n $uenvcmd`——变量没有加引号**。

U-Boot 的 hush 在展开 `$uenvcmd` 时会**递归展开里面的变量**。第一版我写的是：

```
uenvcmd=echo === PL RELAY BOOT ===; load mmc 0 0x1000000 relay.bit; setenv bs ${filesize}; ...
```

结果启动日志里出现：

```
Importing environment from SD ...
test - minimal test like /bin/sh
Usage:
test [args..]              ← test 参数解析失败，判假
Copying Linux from SD to RAM...
```

**实测结论：**

| `uenvcmd` 值 | `test -n` 结果 |
|---|---|
| `relayboot`（1 个词） | ✅ 通过 |
| `run relayboot`（2 个词） | ✅ 通过 |
| 含 `${filesize}` / `\|\|` / `===` 的长命令 | ❌ 失败（test 用法错误） |

**所以：`uenvcmd` 只放一句 `run <变量名>`，真正的命令放到另一个变量里，且那个变量里不要用 `${filesize}` 这类展开。**

**码流长度直接写死**（`fpga loadb 0 0x1000000 2083846`）。重新综合后 `relay.bit` 大小会变，记得同步改这个数字。

### 坑 2：`uenvcmd` 的值必须是能被执行的命令

`uenvcmd=relayboot`（单词）虽然能过 `test`，但 `run uenvcmd` 会去执行一个叫 `relayboot` 的**命令** → `Unknown command` → 继续启动 Linux。

**必须是 `uenvcmd=run relayboot`。**

### 坑 3：U-Boot 存不了环境变量

启动时如果看到：

```
SF: Unsupported flash IDs: manuf 00, jedec 0000, ext_jedec 0000
*** Warning - spi_flash_probe() failed, using default environment
```

说明 **SPI Flash 探测失败，`saveenv` 写不进去**。所以：

- ❌ 不要在 U-Boot 里 `setenv` + `saveenv` 就以为持久化了
- ✅ **唯一的持久化手段就是 SD 卡上的 `uEnv.txt`**

## 五、怎么改 `uEnv.txt`（三种方式）

### 方式 A：读卡器（最简单）

把卡插进电脑，编辑 `uEnv.txt`，末尾加那两行。

### 方式 B：板子的 Linux（不用读卡器）★ 推荐

**板子能读卡就能写卡。** 启动进 Linux（登录 `root` / `analog`），然后：

```bash
mkdir -p /mnt/sd && mount -t vfat /dev/mmcblk0p1 /mnt/sd

# 删掉旧行、追加新行（避免 sed 特殊字符问题）
grep -v '^uenvcmd='   /mnt/sd/uEnv.txt > /tmp/u.new
grep -v '^relayboot=' /tmp/u.new       > /tmp/u2
cat >> /tmp/u2 <<'EOF'
relayboot=echo RELAY_START; load mmc 0 0x1000000 relay.bit; fpga loadb 0 0x1000000 2083846; load mmc 0 0x2000000 relay.elf; bootelf 0x2000000
uenvcmd=run relayboot
EOF

cp /tmp/u2 /mnt/sd/uEnv.txt
sync; umount /mnt/sd
reboot
```

### 方式 C：U-Boot 的 `fatwrite`（板子起不来 Linux 时）

在 U-Boot 提示符下：

```
setenv relayboot 'echo RELAY_START; load mmc 0 0x1000000 relay.bit; fpga loadb 0 0x1000000 2083846; load mmc 0 0x2000000 relay.elf; bootelf 0x2000000'
setenv uenvcmd 'run relayboot'
env export -t 0x3000000
fatwrite mmc 0 0x3000000 uEnv.txt ${filesize}
reset
```

`env export` 会把**整个环境**导出成文本，`fatwrite` 写回卡上，效果持久。

## 六、怎么打断 U-Boot（调试用）

U-Boot 有 3 秒自动启动倒计时（`bootdelay=3`），提示出现时敲任意键即可停在 `Pluto> ` 提示符。

**从上位机自动做：**

```python
# 登录 Linux → reboot → 抓串口 → 见到 "Hit any key" 就发一个空格
# 见 tools 里的 capture_reboot.py / uboot_persist.py
```

如果板子已经卡在别处（比如跑着我们的应用，没有 shell），可以**用 JTAG 复位**：

```tcl
connect
targets -set -filter {name =~ "APU*"}
rst -system
after 2000
targets -set -filter {name =~ "Arm*#0"}
con                      # ← 必须 con 释放 CPU，否则板子停住
```

## 七、验证与回退

### 验证

上电后串口应出现：

```
U-Boot PlutoSDR  (Jul 08 2025 - 22:41:56 +0800)
...
Loaded environment from uEnv.txt
Running uenvcmd ...
RELAY_START
===== PL relay enabled =====
  RX_LO       = 900000000 Hz
  ...
  status      : in=... out=... rc=0
  relay OK
============================
```

**看到 `===== PL relay enabled =====` 即成功。**

### 回退

删掉 `uEnv.txt` 里的 `uenvcmd=` 那一行即可（或整个 `uEnv.txt`），板子就恢复启动 Linux。

**原厂文件全部保留**：`BOOT.bin`、`uImage`、`devicetree.dtb`、`uramdisk.image.gz` 一个都没改。

## 八、改代码后怎么更新

| 改了什么 | 需要做的 |
|---|---|
| 只改 PS 应用（`main.c` / `relay_*.h`） | 重新编译 → 把新的 `9361.elf` 拷成 `relay.elf` 覆盖到 SD 卡 |
| 改了 RTL | 重新综合 → 把新的 `.bit` 拷成 `relay.bit` 覆盖，**并同步改 `uEnv.txt` 里的字节数** |

调试阶段直接双击 `下载转发器.bat` 走 JTAG 更快，不必每次写卡。

## 九、走过的弯路（供参考，别重复）

| 尝试 | 结果 | 原因 |
|---|---|---|
| 自造 BOOT.bin（自编 FSBL） | ❌ 板子卡死 | **FSBL 没有 SD 驱动**，读不了后续分区 |
| 启用 PS7 的 SD0 重新生成 FSBL | ❌ 未完成 | SDK 2018.3 命令行下 BSP 死活带不上 `sdps` 驱动头文件 |
| 串口 uuencode 传 BOOT.bin | ✅ 传输成功（md5 一致） | 但传上去的镜像本身是坏的，白忙 |
| **改 `uEnv.txt` 用 `uenvcmd` 钩子** | ✅ **成功** | **最终方案** |

**教训：改动面越小越可靠。** 复用原厂已验证的引导链、只加两行文本，比自造整个启动镜像稳得多。
