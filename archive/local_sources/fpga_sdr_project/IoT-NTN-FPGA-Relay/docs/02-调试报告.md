# 调试报告 — 从「CPU 软转发」到「PL 硬件弯管转发器」

> 本文记录整个项目从零到硬件跑通的完整过程，包括**每一次误判、每一个坑、每一条根因分析**。
> 所有结论都来自实际文件核查或实测数据，不含推测性描述。

---

## 0. 先回答一个最常被问到的问题：改了 PL 还是 PS？

**两个都改了，但性质完全不同。**

| 部分 | 改动内容 | 性质 |
|---|---|---|
| **PL（FPGA 逻辑）** | 6 个自研 Verilog 模块（转发数据面，约 700 行）；Block Design 重新连线；厂商 `axi_ctrl` IP 扩展 8 个寄存器；ILA 探针重指；时序约束修正 | 🔴 **新增了完整的数据通路** —— 数据第一次真正走 PL |
| **PS（ARM 裸机程序）** | 关闭 AD9361 内部 BIST；修正 TX 衰减单位；改频点与采样率；继电器启动序列 + 健康自检；JTAG 状态信箱；UART 命令行 | 🟡 **只做配置与监测，不碰数据流** |
| **未改动** | AD9361 片内 FIR 系数、时钟链计算（仍由 ADI 驱动自动推导）、PS7 硬件配置、顶层 `ad9361_top.v`（一行没动） | — |

**一句话总结：数据面 100% 搬到了 PL，PS 从「搬运工 + 处理器」变成了「配置器 + 监视器」。**

改动前后对比：

```
改动前：
  AD9361 → PL(LVDS PHY) → ILA(只看不处理)          ← ADC 数据没有下游
  DDS → PL → AD9361 TX                              ← TX 由单音发生器驱动

改动后：
  AD9361 → PL[DDC→隔直→DUC→增益] → AD9361 TX        ← 数据在 PL 内部闭环
  ARM ──AXI-Lite──► 寄存器（只写参数）
  ARM ◄─状态计数器─┘
```

## 1. 起点：原厂工程到底是什么

项目开始时手上有一个可运行的工程 `zynq_dev_fmcomms3.xpr`，以及一个之前"能跑通"的验证：**用 RK3588 通过 USB 控制 SDR，把 900 MHz 的信号转发到 1000 MHz**。

### 1.1 第一次核查就推翻了三个假设

**假设一：「PL 在做信号处理」→ 错。**

解析 `design_1.bd` 的组件清单：

```
ad9361_phy_0      (厂商自研 LVDS PHY)
axi_ctrl_v1_0_0   (厂商自研 AXI-Lite 寄存器，只有 4 个)
dds_compiler_0 + dds_dq_0   (DDS 单音 → TX)
ila_0, clk_wiz_0, processing_system7_0, axi_interconnect_0, proc_sys_reset_0
```

**没有 `axi_ad9361`、没有 `axi_dmac`、没有任何 AXI-Stream 基础设施、没有到 DDR 的数据通路。**

网表更直接：

```
ad9361_phy_0/adc_data_d1  →  ila_0/probe4        ← ADC 只接到 ILA
dds_dq_0/dac_d1           →  ad9361_phy_0/dac_data_d1   ← TX 由 DDS 驱动
main.c 末尾: while(1);                            ← 初始化后 PS 什么都不做
```

这是**「单音信号源 + 示波器」**的裸机 demo，连 ADC→DAC 的转发通路都没有。

**假设二：「工程就是板子上跑的固件的工程」→ 错。**

正在跑的固件（`adi.ad9361` over USB、`ip:192.168.2.1`）是 **ADI 官方 fmcomms2/Pluto 参考设计**，里面有 `axi_ad9361` + `axi_dmac` + AXIS + DDR 通路。**而那个工程的源文件并不在手上。**

两个设计互斥：

| | 厂商裸机 demo（手上有源工程） | ADI 参考设计（板子在跑） |
|---|---|---|
| 数据通路 | 无 | 有 DMA + DDR |
| 弯管转发 | 插入点极干净 | 可行但复杂 |
| 上电即工作 | ✅ | ❌ 依赖主机 |
| 源工程 | ✅ 在手 | ❌ 需从 ADI GitHub 取 |

**决策：走厂商裸机路线做数据面。** 因为弯管转发本来就不需要 PS 参与数据搬运，而且插入点干净得多。

**假设三：「简介里的 PL DDC/DUC 已经在做了」→ 错。**

`config.h` 里明确写着 `#define AXI_ADC_NOT_PRESENT`，`ADC_DMA_EXAMPLE` / `DAC_DMA_EXAMPLE` 全部是注释状态。这个工程**从来就没有过 DMA**。

## 2. 找到插入点

`ad9361_phy` 的端口列表出乎意料地干净：

```verilog
module ad9361_phy(
    output data_clk,                          // 全局数据时钟
    // ===== ADC 输出（DDC 的输入）=====
    output adc_d1q1_valid, adc_d2q2_valid,
    output [11:0] adc_data_d1, adc_data_q1,   // RX1 I/Q, 12-bit
    output [11:0] adc_data_d2, adc_data_q2,   // RX2 I/Q, 12-bit
    // ===== DAC 输入（DUC 的输出）=====
    input  dac_valid,
    input  [11:0] dac_data_d1, dac_data_q1,
    input  [11:0] dac_data_d2, dac_data_q2,
    input  phy_mode                           // 1 = 1R1T, 0 = 2R2T
);
```

**收发在同一时钟域，无需 CDC。** 于是整个弯管转发的核心只需要三行：

```verilog
assign dac_data_d1 = adc_data_d1;
assign dac_data_q1 = adc_data_q1;
assign dac_valid   = adc_d1q1_valid;
```

还有一个意外收获：厂商已经写好了一个 `dds_dq.v`（83 行），接口与需求几乎一模一样，**可以直接照抄结构**。而且 `axi_ctrl` 里已经有一条 `phase_inc` 通路（PS 写频率字 → DDS），正好是"寄存器控制"的现成模板。

### 2.1 从 `phy_rx.v` / `phy_tx.v` 反推出的关键时序

这一步决定了很多设计细节，只能读源码得到：

`phy_rx.v`：
```verilog
// 2R2T: frame 全 1 → 通道1；frame 全 0 → 通道2
// 两个 valid 互斥，且不同拍出现
assign adc_d1q1_valid = rx_1r1t_dq1_valid || rx_2r2t_dq1_valid;
assign adc_d2q2_valid = rx_2r2t_dq2_valid;
// 1R1T 下 adc_d2q2_valid 恒为 0
```

`phy_tx.v`：
```verilog
// dac_valid 是"启动脉冲"而非"每样点使能"
// 它锁存四路输入，然后按内部计数器串行发出：
//   1R1T 用 2 个 data_clk/样点
//   2R2T 用 4 个 data_clk/样点
```

**结论：`dac_valid` 直接由转发后的通道 1 valid 产生即可，不需要额外的节拍计数器** —— 因为 `phy_rx` 的 valid 节奏（1R1T 是 1/2 拍、2R2T 是 1/4 拍）与 `phy_tx` 需要的发送序列周期完全一致。

同时得到 `DATA_CLK` 与采样率的关系：**2R2T 模式下 `DATA_CLK = 4 × 每通道采样率`**。这个关系后来成了时序问题的关键。

## 3. AD9361 的两个反直觉事实

读 UG-570（128 页）得到两个影响架构决策的事实。

### 3.1 拿不到原始 ADC 数据

手册第 34 页的 LTE 10 MHz 例子：

```
ADC ─► HB3/DEC3 ─► HB2 ─► HB1 ─► Rx FIR ─► 输出
(245.76MHz)  (÷2)    (÷2)   (÷2)   (÷2)    15.36 MSPS
```

**ADC_CLK 高达 245.76 MHz，而接口上限只有 61.44 MSPS。片内必须先抽取才能出芯片。**

⇒ 「PL 从 ADC 裸数据开始做全数字 DDC」这条路**在 AD9361 上物理不成立**。PL 的 DDC 是在片内已抽取、已抗混叠的 IQ 上做的**第二级**处理。

### 3.2 片内已经有一个 128 抽头可编程 FIR

收发各一个。所以在往 PL 里写 FIR 之前，先问它能不能满足——能的话直接省下宝贵的 DSP48。

### 3.3 那么 PL 做上下变频的价值是什么？

不是"LO 搬频那一下"（那本来就是模拟混频器 + PLL 干的），而是 AD9361 做不到的四件事：

| # | 价值 | 为什么 AD9361 做不到 |
|---|---|---|
| 1 | **频偏/多普勒的连续相位、快速补偿** | RF LO 是 PLL，调谐离散、有建立时间、跳频引入相位不连续 |
| 2 | **多信道并行信道化** | 片内只有一条滤波链 |
| 3 | **数据率压缩**（为星上存储与遥测） | 片内最低输出就是接口速率 |
| 4 | **窄带抗干扰滤波 + 可控 AGC** | 片内 AGC 时间常数不受控 |

## 4. 数据面设计

### 4.1 模块划分

| 文件 | 作用 |
|---|---|
| `relay_dq.v` | 顶层：双通道实例化、共享 NCO、控制字 CDC、DAC 输出寄存、诊断计数器 |
| `relay_path.v` | 单通道 9 级 valid 限定流水线，四种工作模式 |
| `relay_cmix.v` | 两级复数混频器（可配置共轭） |
| `relay_nco.v` | 32 位相位累加器 + 象限重构，1/4 波 ROM |
| `relay_cdc.v` | 复位同步 / 多 bit 控制字跨域 / 计数器快照 |

### 4.2 流水线（这一版是最终版，9 级）

| 节拍 | valid | 内容 |
|---|---|---|
| t | `in_valid` | 样点 s 呈现，两个 NCO 推进 |
| t+1 | `vld[0]` | `s_i/s_q` = 样点 s |
| t+2 | `vld[1]` | NCO 输出 cos/sin(s)；DDC 乘积寄存 |
| t+3 | `vld[2]` | DDC 第二级（加法 + 饱和） |
| t+4 | `vld[3]` | DDC 输出 |
| t+5 | `vld[4]` | 旁路选择，**寄存** |
| t+6 | `vld[5]` | 隔直（差值寄存） |
| t+7 | `vld[6]` | DUC 乘积；n4 = NCO(s) |
| t+8 | `vld[7]` | DUC 第二级 |
| t+9 | `vld[8]` | 增益 → `out_valid` |

**每级寄存器都由各自的 valid 位限定**，所以稀疏 valid（2R2T 每 4 拍一个样点）不会样点碰撞。四种模式延迟完全一致，切换模式不会改变 DAC 时序。

### 4.3 资源估算 vs 实测

设计时按 DSP 逐个估算：

```
DDC NCO 复混频   4
DC 阻断          0   ← 泄漏积分器，无乘法器
CIC              —   ← v1 未做
DUC NCO 复混频   4
数字增益         2
─────────────────────
单通道          10  →  双通道 20
```

**实测：DSP48E1 = 20。估算完全命中。**

## 5. 仿真阶段：抓到 2 个真 bug

环境：ModelSim ASE 10.5b（不需要硬件）。
方法：64 点 LUT 产生 fs/64 的复数单音，输出 dump 到文件后用 numpy 做**整周期矩形窗 FFT**（频率与幅度是精确值而非估计值）。

### 5.1 Bug 1：NCO 复用错误

**现象**：T4（DUC 单独工作）输出频率完全不变，只出现一个恒定的 **78.8° 相移**；只有 DDC 与 DUC 频率字相同时才"看起来正确"。

**根因**：`relay_path` 只声明了一对 NCO 输入，DDC 与 DUC 两级混频器**复用了同一个 NCO 的输出**。当 `ddc_freq=0`、`duc_freq=fs/64` 时，DUC 用的是频率为 0 的 NCO ⇒ 只做相位旋转，不搬频。

**为什么读代码没发现**：这个错误只在"两个频率字不同"时暴露，而最直觉的测试（DDC=DUC）恰好掩盖了它。

**修复**：拆成 `ddc_cos/sin` 与 `duc_cos/sin` 两组独立输入。

### 5.2 Bug 2：输出寄存器未复位

**现象**：2R2T 下第二通道首个输出样点为 X（dump 出 `x x`）。

**根因**：`relay_path` 的 `s_i/s_q`、`d_i/d_q`、`o_i/o_q`、`n1/n2`、旁路延迟线全部无复位，上电后到首个 valid 之间保持未知态。

**修复**：为全部流水线寄存器补上同步复位（硬件代价为 0）。

### 5.3 仿真结果：12/12

| 编号 | 验证内容 | 结果 |
|---|---|---|
| T1 | NCO 相位精度（直流输入 → 输出即 NCO 相量） | 幅度 2046.3（理论 2046.0） |
| T2 | 旁路直通 | 位精确 |
| T3 | DDC+DUC 级联，净变换 0 | 1998.6（理论 1998.0） |
| T4 | **DUC 单独搬频 +fs/64** | +960.0 kHz（理论 +960.0） |
| T5 | DDC 单独搬频 −fs/64 → 直流 | 直流 1997.8，**残差 std 0.65** |
| T6 | 静音 | 全零 |
| T7 | 数字增益 0.5 | 999.5（理论 999.5） |
| T8 | 过驱动饱和 | 峰值 2048，100% 饱和 |
| T9 | **2R2T 稀疏 valid，双通道** | ch1/ch2 均 +240.0 kHz |
| T10 | 2R2T 净变换 0，双通道 | ch1/ch2 均 +120.0 kHz |

**这两个 bug 都无法靠阅读代码发现。这说明了先建仿真环境再上板的必要性。**

## 6. 构建阶段：3 个工具链问题

### 6.1 问题一：Block Design 的 IP 端口不刷新

**现象**：给 `repo/axi_ctrl` 打了补丁、也执行了 `update_ip_catalog -rebuild`，但 BD 里的 `axi_ctrl_v1_0_0` 单元始终只有原来的 4 个用户端口。

**根因**：解析 `design_1.bd` 的 JSON 发现，它**只保存 `vlnv` 和 `xci_name`，不保存端口列表**。端口来自「生成的 IP 产物」目录 `bd/design_1/ip/design_1_axi_ctrl_v1_0_0_1/`，而那是缓存，不会因为 `component.xml` 变化而失效。

**修复**：删除生成产物，强制 Vivado 按新定义重建。

```bash
rm -rf zynq_dev_fmcomms3.srcs/sources_1/bd/design_1/ip/design_1_axi_ctrl_v1_0_0_1/
rm -rf zynq_dev_fmcomms3.ip_user_files/bd/design_1/ip/design_1_axi_ctrl_v1_0_0_1/
rm -rf zynq_dev_fmcomms3.cache/
```

**并且顺序很重要：必须先重建 IP、再改 BD。** 顺序反了会出现更隐蔽的问题——脚本检测不到新端口，**静默退化成用 `xlconstant` 常量把控制口固定住**：转发本身能用，但软件改不了频率字。

### 6.2 问题二：`connect_bd_net` 不是幂等的

**现象**：第二次运行 BD 脚本时报 `all ports/pins are already connected to '/Net'`。

**修复**：写一个 `safe_connect` 包装，先检查两个 pin 是否已在同一 net 上，是则跳过。

### 6.3 问题三：端口名不匹配（最隐蔽的一个）

**现象**：BD 改动"成功"了，但 `relay_dq_0/ctrl_*` 全部被接到了 `xlconstant` 上而不是寄存器。

**根因**：`axi_ctrl` 的端口叫 **`relay_mode`**，而 `relay_dq` 的叫 **`ctrl_mode`**，我的连接函数用了**同一个名字**去两边查找。只有状态口（`status_*`）恰好同名才连上了。

**修复**：`tie_or_connect` 改成接收两个名字（`rl_port` 与 `ip_port`）。

**教训**：这类"看起来成功、实际静默退化"的问题，必须靠**事后验证**捕获。所以构建脚本里加了一步：在综合之前检查生成的 `axi_ctrl_v1_0_S00_AXI.v` 里是否真的含 `relay_ddc_freq`，不含就报错退出。

## 7. 时序收敛：整个过程

这是整个项目最花时间、也最有价值的一段。

### 7.1 第一次实现：WNS = -8.572 ns，1926 个终点失败

码流虽然生成了，但**不可靠**。

### 7.2 三层原因，逐层剥离

#### 第一层：时钟约束本身就是错的

`toppin.xdc` 里：

```tcl
create_clock -period 4.069 -name rx_clk [get_ports rx_clk_in_p]
```

4.069 ns = **245.76 MHz**。这是 **ADI 参考设计给最高速率（61.44 MSPS × 4）的值**。

而实际配置：2R2T 模式，30.72 MSPS/通道 ⇒ `DATA_CLK = 4 × 30.72 = 122.88 MHz` ⇒ **应为 8.138 ns**。

**顺带发现：厂商原设计本来也不满足这个约束**（WNS = -2.692 ns，129 个终点失败）——他们大概是照抄了 ADI 参考设计的约束值。

修复：改为 8.138 ns，并在注释里写清换算关系 `period_ns = 4000 / sample_rate_in_MSPS`。

#### 第二层：单周期运算太重

关键路径：

```
ROM → 象限取反(CARRY4×3) → LUT → DSP48 乘 → DSP 级联加 → 饱和比较 → 寄存器
数据路径 12.03 ns（要求 4.069 ns）
```

修复（分三步迭代）：

1. `relay_nco` 输出加一级寄存（延迟 1 → 2）
2. `relay_cmix` 拆成两级：`乘积寄存` / `加法+饱和寄存`（延迟 1 → 2）
3. `relay_path` 加深流水线

**第一次重流水线后：片内 `rx_clk` 组从 1926 个失败终点降到 36 个。**

#### 第三层：跨时钟域被互相计时

时序汇总显示，真正的 WNS 来自**跨时钟组**：

| 跨时钟路径 | WNS | 终点数 | 性质 |
|---|---|---|---|
| `rx_clk` → ILA 时钟 | **-8.670** | 224 | ILA 抓异步域数据 |
| `clk_fpga_0` → `rx_clk` | -5.968 | 484 | 控制字（**已有 2-FF + 稳定性滤波**） |
| `rx_clk` → `clk_fpga_0` | -3.424 | 97 | 计数器快照（**已有握手**） |

这些都是**功能上真异步、RTL 里已显式同步**的路径，Vivado 却在互相计时。而且 `rx_clk` 与 ILA 时钟**无公共周期**（Vivado 明确警告 `No common period was found`）。

修复：在 XDC 里显式声明异步域。

```tcl
set_clock_groups -asynchronous \
    -group [get_clocks -quiet rx_clk] \
    -group [get_clocks -quiet clk_fpga_0] \
    -group [get_clocks -quiet clk_fpga_1] \
    -group [get_clocks -quiet -include_generated_clocks sys_clk]
```

#### 补充：寄存器被 DSP 吸收

修完时钟组后还剩 -0.342 ns（36 个终点）。查报告发现：

```
Source:      u_nco_ddc/u_rom/data_a_reg/CLKARDCLK   (RAMB18E1)
Destination: u_path_ch1/v0/B[5]                     (DSP48E1)
```

**Vivado 把 `relay_nco` 的输出寄存器吸收进了 DSP48 的 BREG**，使 `ROM → 取反 → LUT → DSP` 又连成了一条路径。

修复：加 `(* dont_touch = "true" *)`。

### 7.3 最终结果

```
WNS = +0.540 ns     WHS = +0.016 ns     失败终点 0 / 13030
  rx_clk    : WNS +0.540 / WHS +0.016, 0 失败 (5009 终点)
  clk_fpga_0: WNS +2.482 / WHS +0.048, 0 失败 (2608 终点)
```

**时序收敛过程小结：**

| 阶段 | 动作 | WNS | 失败终点 |
|---|---|---|---|
| 初版 | — | -8.572 | 1926 |
| 修约束 | 4.069 → 8.138 ns | -8.525 | 1926 |
| 重流水线 | NCO/cmix 各加一级，path 加深 | -8.670 | 843 |
| + 时钟组 | `set_clock_groups` | （片内已过，跨域排除） | 36（片内） |
| + dont_touch | 阻止 DSP 吸收寄存器 | **+0.540** | **0** |

> 有意思的是：**约束放宽 4 ns 后 WNS 反而几乎没变**（-8.572 → -8.525），这本身就是"关键路径换了一条"的信号——如果只盯着 slack 数字看，会误判成"改了没用"。

## 8. 上机：下载与两个新问题

### 8.1 DDR 控制器被held在复位状态

第一次下载：

```
Memory write error at 0x100000. Cannot access DDR: the controller is held in reset
```

**根因**：`rst -system` 之后 PS 的外设（含 DDR 控制器）处于复位状态，必须先跑 `ps7_init`。

**修复**：下载脚本加入 PS7 初始化。

```tcl
rst -system
after 3000
source .../ad9361_top_hw_platform_0/ps7_init.tcl
ps7_init
fpga -file xxx.bit
ps7_post_config
dow xxx.elf
con
```

### 8.2 JTAG 读不到 PL 寄存器

想通过 JTAG 直接读 `0x43C00000` 的状态寄存器，被 hw_server 拦住：

```
Blocked address 0x43c00010. PL AXI slave ports access is not allowed.
This address has not been added to the memory map.
```

**绕法**：在 DDR 里放一个「**JTAG 状态信箱**」（地址 `0x003F0000`），主循环持续刷新。DDR 在内存映射里，可以直接 `mrd` 读。

```tcl
xsct> connect
xsct> targets -set -filter {name =~ "ARM*#0"}
xsct> stop
xsct> mrd 0x003F0000 8      # [0]magic [1]收 [2]发 [3]饱和 [4]rc [5]心跳
xsct> con
```

这个信箱后来成了**"零丢样"验证的关键手段**，也是 GUI 的备用通道。

## 9. 硬件验证：零丢样

```
read 1 : magic=0x524C4159  in=1,186,590,702  out=1,186,590,714  clip=275,615  rc=0  hb=13433
read 2 : magic=0x524C4159  in=1,264,861,166  out=1,264,861,178  clip=275,615  rc=0  hb=14402
         Δin = 78,270,464   Δout = 78,270,464
read 3 : magic=0x524C4159  in=1,343,057,902  out=1,343,057,914  clip=275,615  rc=0  hb=15368
         Δin = 78,196,736   Δout = 78,196,736
```

**判读：**

1. **`rc = 0`** — 健康检查通过（ADC 有数据 且 DAC 有输出）
2. **Δin 与 Δout 逐位相同** — **零丢样**
3. 78,270,464 / 2.55 s ≈ **30.7 MSPS** = 配置速率 ✓
4. **`in − out` 恒定 = 12**，等于流水线深度 ⇒ 数据是有序流动，不是重复计数
5. **`clip` 三次读数完全不变**（275,615）⇒ 该时间段内无新增饱和

> **这个方法是本项目最有价值的验证手段**：不依赖任何仪器，纯粹用两个计数器的增量比对，就能证明"收多少发多少"。

### 9.1 端到端（CMU200）

```
CMU200 RF2 ──900.100 MHz──► SDR RX1
SDR TX1 ──► CMU200 RF1

实测：转发输出 1000.100 MHz，-36.6 dBm
界面点「+100 kHz」→ 输出移到 1000.200 MHz，波形明显左移
```

**这直接证明 PL 在数字域完成了上下变频，而不是靠 TX_LO 硬件搬频。**

## 10. 上机后又发现的三个问题

### 10.1 负频偏失效（真 bug，已修）

**现象**：GUI 日志显示

```
→ DUC 频偏 +480000 Hz   < OK duc=04000000     ✓
→ DUC 频偏 -100000 Hz   < OK duc=00000000     ✗ 应为 FF2AAAAB
```

**根因**：`relay_freq_word()` 里

```c
double w = ((double)offset_hz * 4294967296.0) / (double)fs_hz;
return (u32)((unsigned long)w & 0xFFFFFFFFUL);   // ← 负数 double 转无符号是 UB
```

负数 double 直接转 `unsigned long` 是**未定义行为**，ARM GCC 上饱和成 0，于是所有负频偏都静默变成 0。

**修复**：经由有符号中间量再截断。

```c
long long v = (long long)(w + (w >= 0.0 ? 0.5 : -0.5));
return (u32)((unsigned long long)v & 0xFFFFFFFFULL);
```

> 这个 bug 从仿真到上机一直存在，因为**仿真里用的是自己算的 32 位字**，绕开了这个 C 函数。**仿真验证的是 RTL，不验证 PS 侧的胶水代码。**

### 10.2 SD 卡会覆盖转发器

**现象**：用户重新上电后，GUI 连上 COM5 却显示登录提示：

```
< Welcome to Pluto
< pluto login: status
< Password:
< Login incorrect
```

**根因**：SD 卡里是原厂 Pluto 兼容固件。**只要卡插着，板子一断电/复位就从卡启动 Linux**，JTAG 下载的转发器消失。

**应对**：开发期间**拔掉 SD 卡**（`ps7_init` 会把 PS 和 DDR 都初始化好，不依赖任何启动介质）。要真正上电即工作，需要做 SD 卡的 `BOOT.bin`。

顺带修了 GUI 的盲区：串口打开本身从不失败，所以"已连接"是假象。现在连上后 1.8 s 内收不到 `STAT` 会明确提示"板子跑的不是转发程序"。

### 10.3 `bootgen` 命令行不可用（环境问题，未解决）

尝试生成 SD 卡启动镜像时：

```
$ bootgen -image relay.bif -arch zynq -o BOOT.bin -w on
****** Xilinx Bootgen v2018.3
exit=0                              ← 报成功

$ 检查输出
size = 2,417,424 字节
magic = FE FF FF EA                 ← 应为 AA 99 55 66
内容  = "FE FF FF EA" 重复 60 万次   ← 未初始化缓冲区
三个输入文件一个都没进去（搜索 fsbl/bit/elf 特征均返回 -1）
```

直接调用 `bootgen.exe` 报 `0xC0000135`（DLL 缺失），走 XSCT 环境也一样。

**结论：本机 bootgen 命令行损坏。** SD 卡自启动需走 SDK 图形界面 `Xilinx → Create Boot Image`。

## 11. 症状 → 根因 速查表

| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| GUI 连上但参数栏全空、日志出现 `pluto login:` | 板子从 SD 卡启动了原厂 Linux | 重新 `program_device.tcl`；开发期拔掉 SD 卡 |
| `dow` 报 `Cannot access DDR: the controller is held in reset` | 缺 `ps7_init` | 用仓库里的 `program_device.tcl` |
| BD 里 `axi_ctrl` 看不到新端口 | 生成产物缓存未失效 | 删 `bd/.../ip/design_1_axi_ctrl_v1_0_0_1/` + `reset_target`/`generate_target` |
| BD "改成功"但频率字改不动 | 控制口被 `xlconstant` 固定 | 检查端口名映射（`relay_*` vs `ctrl_*`），确认构建脚本第 6 步的校验通过 |
| 时序大面积失败、跨时钟组为负 | 缺 `set_clock_groups` | 见 `toppin.xdc` |
| 片内 `rx_clk` 时序差一点点 | 寄存器被 DSP 吸收 | 加 `(* dont_touch = "true" *)` |
| 负频偏无效果（回 `duc=00000000`） | 负数 double 转无符号 UB | 用 `relay_reg.h` 里的修正版 `relay_freq_word` |
| 转发不出信号 | TX 衰减过大 / RX 增益过小 / BIST 未关 | 见下节 |
| 中心频点有杂散单音 | AD9361 RX 本振泄漏 | 界面里把「隔直」设 1 |

## 12. 结论

### 做成了什么

- **数据面 100% 下沉到 PL**：DDC / 隔直 / DUC / 数字增益全部在 FPGA 内部闭环，PS 不参与数据搬运
- **零丢样**：连续 2.55 s、7800 万样点，收 = 发，逐位一致
- **数字变频在硬件上验证通过**：CMU200 上可见波形随寄存器设置左右移动
- **资源可控**：20 个 DSP48（25%），时序收敛（WNS +0.540 ns）
- **可观测**：串口命令行 + 零依赖 PC 图形界面 + JTAG 状态信箱，三条独立的观测通道

### 走了哪些弯路（供后来者参考）

1. 以为 PL 在做信号处理 → 实际是纯直通 DMA
2. 以为手上的工程就是板子在跑的固件 → 实际是两个完全不同的设计
3. 以为 `dac_valid` 是每样点使能 → 实际是启动脉冲
4. 以为 `create_clock -period 4.069` 是真实需求 → 实际是参考设计的最大值
5. 以为 slack 没变说明改动无效 → 实际是关键路径换了一条
6. 以为仿真通过就万事大吉 → PS 侧的胶水代码（`relay_freq_word`）从未被仿真覆盖

### 后续方向

| 优先级 | 事项 | 说明 |
|---|---|---|
| P1 | SD 卡 `BOOT.bin` | 上电即工作，脱离 JTAG。需走 SDK 图形界面绕过损坏的 bootgen |
| P1 | ILA 时钟改接 `data_clk` | 现在 ILA 抓的是异步域数据，波形混叠，无法用于诊断 |
| P2 | CIC 抽取 + 信道 FIR | 窄带信道化模式，剩余 60 个 DSP48 足够做 2~3 个信道 |
| P2 | 闭环 AGC | 当前是手动增益 |
| P3 | 多普勒闭环 | 接口已就绪，`relay_ddc_freq` / `relay_duc_freq` 可被外部算法实时写入 |
| P3 | 轻量 AXI DMA → GPU 感知面 | DDC 后 0.8 MB/s，Xilinx 自带 AXI DMA 即可 |
