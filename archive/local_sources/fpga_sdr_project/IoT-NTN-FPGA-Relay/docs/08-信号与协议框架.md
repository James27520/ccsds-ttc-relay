# LDSDR 信号与协议框架结构报告

> 基于 `E:\LDSDR_010` 工程的实际源码逐行核查，**不含推测**。所有结论都标注了出处文件。

---

## 〇、一句话结论

**这套系统里根本没有"通信协议"的概念——转发数据面是一条没有任何协议封装的裸样点流。**

| 链路 | 本质 | 有协议吗 |
|---|---|---|
| 地面 → SDR | 串口点对点命令（现在）/ USB 网络（原厂） | 是，自定义 ASCII |
| PS → AD9361 **控制** | **SPI**（点对点同步串行） | 是，ADI 芯片手册规定的寄存器读写格式 |
| PL ↔ AD9361 **数据** | **LVDS 源同步并行总线**，裸数据流 | ❌ **没有任何协议**：无地址、无帧头、无校验、无握手 |
| PS → PL 控制 | **AXI4-Lite** | 是，ARM AMBA 标准 |
| **转发功能本身** | **透明弯管（bent-pipe）** | ❌ **不解调、不解码、不看任何协议** |

**"是通讯还是广播模式"这个问题，答案取决于你问哪一层：**

- **对上层业务数据**：是**广播式透明转发**——不做寻址、不做过滤、来什么转什么，PL 完全不知道自己在搬的是 LTE、NR 还是自定义波形。
- **对控制链路**：是**点对点通信**——主从明确、有回执。
- **对 AD9361 数据口**：两者都不是，是**连续时钟同步的裸样点流**。

## 二、链路逐条拆解

### 2.1 上位机 ↔ SDR（现在：串口命令行）

| 项 | 值 | 出处 |
|---|---|---|
| 物理 | USB → **FT4232H** 四通道桥 | 设备管理器中 `USB Serial Converter A/B/C/D` |
| 通道分配 | A = JTAG，B/C/D = 串口（COM4/5/6） | PS UART1 落在 **COM5** |
| 电气 | **UART 115200 8N1**，无流控（软件用 XON/XOFF） | `xparameters.h`: `STDIN_BASEADDRESS 0xE0001000` |
| 协议 | **自定义行式 ASCII**，`\r\n` 结尾 | `relay_cli.h` |

**命令格式**：`<命令> <参数>\r\n`，回执三类：

| 前缀 | 含义 | 例子 |
|---|---|---|
| `OK ...` | 成功，回显生效值 | `OK duc=00D55555` |
| `ERR ...` | 失败 | `ERR unknown command: xxx` |
| `STAT ...` | 状态行 | 见下 |

**状态行格式**（注意 `ddc`/`duc`/`gain` 是**十六进制**，其余十进制）：

```
STAT mode=1 ddc=00000000 duc=04000000 gain=800 dc=0 rxgain=0 txatt=30 \
     rxlo=900 txlo=1000 fs=30720000 in=3134275583 out=3134275578 clip=178051 rc=0
```

**JTAG 通道**独立走 FT4232H 的通道 A，用 Xilinx `hw_server`（TCP:3121）。

**原厂固件的接口完全不同**：Zynq 的 USB OTG 做成复合设备（RNDIS 网卡 192.168.2.1 + CDC-ACM 串口 + Mass Storage），上位机用 `libiio` 走 TCP 访问。**我们现在的裸机程序没有这些。**

### 2.2 PS → AD9361 控制（SPI + GPIO，都走 EMIO）

**关键事实：SPI 和 GPIO 都不走 PS 的 MIO，而是走 EMIO 穿过 PL 到物理引脚。**

出处：`xparameters.h` 里 `PCW_SPI0_SPI0_IO = EMIO`，`PCW_GPIO_MIO_GPIO_ENABLE = 0`。

#### SPI 电气与配置

```c
spi_options = XSP_MASTER_OPTION | XSP_CLK_PHASE_1_OPTION | XSP_MANUAL_SSELECT_OPTION;
XSpi_SetSlaveSelect(&spi_instance, 1);
```
（`platform.c:113-119`）

- PS SPI0 作 **Master**，AD9361 作 Slave
- **CPHA = 1**（`XSP_CLK_PHASE_1_OPTION`）
- 片选手动控制（`spi_csn` 是独立引脚，XDC 指派 **T20**）

#### AD9361 SPI 帧格式（ADI 芯片手册规定）

**16 位命令 + N 字节数据**，大端：

```
 bit15   bit14:12    bit11:10  bit9:0
┌──────┬──────────┬─────────┬──────────────┐
│ W/R  │ 字节数-1  │  保留    │  寄存器地址   │
│0=读   │  0..7    │         │   0..1023    │
│1=写   │          │         │              │
└──────┴──────────┴─────────┴──────────────┘
```

出处 `ad9361.h:2803-2806`：

```c
#define AD_READ     (0 << 15)
#define AD_WRITE    (1 << 15)
#define AD_CNT(x)   ((((x) - 1) & 0x7) << 12)
#define AD_ADDR(x)  ((x) & 0x3FF)
#define MAX_MBYTE_SPI  8          /* 一次最多 8 字节 */
```

**读操作时序**（`ad9361.c:695` `ad9361_spi_readm`）：

```c
cmd = AD_READ | AD_CNT(num) | AD_ADDR(reg);
buf[0] = cmd >> 8;  buf[1] = cmd & 0xFF;
spi_write_then_read(spi, buf, 2, rbuf, num);   /* 先发 2 字节命令，再读 num 字节 */
```

**写操作**：`cmd = AD_WRITE | ...` 后跟数据字节。

> PS 用这套格式配置 AD9361 内部 **约 1000 个寄存器**——包括 PLL、抽取/内插比、FIR 系数、增益表、ENSM 状态机、LVDS 时序等。
> **PL 完全不参与 AD9361 的配置**，它只是 EMIO 信号的"过路人"。

#### GPIO / EMIO 映射（厂商自定义）

```c
#define EMIO_TXNRX   54+0      /* ENSM 的 TX/RX 控制，FDD 下常置 1 */
#define EMIO_ENABLE  54+1      /* AD9361 ENABLE，ENSM 使能 */
#define EMIO_RESET   54+2      /* RESETB */
#define EMIO_SYNC    54+3      /* SYNC_IN 多片同步（本例未用） */
#define EMIO_EN_AGC  54+4      /* AGC 使能（MGC 下置 1） */
#define EMIO_CTL0..3 54+5..8   /* 通用控制，本例置 0 */
```
（`main.c:58-66`，初始化见 `gpio_initial()` at `main.c:400`）

**54** 这个数字不是随便来的：Zynq 的 **EMIO GPIO bank 2 从 54 号开始**。所以 `54+n` = EMIO 第 n 根线。

### 2.3 PL ↔ AD9361 数据（LVDS 双端口）★ 核心

**这不是通信协议，是 ADI 私有的源同步 DDR 并行总线。**

#### 引脚（16 对差分，共 32 脚）

| 方向 | 信号 | 对数 | 说明 |
|---|---|---|---|
| RX | `rx_clk_in_p/n` | 1 | **AD9361 发出**的 DATA_CLK |
| RX | `rx_frame_in_p/n` | 1 | 帧标志 |
| RX | `rx_data_in_p/n[5:0]` | 6 | 数据 lane |
| TX | `tx_clk_out_p/n` | 1 | **PL 用 ODDR 生成**（D1=0,D2=1） |
| TX | `tx_frame_out_p/n` | 1 | 帧标志 |
| TX | `tx_data_out_p/n[5:0]` | 6 | 数据 lane |

每对都用 `IBUFDS`/`OBUFDS` 差分缓冲；接收侧每根线经过 `IDELAYE2`（VAR_LOAD，200 MHz 参考）再进 `IDDR`（SAME_EDGE_PIPELINED）。

**6 lane × DDR = 每个 data_clk 传 12 位。**

#### 帧结构（2R2T 模式，周期 = 4 个 data_clk）

RX 侧（`phy_rx.v:181-216`）：

```
data_clk 拍号:    0    1    2    3    0    1    2    3
frame 电平:      1    1    0    0    1    1    0    0
              ┌─── ch1 ───┐┌─── ch2 ───┐
              2 拍高        2 拍低
```

判决用的是一个 4 位移位寄存器（存最近 2 拍的双沿）：

| `rx_frame_shift_reg` | 含义 |
|---|---|
| `4'b1111` | **RX1** (D1/Q1) 有效 |
| `4'b0000` | **RX2** (D2/Q2) 有效 |
| `4'b1100` | 1R1T 模式下 RX1 有效 |

**数据打包**（24 位移位寄存器 = 2 拍 × 12 位）：

```verilog
// phy_rx.v:196-197
rx_data_d1_reg <= {rx_data_shift_reg[23:18], rx_data_shift_reg[11:6]};  // 12 位 I
rx_data_q1_reg <= {rx_data_shift_reg[17:12], rx_data_shift_reg[5:0]};  // 12 位 Q
```

**即：一个 12 位样点被拆成两次 6 位传输，高 6 位先发。**

TX 侧（`phy_tx.v:104-134`）——4 拍序列，**正好是 RX 的镜像**：

| `{phy_mode, cnt}` | cnt | frame | posedge 发 | negedge 发 |
|---|---|---|---|---|
| `3'b000` | 0 | **1** | `d1[11:6]` | `q1[11:6]` |
| `3'b001` | 1 | **1** | `d1[5:0]` | `q1[5:0]` |
| `3'b010` | 2 | **0** | `d2[11:6]` | `q2[11:6]` |
| `3'b011` | 3 | **0** | `d2[5:0]` | `q2[5:0]` |

#### `dac_valid` 的真实语义 ★

**它不是"每样点使能"，而是"启动脉冲"**：

```verilog
// phy_tx.v:44-50
if(dac_valid == 1'b0 && tx_data_valid_reg == 1'b1 && tx_data_cnt_reg == 'd3)
    tx_data_valid_reg <= 1'b0;            // 跑完 4 拍自动停止
else if(dac_valid == 1'b1)
    tx_data_valid_reg <= 1'b1;            // 收到脉冲就启动
```

`dac_valid` 拉高时锁存 `dac_data_d1/q1/d2/q2` 四路输入（`phy_tx.v:87-92`），随后 TX 状态机自动跑完 4 拍（2R2T）或 2 拍（1R1T）。

**这解释了为什么转发只需要 `dac_valid = adc_d1q1_valid` 延迟一拍——收发的节拍天然一致。**

#### 速率关系

```
2R2T:  data_clk = 4 × 每通道采样率     30.72 MSPS → 122.88 MHz
1R1T:  data_clk = 每通道采样率
```
（这也是 `toppin.xdc` 里 `create_clock -period 8.138` 的由来：`4000 / 30.72 = 130.2`… 实为 `1000/122.88 = 8.138 ns`）

## 三、"通讯还是广播"——分层回答

| 层 | 模式 | 依据 |
|---|---|---|
| **业务数据（转发内容）** | **广播式透明转发** | PL **不解调、不解码、不做任何协议识别**。RX 频段上收到什么就原样搬到 TX 频段。对上层是 LTE / NR / 自定义波形**完全无感** |
| **控制链路（上位机↔PS）** | **点对点通信** | 串口一问一答，有 `OK`/`ERR` 回执 |
| **PS→AD9361** | **点对点通信**（SPI 主从） | 片选明确，无总线仲裁 |
| **PL↔AD9361 数据** | **两者都不是** | 无地址、无帧头、无校验、无握手——是**连续时钟同步的裸数据流** |
| **原厂 Linux 固件** | 网络通信 | RNDIS + TCP/IP + iio |

**为什么转发是"广播式"？**

因为弯管转发器的定义就是**透明**：它工作在物理层/基带层，**不知道也不关心上面跑的是什么协议**。这既是优点（对任何波形都能转）也是缺点（无法按需过滤）。

**唯一带"寻址"概念的地方**是我加的 CCSDS 层——但那一层跑在 RK3588/上位机上，**不经过 PL**。

## 五、数据流的完整时序（2R2T，30.72 MSPS）

```
时刻 ↗
─────────────────────────────────────────────────────────────────────
RF 输入 ──► AD9361 混频 ──► 模拟 LPF ──► ADC ──► 4 级抽取 ──┐
                                                          │
LVDS RX ◄─────────────────────────────────────────────────┘
       data_clk 122.88 MHz, 帧周期 4 拍
       ┌ ch1 (frame=1, 2拍) ┐┌ ch2 (frame=0, 2拍) ┐
       │ I[11:6] I[5:0] Q.. ││ I[11:6] I[5:0] Q.. │
       ▼
phy_rx 解串 ──► adc_data_d1/q1/d2/q2 + adc_d1q1_valid（每 4 拍一个脉冲）
       ▼
relay_dq  ──► relay_path ch1/ch2（9 级流水线，valid 限定）
       │        DDC 复混频 e^-jθ₁ → 隔直 → DUC 复混频 e^+jθ₂ → 数字增益
       │        θ₁ = ddc_freq/2³²·fs    θ₂ = duc_freq/2³²·fs
       ▼
dac_data_d1/q1/d2/q2 + dac_valid（= adc_d1q1_valid 延迟 10 个 data_clk）
       ▼
phy_tx 串化（4 拍序列，帧格式镜像 RX）
       ▼
LVDS TX ──► AD9361 4 级内插 ──► DAC ──► 模拟 LPF ──► TX 混频 ──► RF 输出
─────────────────────────────────────────────────────────────────────

同时（异步）：
PS ──AXI-Lite──► relay_dq 寄存器（参数写入，经 CDC 同步）
PS ◄─AXI-Lite── relay_dq 状态计数器（每 4096 样点快照一次）
PS ──UART──► 上位机 状态行 / 命令回执
```

**关键数字：**

| 项 | 值 |
|---|---|
| data_clk | 122.88 MHz |
| 流水线深度 | 9 级 = 10 个 data_clk |
| 数据面时延 | 10 / 122.88 MHz ≈ **81 ns** |
| 计数器快照周期 | 4096 样点 ≈ **133 µs** |
| 32 位计数器回绕 | 2³² / 30.72 MHz ≈ **140 秒** |
| 收发固定差值 | 21（流水线在途，**不是丢样**） |

## 六、几个容易误解的点

| 误解 | 事实 |
|---|---|
| "PL 在做 DDC/DUC，所以它在处理通信协议" | ❌ PL **只做复数乘加**，不认识任何协议 |
| "SPI 走的是 PS 的 MIO" | ❌ **走 EMIO 穿过 PL**（`PCW_SPI0_SPI0_IO = EMIO`） |
| "`dac_valid` 是每样点使能" | ❌ 是**启动脉冲**，TX 状态机自己跑 4 拍 |
| "转发器是通信设备" | ⚠️ 它是**广播式透明弯管**，不解调不解码 |
| "`in − out` 不为 0 就是丢样" | ❌ 固定差值 = 流水线在途样点数；判据是 **Δin == Δout** |
| "`status` 行一次读全三个计数器" | ❌ **逐个读**，快照更新落在两次读之间会造成恰好 4096 的假差值 |
| "计数器可以长期累加" | ❌ 32 位，**140 秒回绕一次**，必须用模运算 |

## 七、如果要接真实星地链路，还缺什么

| 缺什么 | 说明 |
|---|---|
| **传输帧**（CCSDS 132.0-B / 232.0-B） | 现在只有空间包，没有帧头/虚拟信道/帧计数 |
| **CLTU + BCH 纠错**（CCSDS 231.0-B） | 空口误码保护不足，只有 CRC 检错没有纠错 |
| **统一时基**（GPSDO / 1PPS） | 没有它，多普勒测量与遥测时间戳都不可审计 |
| **加密与鉴权**（SDLS） | 任何能接串口的人都能发遥控 |
| **命令回滚** | 错误参数会直接生效 |
| **多普勒闭环** | 接口已就绪（`RELAY_DDC_FREQ`/`RELAY_DUC_FREQ`），缺的是频率估计算法 |
