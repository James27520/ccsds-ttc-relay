# 以太网通路验证报告

> 2026-10-02 实测。**结论：LDSDR 板载千兆网口可用，实测 92.3 MB/s（739 Mbps），比 UART 快 8028 倍。**

---

## 一、硬件确认

| 项 | 内容 | 出处 |
|---|---|---|
| LDSDR PHY | **RTL8211E Gigabit Ethernet** | Linux 启动日志 |
| LDSDR MAC | Cadence GEM（`macb` 驱动）`rev 0x00020118` @ `0xe000b000` | 同上 |
| 接口模式 | **RGMII-ID** | `configuring for phy/rgmii-id link mode` |
| 3588 MAC | `rk_gmac-dwmac` @ `fe1b0000.ethernet`，RGMII-RXID | 3588 dmesg |
| 连接 | **网线直连**（无交换机，千兆 auto-MDIX） | — |

**原理图第 2 页**：千兆 PHY + 网络变压器 + RJ45，RGMII 接 PS 的 GEM。
（控制链路的 FT4232 USB 见第 1 页，两套完全独立。）

## 三、⚠️ 验证过程中踩的两个坑

### 坑 1：`uenvboot` 会重新导入 `uEnv.txt`，覆盖手动 `setenv`

想启动原厂 Linux 时，我先在 U-Boot 里 `setenv relayboot 'echo SKIP'`，
结果 `run sdboot` 内部的 `uenvboot` 又跑了一次 `loadbootenv` + `importbootenv`，
**把 `relayboot` 覆盖回原值**，转发器照样起来了。

**而且这反过来证明了一件事：`env import` 是会覆盖已存在变量的。**
（之前我以为它不覆盖——那个结论是错的。）

**正确做法：绕开 `sdboot`，手动 `load` + `bootm`：**

```
load mmc 0 0x2080000 uImage
load mmc 0 0x2000000 devicetree.dtb
load mmc 0 0x4000000 uramdisk.image.gz
bootm 0x2080000 0x4000000 0x2000000
```

地址取自厂家 `uEnv.txt` 的 `fit_load_address` / `devicetree_load_address` / `ramdisk_load_address`。

### 坑 2：3588 手动加的 IP 会被 NetworkManager 清掉

用 `ip addr add 192.168.10.2/24 dev eth0` 加的地址**几分钟后就没了**，
表现为「3588 收得到 ARP 请求但不回应」（它已经没有那个地址了），
LDSDR 侧看到 `ip neigh` 一直是 `FAILED`。

**正确做法：用 `nmcli` 配置，抗重置：**

```bash
sudo nmcli con mod 'Wired connection 1' ipv4.addresses 192.168.10.2/24 ipv4.method manual
sudo nmcli con up 'Wired connection 1'
```

### 附带：JTAG 其实一直是好的

`targets` 在 Tcl 里是**返回值不是打印**，我没写 `puts` 所以看着像"链上没目标"。
实际扫描结果：

```
1  APU
2  ARM Cortex-A9 MPCore #0 (Running)
3  ARM Cortex-A9 MPCore #1 (Suspended)
4  xc7z010
   3  xc7z010 (idcode 13722093 irlen 6 fpga)
```

## 四、这把架构彻底改了

### 原方案 A（UART 传频谱）

```
AD9361 → PL[FFT+功率谱] → PS → UART 11.5kB/s → 3588
                                   ↑ 瓶颈
需要：Xilinx FFT IP + 加窗 + dB 表 + 缓冲 + 7 个 AXI 寄存器
```

### 新方案 D（网线传 IQ）★

```
AD9361 → PL[采样] → AXI-DMA → DDR → PS[裸机以太网] → 3588 → numpy / GPU FFT
                                            ↑ 92.3 MB/s，够传原始 IQ
需要：AXI-DMA + 裸机以太网发送
```

**为什么 D 更好：**

| 维度 | 方案 A | **方案 D** |
|---|---|---|
| PL 改动 | FFT IP + 加窗 + dB + 缓冲 | **只要个 DMA 搬运**（更简单） |
| 带宽 | 11 帧/秒 | **原始 IQ 全带宽** |
| 3588 拿到什么 | 已经算好的频谱 | **原始 IQ** → 算法完全自由 |
| 能否用 GPU 做 FFT | ❌ 用不上 | ✅ **正是你最初想要的分工** |
| 控制链路 | UART | **同一条网线**（USB 空出来做 JTAG） |

**核心：PL 不需要做 FFT 了。** 只把 IQ 搬进 DDR，剩下的交给 3588 的 CPU/GPU。

## 五、新的拓扑

```
        ┌──────────────────┐
电脑 ───┤ USB (FT4232H)    │  JTAG + 串口控制 + 调试
        │                  │
        │   LDSDR (Zynq)   │─── 网线 92.3 MB/s ───┐
3588 ───┤                  │                      │
(调试)  └──────────────────┘                      │
   │                                              │
   └──────────────────────────────────────────────┘
              RK3588
```

- **USB 留在电脑** → JTAG 随时可用（改 PL、下载码流、调试）
- **网线连 3588** → 控制命令 + IQ 数据一条链路
- 3588 的调试串口（COM8）连电脑
