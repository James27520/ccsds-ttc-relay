### 2.1  转发板：双通道双向转发 ✅

**需求**：原来只有一组通道（TX1+RX1）。现在要求「基站→终端」和「终端→基站」双向，用上两组通道。转发不做校验。

**通道映射**：
- **ch1 = RX1 → TX1**（馈电上行 → 用户下行）

|---|---|

### 2.5  遥测板 CCSDS FPGA 移植：RTL 完成 + 仿真端到端验证通过 ✅（2026-10 本轮）

详细笔记见 **`E:\ccsds_fpga\PORTING_NOTES.md`**（含全部实测证据）。要点：

**协议核与软件参考有 5 处不一致，其中 4 处会直接导致收不到码，已全部修复：**

| # | 问题 | 现象/后果 | 修复 |
|---|---|---|---|
| 1 | **`ccsds_tx_coder` 根本没有卷积编码**（同目录的 `ccsds_tx_coder_convolutional.vhd` 从未被实例化） | 收到的是未编码帧，Viterbi 解不出 | 在随机化与插 ASM 之间接入 rate-1/2 编码 |
| 2 | **随机化 LFSR 的抽头多项式被位反转** | 序列完全不同，解随机化后全是乱码 | 见下方「升序索引陷阱」 |
| 3 | **BPSK 极性反了**（VHDL bit0→−满量程，Python bit0→+1） | ASM 收到的是补码，永远搜不到 | adapter 里 `INVERT_BPSK=1` |
| 4 | **帧长 12 字节**，而接收端只找 40/108 字节的帧 | 永远找不到 | `DATA_LENGTH := 32`（帧 40B，CADU 672 bit） |
| 5 | SRRC 默认 β=0.5 + Hamming 窗（软件版是 β=0.35、无窗） | 波形不一致、损失眼图余量 | 默认值改成 0.35 / 无窗 |

**★ 最难的一处：`std_logic_vector` 泛型的「升序索引陷阱」**

```vhdl
constant CCSDS_RXTX_LFSR_POLYNOMIAL: std_logic_vector := x"A9";   -- 未约束长度
...
if (CCSDS_RXTX_LFSR_POLYNOMIAL(i) = '1') then ...                  -- 直觉：bit i = x^i
```
字符串字面量初始化**未约束** `std_logic_vector` 时，索引范围是**升序**的，
`POLYNOMIAL(0)` 是**最左边那个字符**（值的最高位）。
于是抽头取成了 `{0,2,4,7}`（= 0x95，恰好是 0xA9 的位反转），而不是 CCSDS 的 `{0,3,5,7}`。

定位方法：把 LFSR 单独拉出来仿真导出 `dat_o`，再用脚本暴力枚举 (掩码×输出端×移位方向)
**从数据本身反解递推关系**，结果精确命中 `mask=0x95`。
修法是加一个归一化函数，不依赖字面量的索引方向。

**★ 端到端仿真验证（决定性）**

用 ModelSim 跑完整发射链，导出真正送进符号映射器的 CADU，交给**已在双板射频环回上验证过的** Python 接收端：

```

SCID=0x02A VCID=0 MCFC=0 FHP=0x000
CRC OK (rx=0x0463 calc=0x0463)   载荷逐字节一致
RESULT: PASS
```

**★ SRRC 的 DSP 问题已解决（原 §3.1）**

加 `attribute use_dsp of rtl : architecture is "no"` 后实测（xc7z010clg400-1，BPSK/OSR=10 全链）：

| SRRC 实现 | LUT | FF | **DSP48** |
|---|---|---|---|
| **`use_dsp="no"`（采用）** | **1832** | 2656 | **0** |
| 默认推断 | 1035 | 1793 | 20 |

基线只剩 24 个 DSP，方案 A 把占用压到 **0**，代价 1832 LUT（余量 9783）。

**★ DAC 注入格式（推翻原 §6.5 假设）**

`bd/system.bd`：`CMOS_OR_LVDS_N=1`（**CMOS**）、`MODE_1R1T=1`；XDC 里 `tx_data_out[11:0]` 是 12 根单端 LVCMOS18。
`ad_data_out.v` 的 ODDR `.D1(tx_data_n) .D2(tx_data_p)`，配合 `cmos_if` 的通道映射 ⇒
**上升沿 = I[11:0]，下降沿 = Q[11:0]，一个 DATA_CLK 周期一对 I/Q**。

因此整条 CCSDS 链直接跑在 AD9361 的 DATA_CLK（= `l_clk`）上：
`clk_i = 2.5 MHz` → 采样率 2.5 MSPS、符号率 250 ksym/s、码率 250 kbit/s、CADU 672 bit/2.688 ms。
**不需要 100 MHz→tx_clk 的异步 FIFO，根本不存在第二个时钟域。**

**★ 不用改 Block Design**

BD 改不了：5 个 ADI 打包 IP 全部 locked，而 `IS_LOCKED` 是只读属性。
但实测 Vivado 允许**一个引脚接两个输入缓冲**（接 `BUFG` 则报 `Synth 8-5535` 非法），
`opt/place` 会把两个 `IBUFG` **合并成一个**并同时驱动两个 `BUFG`
——所以顶层 `system_top.v` 里镜像 `ad_data_clk` 再取一次 `rx_clk_in` 即可，
IP 时钟与注入时钟是同一个网。实验见 `E:\ccsds_fpga\syn\ibuf_test\`。

**⚠️ 已知限制：成帧器（framer/footer/CRC）跑不起来**

实测：无论把 `CCSDS_TX_FRAMER_PARALLELISM_MAX_RATIO` 设成 16/1/2，也无论数据源节流成 1/10/20 个 `clk_dat` 一个字，
**发出的 CADU 逐字节完全相同**（都是启动时那一帧空闲帧：`FHP=0x7FE`、载荷 32×0xFF、MCFC 恒 0）。
定位：握手是通的（数据确实送到成帧器）、编码器没卡死（202 µs 内被触发 681 次），
但每次拿到的都是同一帧——`footer valid` 之后再没拉高过。

两条结构性原因：
1. **相位锁死**：`frame_output_counter` 与 `next_frame_write_pos` 都只在「源送出一个字」时推进，
   而 P=1 时两者重装值相等（都是 16）→ 每帧收满的瞬间恰好是起帧瞬间 → `current_frame_ready` 永远来不及置位。
2. **吞吐不匹配**：P=16（上游默认）时一帧要 4096 `clk_dat`，串行器一帧只要 336 `clk_dat`，慢 12.2 倍。

这套状态机是给慢速 Wishbone 从设备写的。**处置**：按原 bring-up 方案，在 `ccsds_tx_datalink_layer.vhd`
加开关 `CCSDS_TX_DATALINK_STATIC_FRAME_ENABLED`（默认 true），绕过成帧器，
直接把这帧（由 Python 参考实现生成、含正确 CRC）喂给已验证的编码链。
这也顺带绕过了 CRC 种子问题（上游算的是 CRC-16/AUG-CCITT，接收端要 CCITT-FALSE）。
**代价：MCFC 不递增，目前发的是固定帧，还不能承载变化的遥测数据。**

### 3.1  ✅ SRRC 的 DSP 占用（已解决）

见 §2.5。结论：`use_dsp="no"` → **0 个 DSP / 1832 LUT**，遥测板 DSP 余量 24 个完全够用。

```
SRRC 结构: 并行 FIR，每个抽头一个乘法器
抽头数 = OVERSAMPLING_RATIO × RESPONSE_SYMBOL_CYCLES
       = 10 × 6 = 60              ← RESPONSE_SYMBOL_CYCLES 硬编码为 6
系数:   elaboration 时由 real 数学算出 → 综合时是【常量】
样点:   8 bit (SIG_QUANT_DEPTH)，乘法器 ≈ 9×8 → 12 位
```

**解决方案（推荐 A）**：
| 方案 | 做法 | 代价 |
|---|---|---|
| **A** ⭐ | 给 SRRC architecture 加 `attribute use_dsp of rtl : architecture is "no"` | LUT ≈ 900~1500（**余量 9783**）|
| **B** | `RESPONSE_SYMBOL_CYCLES` 6 → 2，抽头变 20 | 带外抑制变差 |
| **C** | 去掉基线的抽取 FIR（遥测发射用不上） | 需改 BD |

**⭐ 系数是编译期常量，Vivado 对常量乘法本可用移位加法（LUT）实现，不占 DSP48。**

## 5  ⚠️ 安全要点（硬件，务必遵守）

```
AD9361/9363 TX 满量程  ≈ +7 dBm（0 dB 衰减时）
RX 绝对最大输入        +2.5 dBm  ← 超过会损伤

上电瞬态（实测）:
  遥测板  ≈ −3 dBm   （默认 TX 衰减 −10 dB）✅ 安全
  转发板  ≈ +4.5 dBm （默认衰减接近 0 dB）  ⚠️ 超过接收端耐压 2 dB

对策:
  ★ 接线状态下【不要重启任何板子】。要重启先拔线
  ★ 串一个 30 dB SMA 衰减器可彻底消除风险
  ★ 用转发板的可编程衰减替代物理衰减器（TX 0~−89.75 dB，RX 0~71 dB，共约 160 dB）

双板环回的安全电平预算:
  遥测板 TX  +7 − 30 = −23 dBm → 转发板 RX (耐 +2.5)  余量 25 dB
  转发板 TX  +7 − 60 = −53 dBm → 遥测板 RX (耐 +2.5)  余量 55 dB
```

## 6  FPGA 移植方案（下一步要做）

### 6.1  注入策略：在顶层拦截 DAC，不改 BD

```
CCSDS 链 (100 MHz 域，clock-enable 推样点)
    |  8 bit I/Q
    v
8 → 12 bit 定标
    |
    v
异步 FIFO (100 MHz → tx_clk 域)
    |
    v
MUX — ccsds_en ? fifo_out : wrapper_out —> tx_data_out —> AD9361
```

**顶层位置**（`system_top.v`）：
```verilog
system_wrapper i_system_wrapper (
    ...
    .tx_data_out (tx_data_out),     // ★ 在这里注入
    ...
);
```

**⭐ 这样完全不动 Block Design，避开「BD 端口列表冻结」那个坑。**

### 6.2  euryspace 接口

entity ccsds_tx is

    CCSDS_TX_MODULATION_TYPE      : 1        -- 1=QPSK  2=BPSK

### 6.4  资源预算

| 资源 | 基线已用 | CCSDS 估算 | 合计 | 余量 |
|---|---|---|---|---|
| LUT | 7817 (44%) | ~3000 | 10817 (61%) | ✅ 够 |
| FF | 14142 (40%) | ~2200 | 16342 (46%) | ✅ 够 |
| BRAM | 2 (3%) | ~4 | 6 (10%) | ✅ 很宽 |
| DSP | 56 (70%) | **60 个乘法器** | 需处理 | ⚠️ 见 3.1 |

### 6.5  ✅ 已证伪（2026-10）

**原假设「1R1T 模式下，12 bit 的 I/Q 样点占 2 个 DATA_CLK 周期（各 6 bit）」是错的——那是 LVDS 格式。**

本板实际是 **CMOS 1R1T**（`bd/system/system.bd` 里 `CMOS_OR_LVDS_N = 1`、`MODE_1R1T = 1`），
XDC 里 `tx_data_out[11:0]` 是 12 根单端 LVCMOS18。引脚格式：
**上升沿 = I[11:0]，下降沿 = Q[11:0]，一个 DATA_CLK 周期传一对 I/Q**（证据链见 `PORTING_NOTES.md` §6）。
所以 **采样率 = DATA_CLK = 采样时钟**，整条链不需要跨时钟域。见 §2.5。
