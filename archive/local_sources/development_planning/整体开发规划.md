### 实施前核实与采用的约束

- 实际 ADDA 的 JTAG 器件为 xc7z020；手册、RevB 原理图及厂商工程对应 `xc7z020clg484-2`。交接包要求改为 `xc7z010clg400-1` 是板卡混淆，不执行。LDSDR 才是本机另一块 xc7z010。
- 空口协议以 `LINK_PROTOCOL_PHY.md` 的三组 20 字节 CADU 金标准为准：100.5 MHz、100 ksym/s、SRRC β=0.35、8 字节命令体、随机化、K=7 卷积码、ASM。K=7 译码为 64 状态，初始状态 0，无尾比特；尝试两种 BPSK 极性，CRC、版本及频率范围均通过才允许交给控制层。
- 当前按用户选择优先验证 ADC 125 MSPS、双通道 DDR 1:8：112 位/31.25 MHz、每通道 4 点，之后每通道每 4 点选 1 点，仍向 C 程序提供 31.25 MSPS。100.5 MHz 在此作为窄带带通采样输入；空口协议不变，DAC 不参与。另保留 ADC 250 MSPS 单通道 SDR 1:8 的对照候选，其首轮条件 STA 已通过；不混用两套源、配置或验收结果。更早的两版双通道 DDR250 时序失败报告也保留。
- 抽取后 31.25 MSPS 的目标混叠频率是 6.75 MHz。原文 6.25 MHz、旧 DAC 角色、删除 ADC、128 状态等内容不采用。平方律对实数输入会产生 DC，载波搜索必须限定到预期的二倍频附近。
- 8 点 boxcar 在 100.5 MHz 会损失约 21.7 dB，不能作为未经验证的默认接收滤波。M2 比较原始抽取诊断路径与数字下变频后滤波路径，再固定接口；这不改变空口格式。
- 65536 点只有 2.097 ms，不能保证任意起点包含一个完整 1.6 ms 帧。初版缓存候选为 131072×16 位（256 KiB，4.194 ms），或有重叠的流式缓存；地址必须自然对齐，点数、字节数、符号格式在 PL/PS 端完全一致。最终资源分配以实现结果为准。
- LDSDR 已有经过历史实板验证的 26 字节 UDP RF_SET，不另造 TCP/SSH 控制。命令中的 MHz 转为该协议的 Hz 大端字段，增益及衰减由显式配置提供；只有匹配的成功回执才记录已应用。当前板上是 UART 诊断固件，不能把历史 UDP 验证当成当前固件已在提供 UDP 服务。

## 4. SMA 直连与 `helloworld` 的实现路线

`helloworld` 是 10 个 ASCII 字节：`68 65 6c 6c 6f 77 6f 72 6c 64`。它要经过组帧、校验、调制变为模拟波形，才能由 DAC/SMA 发送；另一端采集、同步、解调、验 CRC 后恢复文本。用 SMA 电缆可以免去天线和空间传播，但不会绕过两块板的模拟频段、电平与采样约束。

资料表明 ADDA 是 Zynq-7020 + AD9643 双路 ADC + AD9122 双路 DAC，SMA 为 ADC/DAC 模拟接口；它不是 AD9363 接口的同类替代。厂商例程 FPGA 数据率每路 250 MSPS，DAC 配置推导为四倍插值、约 1 GSPS 转换，当前例程输出 1 MHz 固定波形。**这个转换时钟不等于已验证的整板输出带宽。**

AD9363 官方工作频段是 325 MHz–3.8 GHz；旧控制代码接受更宽频率范围不代表芯片在全范围有规格保证。[AD9363 官方资料](https://www.analog.com/en/products/AD9363.html)

AD9122 支持数字频移和插值，AD9643 支持中频采样，因此也不能仅以“250 MSPS/2”就断言所有更高频信号都不可用。但数字频移可能耦合两个 DAC 通道，模拟前端通带、幅度、滤波及 ADC 混叠必须一并设计和实测。[AD9122 数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/AD9122.pdf)

本轮已查完资料目录、板级原理图和例程，**未找到配套外置混频器或上下变频模块的资料/电路**。约 350 MHz 可以作为单路窄带实验候选：利用 DAC 插值与数字频移合成，ADC 以 250 MSPS 带通采样后折叠至约 100 MHz。这只是芯片能力层面的设计推导，尚未在本板实现或测量；细节与双 DAC 通道耦合限制见 [ADDA 专项报告](research/adda_research.md)。

首次接线前需要确认 50 Ω 负载下的输出幅度、偏置和接收口允许电平，不能直接采用厂商满幅例程。专项报告还记录了原理图 U28 供电标注与芯片手册上限不一致的问题，须核实资料修订或实板情况；这不是认定实物损坏，也不影响先做 GUI 与数字算法开发。

**路线选择顺序：**

1. 从厂商例程恢复 ADDA 自身的已知单音输出与采样，确认端口、极性、时钟和幅度。
2. 依据已查到的前端电路与电平限制，在候选共同频段做单音通过试验，并核实上述供电资料疑点。当前没有足够证据承诺 SMA 直接连接一定能通，也没有证据断言必须购买外部射频模块。
3. 单音路径通过后，采用已有 BPSK/CCSDS 代码生成短帧；先降低信息速率，以 `helloworld`、帧序号和 CRC 完整接收为目标。载频、符号率和采样参数写进可复现配置，不沿用旧 900/1000 MHz 或 2.4 GHz 默认值。
4. 优先用两块自有板搭建临时验收环路：ADDA DAC→LDSDR RX→已有转发路径→LDSDR TX→ADDA ADC→电脑解码。这个环路是开发测试夹具，不改写最终草图的通道分配。
5. 两端频段没有可验证交集时，再评估外部变频方案或其他可用接入点；先形成具体参数和器件需求再决定，不预先采购或下载大型工具。
6. 自有板链路通过后，与队友的模拟板/电脑2接通单向信息传输，再做反向和并发运行。

LDSDR 透明转发不必解析 `helloworld`；最终接收端应恢复文本。用电脑抓取样点解码适合初期定位，若竞赛要求板上自主接收/解码，后续把相同算法与向量移入 PL/PS 并独立验收，不能把 PC 解码包装成板上解码。

```text
  └─ 应用服务：组帧、参数校验、请求序号、超时、结果与证据记录
      ├─ 离线设备后端：独立测试向量、模拟收发
      ├─ ADDA 后端：控制命令、波形装载、触发采集、采样块读取
      └─ LDSDR 后端：现有 UDP RF_SET + UART 调试/独立读回

ADDA：PS 命令/缓存管理 ↔ AXI 寄存器、缓冲/DMA ↔ PL 波形/采集 ↔ ADC/DAC
LDSDR：PS 解析/检查/应用/读回 ↔ 原有控制寄存器 ↔ 双路 DDC/DUC 转发
```

电脑1与ADDA优先考虑已有千兆网口作为数据通路，USB DEBUG 保留 JTAG/UART 调试；这是工程建议，仍需用户确认可用接线。首通不需要持续上传满速 ADC：可先板上周期回放短波形、触发采集有限样点、上传电脑解码。是否采用裸机 lwIP、Linux 驱动或 IIO，应以现有工程可重建性决定；不会因有网口就假定厂商已经实现远程采样。

双路 ADC 原始量为 `2 × 250 MSPS × 14 bit = 7 Gbit/s`，按 16 位容器则为 **8 Gbit/s**，超过单千兆网口。因此连续 GUI 显示应使用板上抽取/DDC、触发分段或摘要数据；DAC 波形预装到缓存重复播放。数据块协议要带通道、格式、采样率、序号、样点数量和丢块信息，不能把网络到达时间当作 ADC 采样时钟。

正式业务控制链按草图预留：电脑1→ADDA→遥控板→网口→LDSDR。电脑1直接 UDP 控制 LDSDR 可保留为工程调试入口，但不能用它替代尚未验收的遥控链。最终控制入口和 ACK 回传路径需要与队友统一。

## 6. 先冻结的接口合同

合同文档由主 agent 维护，各子 agent 按同一版本实现。字段变动先更新合同和黄金向量，不能各自定义相似但不兼容的格式。

| 接口 | 必须约定的内容 |
| --- | --- |
| 电脑1↔ADDA | 连接方式、设备发现、控制端口、命令序号、波形/采样格式、缓存边界、采样率、触发、超时/丢块处理 |
| ADDA↔各板模拟口 | 发/收端与物理通道、真实信号或 I/Q、载频、带宽、调制、符号率、幅度/负载、是否需衰减/隔直 |
| CCSDS/业务消息 | TM帧与Space Packet的层次、文本/参数类型、字节序、长度、CRC、填充、序号、错误拒绝 |
| 遥控板↔LDSDR | 以太网角色和地址、兼容旧 RF_SET 还是新版本、应用结果、读回、失败恢复和应答路由 |
| LDSDR 内部控制 | 两路映射、共享 RX/TX LO 与各路 DDC/DUC、mode 枚举、增益单位、更新原子性 |
| GUI 状态 | 模拟/实测来源、已发出/已接收/已应用/读回一致、频率配置值与独立测量值区别 |

现有 GUI 参数区是 32 字节小端字段；旧 UDP RF_SET 是 26 字节自定义包，RX/TX Hz 等字段大端。两者不能直接互传。`tm_params.py` 与 `relay_link.py` 对 mode=0..3 的含义也不同，必须有明确映射。旧协议还存在 CCSDS 类型位/长度字段的兼容偏差，详见 [电脑端审查](research/host_software_review.md)，后续升级应保留旧固件兼容路径。

## 7. 主 agent 与三个子 agent 的执行安排

本轮已由三个只读子 agent 分别审查 ADDA、LDSDR/参考资料和仓库 RTL/仿真；主 agent 审查电脑端、核对证据、研究官方参考并编写本规划。以下为实施阶段分工，不是新增人员或给队友分配任务。

| 执行者 | 负责范围 | 必须复用的输入 | 交付与验收 |
| --- | --- | --- | --- |
| 主 agent（本机） | 总体接口、方案选择、合并审查、硬件调度、端到端验证与记录 | 本规划、用户确认、三方代码和历史证据 | 统一接口文档、可重建集成版本、实测报告；核验成功信号来源 |
| 子 agent A：ADDA | ADC/DAC/时钟、波形缓存与采样、PS控制与数据上传、ADDA板级工程 | `D:\Z7ADDALite资料` 厂商例程；既有编码模块按需适配 | 可配置单音、动态文本波形、有限采样回传；保存真实样点和时钟/端口配置 |
| 子 agent B：LDSDR | 复用双路转发、整理 UDP RF_SET、寄存器/通道能力、状态与恢复 | `LDSDR_010` + `relay_udp_work` 已验证软件 | 原 7 项用例回归；正确通道映射、两路独立频移；可重复构建及加载说明 |
| 子 agent C：电脑软件 | 原 GUI 的路径/依赖修复、设备后端、文本收发、解码显示、日志与错误处理 | `sw/gui`、`sw/ccsds`、`sw/link`、本地缺失解码参考 | GUI 离线可启动；黄金向量一致；硬件结果与模拟结果明确；采样和日志可导出 |

代码路径拟由 A 负责 `fpga/adda`、`ps/adda`，B 负责 `fpga/relay`、`ps/relay`，C 负责 `sw`；这些目录尚未新建，开始实施时再结合仓库惯例确定。公共 RTL、协议文档及测试向量由主 agent 协调归属，避免多人同时改同一份副本。已有 `rtl`/`fpga/src/ccsds` 的 34 份重复源码应明确唯一维护来源，再生成/引用副本。

三个子 agent 可并行做源码工作；串口、JTAG、网口与两块实物由主 agent 统一安排，避免一个任务复位或改频时另一个正在采样。后续有代码改动时采用独立分支/适合的工作区隔离，不覆盖用户已有工程，也不自动推送共享仓库。

| G2 ADDA 单板 | 厂商单音复现；动态波形/采样缓存；电脑控制与采样上传 | 实测波形、原始 ADC 样点、通道/极性/样率记录；本板模拟回环文本恢复 | 板级工程和电平确认 |
| G3 LDSDR 整理 | 双路 RTL 与 UDP 软件版本对齐；原有改频能力回归 | 原 7 项控制用例、独立 SPI 读回、对应 PL/PS 哈希；通道计数/映射证据 | 以现有 LDSDR 基线为准 |

| G5 团队联调 | 电脑1到电脑2单向；遥控板通过网口控制 LDSDR；验证改频后业务 | 两端日志关联、命令/应答对应、读回及业务恢复证据 | 队友端格式、端口和 ACK 路由一致 |
| G6 完整系统 | 反向/双向、重复指令、长时间传输、断线恢复；按要求固化启动 | 规定时长/帧数下成功率、延时、丢帧；重启结果和可复现操作记录 | 并发目标与最终性能门槛确认 |

G4首通首先证明一帧确实经过实际通路；随后增加连续帧和独立时钟/频偏测试。具体速率、持续时间、误码率与延迟门槛待接口及竞赛要求确定，不预填“零误码”或“满速”结论。

硬件验收分别记录“收到命令”“配置应用”“SPI读回”“频谱/采样变化”“内容恢复”。10月18日已经验证其中部分控制层，不重复包装成信号链全部通过。现有固件为 JTAG 内存加载，尚未生成冷启动镜像；上电自主运行是后续明确的交付项，而不是已有能力。

用户不需要代替开发者选择芯片寄存器或计算频点。硬件参数由我们查证与实验，以下仅保留影响系统目标和队友接口的问题。

| 编号 | 需明确的事项 | 当前建议或处理 |
| --- | --- | --- |
| Q1 | GUI 首版除文本发送/接收外，哪些功能必须有？电脑1与ADDA是否可用网线？ | 建议先做文本、连接状态、转发参数/真实读回、日志；网口传数据，USB用于调试。已发出的 GUI 问题待答 |
| Q2 | 草图是否明确要求 LDSDR RX1→TX2、RX2→TX1？还是端口编号可按现有 RX1→TX1、RX2→TX2 调整？ | 不从线条位置猜测；先用现有同号转发测试夹具，最终接线表留待确认 |
| Q3 | 第一阶段是否先单向首通，最终是否两向同时工作？`helloworld` 最终在电脑2显示是否符合预期？ | 规划先自有板环回，再电脑1→电脑2，最后反向/同时工作；属于建议顺序 |
| Q4 | 正式改频命令是否必须经 ADDA→遥控板→网口→LDSDR？队友返回执行结果的接口是什么？ | 按草图预留正式遥控路径，电脑直连UDP作为工程测试；ACK路由须共同确定 |
| Q5 | 竞赛是否要求解调/CCSDS全部在 FPGA，还是允许首版电脑解码？ | 初期电脑解码便于诊断；最终执行位置以明确的验收要求为准 |

红圈意义不再作为阻塞项；实物为同一块 LDSDR 已确认；信号业务内容采用 `helloworld`。如果 Q2/Q4 的团队约定暂时没有结论，可以先完成 G1 与独立板级验证，不编造最终系统映射。
