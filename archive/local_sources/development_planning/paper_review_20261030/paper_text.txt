[0] 面向6G非地面网络的卫星测控与变频转发验证系统
[1] 摘要
[2] 本作品构建基于AMD Zynq-7000与软件无线电的卫星测控及变频转发验证系统。两块7010分别承担发射与接收，Z7ADDALite承担遥控，LDSDR承担业务转发。遥控板PL完成高速ADC接口、采集缓冲与自检，PS以裸机C完成解调、译码及指令解析，并通过以太网配置转发板；转发板完成业务频率搬移，独立接收端解调还原业务内容。遥控板另以DAC实现有限长度遥测下行。
[3] 原报告记录了1:8反序列化、跨时钟域握手、采集完整性判定及载波恢复优化，并给出四组指令控制、独立遥测下行和业务转发的测试结果。本稿按比赛模板重组技术与验证材料；实际烧写版本、ADDA完整型号及各项测试对应版本正在核对，相关结果保留原记录值。
[4] 关键词：卫星测控；变频转发；Zynq；高速采集；软硬件协同
[5] 第一部分 作品概述
[6] 1.1 功能与特性
[7] 系统实现测控指令接收、板端解调与参数解析、网络控制下发、业务变频转发及独立遥测下行。测控与业务采用分时方式运行，控制过程包含应答与参数读回；接收端独立完成业务内容还原。
[8] 1.2 应用领域
[9] 6G 将非地面网络（NTN）纳入体系架构，卫星由“补充覆盖”转为“内生组成”。星上载荷按处理深度分为再生式与弯管式两类：再生式解调后再调制，可与地面体制解耦；弯管式只做频率搬移，具有低时延、与调制体制无关、实现简单的优点，仍是多数中继卫星的主流形态。传统弯管式载荷存在三个局限：其一，转发频段在发射前固化，在轨变更需重新上注固件，响应慢、风险高；其二，转发参数对地面不可观测，地面无法确知星上本振的真实取值；其三，测控与业务由不同分系统承担，缺少“指令—生效”的闭环证据链。针对上述问题，本作品在 AMD Zynq-7000 系列 SoC 平台上实现“测控指令 → 参数解析 → 在线改频 → 业务中继 → 状态回读”的闭环，以实板测量与自检式仿真量化其能力与边界。与既有实现相比，差异在于：转发参数可在运行中变更且无需重新上注；每次改频都有 ACK 与独立读回作为证据；测控上行与遥测下行在同一平台上形成双向闭环。
[10] 1.3 主要技术特点
[11] 采用Zynq软硬件协同架构：PL负责高速接口、实时采集、缓冲及内建自检，PS负责解调算法与协议决策。采集通路采用1:8反序列化、异步FIFO及快照缓冲；通过轮次、完整性与源状态检查管理采集结果。射频业务通路与测控指令处理分离。

[19] 第二部分 系统组成及功能说明
[20] 2.1 系统整体介绍
[21] 平台选择上，系统四块板卡全部采用 AMD Zynq-7000 系列全可编程 SoC（XC7Z020 与XC7Z010），其“ARM Cortex-A9 双核处理系统 + 7 系列可编程逻辑”的异构结构恰好对应本作品的分工：可编程逻辑承担高速接口、实时搬运与内建自检，处理系统承担解调算法、协议与控制决策。同系列器件使 RTL、约束与仿真平台可跨板复用，工具链统一为 AMD Vivado（本作品使用 2018.3与 2026.1 两个版本），板间差异仅体现在引脚约束与器件规模上。四块板卡按处理负载分两级规模：遥控板需要承载 125 MSPS 采集、131072 点缓冲与解调协同，采用规模较大的 Zynq-7020；发送端、转发板与接收端主要承担射频收发与数据搬运，采用 Zynq-7010 即可满足。发送端与接收端运行厂商 Linux 固件，可直接通过 libiio 配置射频参数；转发板在ARM 侧运行嵌入式 Linux 应用，负责 I/Q 修正、SPI 诊断、安全静音与 UDP 遥控；遥控板的处理系统则为裸机 C，以保证采集—解调的确定性时延。系统由四类节点构成（见本节配图）：发送端（业务/指令信号源）、遥控板 Z7ADDALite、转发板LDSDR、独立接收端，计算机承担界面与记录。发送端在测控窗口发送 100.5 MHz 的指令信号，经 SMA 送入遥控板 ADC1/J5；遥控板完成采集与解调后，经以太网以 UDP 报文将转发频率下发至转发板并等待 ACK；业务窗口中发送端改为输出 900.5 MHz 业务信号，转发板将其搬移至 1000.5MHz 后由独立接收端解调还原；遥控板另通过 AD9122 DAC 在 90.5 MHz 上发送有限长度状态包，构成遥测下行。

[38] 2.2.3 接口与可编程逻辑模块
[39] 软硬件设计思路
[40] PL 的职责被有意限定为三件必须由硬件完成、且不能有软件延迟的事：接口对齐、实时搬运、内建自检；解调、协议与决策全部交由 PS。这一分工的直接原因是：解调算法会随体制与参数迭代，改 PS 代码只需重新编译，而改 PL 需要重新综合与实现。数据通路的实质是一个逐级降维的过程：125 MSPS 的源同步电气问题，经七级处理后变成 PS可读的一块 4.194 ms 数字内存。每一级只解决一个物理问题——接口相位差由 IDELAY 对齐解决，织体频率过高由 ISERDES 1:8 与 BUFR ÷4 解决，单流化由固定选点解决，跨时钟域由 XPM 异步FIFO 解决，完整性由状态机与三重判据解决，最终由 AXI4-Lite 交给 PS。与“做什么”同等重要的是“不做什么”：不在此 PL 内做解调（PS 承担）；不追求连续流接收，而只做 4.194 ms 的确定性快照（PS 解调约需 277 ms，连续流并无实际收益）；不接触业务信号（业务只经转发板的模拟/射频通路）。据此形成五条设计原则：时钟域只下移不上升；跨域只传稳定载荷与单比特控制；数据进内存前先过契约；硬件层面拒绝危险写入；不依赖外部信号源即可自检。
[41] ADC高速接口
[42] AD9643 以 125 MSPS 双通道输出 DDR LVDS 数据。设计先以 IBUFDS 接收差分信号，经IDELAYE2 逐比特固定延迟完成源同步对齐（REFCLK 由 200 MHz 提供，IDELAYCTRL 独立延迟组），再以 ISERDESE2 在 DDR / DATA_WIDTH = 8 / NETWORKING 模式下反序列化。时钟侧由BUFIO 驱动 ISERDES 的 CLK 与 CLKB，由 BUFR 四分频产生 31.25 MHz 的 CLKDIV。八级输出Q8…Q1 直接映射到向量位段，每个 31.25 MHz 拍产出 112 bit，即 8 个时刻 × 14 路，其中包含 4 个A 通道与 4 个 B 通道样点（见本节配图）。
[44] 图 3 遥控板 ADC 高速采集数据通路
[45] 采用 1:8 而非 1:2 或 1:4 的关键收益是时钟域下移：除接口本身外，所有处理逻辑工作在 31.25MHz 及以下，这是后续时序收敛的根本前提。代价是必须经异步 FIFO 跨时钟域，由 XPM 异步FIFO（65 bit × 1024，CDC 三级同步，FWFT 读模式）承担，代价可控。
[46] 采集引擎与状态判据
[47] 采集引擎由采集源与采集控制两部分构成。采集源工作在 31.25 MHz 域，按命令给出的位置从112 bit 向量中选出单一样点，将 14 bit 符号扩展为 16 bit，再把相邻两个样点配成一组写入 FIFO；每个条目自带三样元数据：轮次标记（epoch，32 bit）、是否为最后一个字（last，1 bit）、以及两路样点本身，合计 65 bit。采集控制工作在 25 MHz 管理域，实现 IDLE / ARMING / CAPTURING / DRAINING / DONE /FAILED / CONFIGURING / RELEASING 八状态机。其核心是写入内存前的三重判据：
[48] • 轮次判据：FIFO 条目携带的 epoch 必须与本次快照的 epoch 一致，杜绝上一轮残留数据混入；
[49] • 完整性判据：条目的 last 标记必须与累计写入字数恰好匹配，杜绝截断或多写；
[50] • 源契约判据：ADC 配置已验证、PN9 训练有效、采集源就绪、时钟心跳正常、且不处于配置忙态。三项同时成立才允许写入采集 RAM。这一设计把“数据是否可信”的判断提前到写入之前，而不是事后校验——错帧、错位、截断的数据从一开始就进不了内存。寄存器写入同样受状态门控：仅当状态机处于 IDLE 时受理命令与选择字段的写入，越界或非法值直接置写错误标志（见本节配图）。
[52] 图 4 采集状态机与 RAM 写入时序（由 Vivado 仿真导出数据绘制）
[53] 本节图(a) 给出 27.1 ms 内的完整状态序列：4 次完整采集各持续 4.194 ms，与 131072 样点 / 31.25MSPS 的理论值 4.194304 ms 吻合；随后 4 组故障注入均在微秒级转入 FAILED 并正确释放。(b) 为单次采集的放大视图，(c) 为 CAPTURING 期间 RAM 写入细节：25 MHz 时钟下每拍写入 1～2 组65 bit 打包样点，地址连续递增、无跳变。
[54] 跨时钟域与存储
[55] 跨时钟域未采用多比特总线直接穿越，而是采用“稳定载荷 + 单比特控制”的 bundled-data 握手：发送侧在载荷被接受后保持其稳定，直到接收侧回送 ack；数据经两级同步、控制经三级同步，同步链显式标注 ASYNC_REG 并禁止被抽取优化。这样多比特数据无需逐位同步，只需保证载荷在窗口内稳定，在约束上即可用最大延迟而非伪路径来约束数据束。采集缓冲为 64 K × 32 bit（256 KiB），在 31.25 MSPS 下对应 4.194 ms、131072 个 16 bit 样点。存储模块有两条刻意的安全设计：其一，PS 侧写通道恒返回错误，从硬件上禁止 PS 覆写采集结果（仿真中设有专项检查）；其二，存储器在复位时不清零，避免无效数据被清零而掩盖问题。PS读地址必须落在规定的 256 KiB 窗口内且四字节对齐，否则返回读错误。
[56] 内建自测
[57] 为在不接入模拟信号的前提下验证整条数据通路，PL 内置 PN9 伪随机序列发生器与比对器：确定性码型经 ADC 接口注入，由比对器逐向量检查，输出训练有效、通道奇偶、失败标志与通过向量计数。训练失败会立即失效采集契约，使数据无法写入内存。实测取 98,304 个 A 通道样点，PN9 错误为 0。该机制的价值在于把“接口对齐是否正确”从依赖外部信号源的定性判断，变成可重复、可自动判定的定量检查。
[58] 遥测DAC发送
[59] 遥测下行由 AD9122 DAC 承担，在 90.5 MHz 上以 100 ksym/s 发送有限长度状态包，单次约33.6 ms。数字侧以直接数字合成方式产生载波（相位步进按 90.5 MHz / 250 MHz 计算），包体存放于片上块 RAM，由单所有者有限状态机驱动，支持单次触发与中止，并在出错时给出定位到具体原因的错误码位图。输出级采用 ODDR 同沿模式构成 word-mode 接口，I 数据在 DCI 上升沿送出、Q 置零，调制运算与输出寄存器分离以避免建立路径过长。

[63] 2.3.2 PS解调模块
[64] 遥控板的处理系统（ARM Cortex-A9 双核，裸机运行、不依赖操作系统）以 C 实现解调链（见本节配图）：对 131072 个样点先做平方律载波恢复，再下变频、匹配滤波、符号同步，随后 Viterbi译码（K = 7，码率 1/2）、解随机化与 CRC-16 校验，最后输出接收频段、转发频段与序号。板端一次完整解调约 277 ms。
[66] 图 5 遥控板 PS 侧解调流程与三项关键设计
[67] 三项设计值得说明。其一，载波恢复采用平方律而非 FFT 峰值搜索：BPSK 信号平方后会在两倍载频处形成谱线，配合抛物线插值可获得赫兹级估计；而直接取 FFT 最强谱线，在 BPSK 上易锁定到符号率附近的旁瓣，实测偏差可达 25 kHz（约符号率/4），足以使判决全错。其二，存在0/π 极性歧义，实现上同时尝试两种判决极性，以 CRC 通过作为判据。其三，当前按短数据块解调，不做连续流跟踪，因此本文不宣称连续无间断接收。
[68] 2.3.3 板间协议与上位机模块

[71] 2.4.1 时序收敛优化
[72] 厂商例程按 7z020-clg484-2 建立，实测违例集中在 ADC 相关的高速域，最差负裕量达 −4.888ns（SIN 场景）与 −4.174 ns（LOOP 场景），且实物为同型号 −1 速度等级（待核对），实际余量更差。优化分三步：一是校正器件与速度等级；二是将 ADC 反序列化从 1:2 改为 1:8，使处理织体从 250 MHz域迁移到 31.25 MHz 域；三是修正约束，去除掩盖性 multicycle 设置并补充 DAC 生成时钟。优化后 WNS = +0.483 ns、WHS = +0.022 ns、WPWS = +0.264 ns，TNS / THS / TPWS 均为 0，DRC = 0（见本节配图）。

[75] 2.4.2 时序约束与签核流程
[76] 时序违约通常不是实现阶段才出现的问题，而是设计前期决策的后果。本设计按“预算先行—结构降域—约束严谨—门禁判定”四步组织，使时序收敛成为可控过程而非反复试错。第一步，预算先行。在编写 RTL 之前先确定“处理织体最高只运行在 31.25 MHz”，据此反推接口必须做 1:8 反序列化。若先按 1:2 实现再优化，织体将被锁在 125 MHz 以上，后续任何优化都只能局部缓解。第二步，结构降域。除 ADC 接口本身外，所有逻辑集中在 25 MHz 管理域与 31.25 MHz 采集域；跨域只走异步 FIFO 与 bundled-data 握手，不做组合逻辑跨域；内嵌逻辑分析仪仅接在采集域，使原始高速信号不经管理域。第三步，约束严谨。伪路径只施加于同步链首级寄存器的 D 引脚，并用正则精确限定数量；跨时钟域数据束不以伪路径豁免，而以最大延迟 20 ns 约束（小于最快目的周期 32 ns），保证建立时间；低速 SPI 使用独立预算时钟约束输出延时，协议沿另行检查。三条纪律的共同目的是：约束只豁免真正的异步首级，绝不掩盖真实的时序路径。第四步，门禁判定。签核脚本对七项指标同时判定——WNS ≥ 0、WHS ≥ 0、WPWS ≥ 0、TNS= 0、THS = 0、TPWS = 0、DRC 错误数为 0——任一不满足即整体判失败，从流程上杜绝“放宽约束以求通过”。最终结果：WNS +0.483 ns、WHS +0.022 ns、WPWS +0.264 ns，三项总量指标均为0，DRC 错误 0，无锁存器。

[143] 第四部分 总结
[144] 4.1 可扩展之处
[145] 后续可补充抽取前抗混叠滤波，并探索双缓冲和解调流水化以支持连续接收；通过独立指令源验证测控与业务并发；完成绝对功率标定、误码率测量及启动恢复验证。
[146] 4.2 心得体会
[147] 本作品在 AMD Zynq-7000 系列 SoC 平台上实现了卫星测控与变频转发的端到端闭环：转发参数可在运行中在线变更且无需重新上注，每次变更均有 ACK 与独立读回作为证据，并具备遥测下行回报能力。在可编程逻辑层面，1:8 反序列化把处理织体从 250 MHz 域降到 31.25 MHz 域，配合异步FIFO 与采集缓冲，形成“PL 实时搬运 + PS 协议决策”的异构分工；写入前的三重判据使不可信数据无法进入内存；三项时序优化使 WNS 从 −4.888 ns 收敛到 +0.483 ns；平方律载波恢复把载波误差压到赫兹量级。六个自检式测试平台合计 169 万余次检查全部通过，为设计正确性提供了独立证据。后续工作包括：增加数字抗混叠滤波以支持连续流接收；引入独立指令源与第三根同轴，验证测控与业务并发；完成绝对功率标定与误码率测量；实现启动介质持久化与异常恢复。
