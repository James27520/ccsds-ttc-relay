[341] 四、关键技术问题与解决（核心章节）
[342] 4.1 问题一：AD9361 打不开（引脚整套错）
[343] 项目
[344] 内容
[345] 现象
[346] 板上 enable/spi 一直不对，AD9361 无法初始化，ad9361_config_init_done 始终为 0
[347] 根因
[348] 本板 AD9361 走的是 LVDS 接口，不是 CMOS；引脚也不对。最初按别的板子资料接的，整套引脚都是错的
[349] 解决
[350] 按本板原理图确认：enable=T15, spi_csn=R17, spi_clk=V18, spi_mosi=P16, spi_miso=V17；数据用 LVDS 差分对；BD 参数 CMOS_OR_LVDS_N=0、MODE_1R1T=0、ADC_INIT_DELAY=30
[351] 验证
[352] 板上 ad9361_config_init_done = 1、chip_rst_n = 1、txnrx = 1
[353] 教训：换板子资料时，引脚复用与接口电平是最容易踩的坑，必须逐个对照原理图。
[354] 4.2 问题二：SRRC 滤波器的综合陷阱（最难定位）
[355] 现象：
[356] 板上实测（12 探针 ILA）：
[357]   datalink + mapper 输出   = 期望 CADU      ->  正确（300/300 逐位验证）
[358]   oversampler 零插值输出   = {0, ±31}       ->  正确
[359]   SRRC 输出                = {0, -128}      ->  ★ 只剩两个值，完全没有成形波形
[360] 而同一份 RTL 在 ModelSim 里输出 -46..+44 的正常波形。
[361] 定位过程（三步）：
[362] ① 先怀疑幅度不够：给滤波器前加 ÷4 余量（算术右移 2 位）
[363]    结果：输入确实变成 ±31，但输出仍是 {0, -128}  ->  不是幅度问题
[365] ② 再怀疑移位量：把输出右移从 7 改成 9（增益降 4 倍）
[366]    结果：板上输出完全没变  ->  ★ 综合结果根本不是那条算式
[368] ③ 决定性实验：把 SRRC 实体改成直通  sam_o <= sam_i
[369]    结果：板上 frame_match = 1、rx_crc_ok = 1、rx_err_cnt = 0，整链全通！
[370]    ->  唯一坏掉的就是这个滤波器，一句实验锁定问题
[371] 根因：
[372] euryspace 第三方库的 SRRC 用 variable + for 循环做 61 级乘加累加。这种写法在 ModelSim 仿真中正确，但 Vivado 综合后行为完全不同 —— 输出恒在 ±128 满量程乱跳。第一版重写（同样是 variable + for）复现了完全相同的现象，说明这是这类 VHDL 描述的通病，不是偶然。
[373] 解决：改成『综合不可能有歧义』的写法 ——
[374] 原来的写法
[375] 修改后
[376] variable 在进程内累加
[377] 全程只用 signal
[378] 隐式截断的 resize
[379] 每级加法显式 resize（18/19/20/21/22 位）
[380] 61 个乘法器
[381] 对称结构（h(k)=h(N-1-k)），31 个乘法器
[382] 位宽靠推断
[383] 乘法两侧精确匹配（9bit x 8bit = 17bit，无需 resize）
[384] 输出直接切片
[385] 一次算术右移 + 显式饱和

[400] 4.3 问题三：clk_sam 是组合门控时钟
[401] 项目
[402] 内容
[403] 根因
[404] ccsds_rxtx_clock_divider 在 DIVIDER=1 时写成 clk_o <= clk_i and (not rst_i)，而 rst_i 接的是 not ena_i —— 等于用时钟去与一个来自其他逻辑锥的使能信号，综合后会产生毛刺
[405] 影响
[406] clk_sam 域上的大块时序逻辑（SRRC）行为不可预测
[407] 解决
[408] DIVIDER=1 时直接透传 clk_o <= clk_i，复位交给各子模块自己的同步复位
[409] 说明
[410] Xilinx 明确不推荐用 fabric 组合逻辑分频做时钟；原厂 ADI 设计用的是 MMCM + BUFG
[411] 4.4 问题四：接收机抽取相位在板上对不齐
[412] 项目
[413] 内容
[414] 现象
[415] rx_asm_hit 始终为 0、rx_state_dbg 始终停在 ST_ASM，接收机在位流里找不到同步字
[416] 根因
[417] 收发两侧的分频器初始相位在硬件上与仿真不一致 —— 仿真里 PHASE=9 能过，板上过不了
[418] 解决
[419] 改成 10 个抽取相位各跑一路 ASM 搜索，哪一路先凑满 32 位同步字就锁定它，后续所有抽取都按锁定相位走。完全不依赖手工标定的相位常数
[420] 代价
[421] 只多了 10 个 32 位移位寄存器 + 比较；匹配滤波器（最贵的一块）仍然共用
[422] 验证
[423] 仿真 10 个相位全部 PASS（改动前只有 9 个）
[424] 4.5 问题五：datalink 输出字没有有效标志
[425] 项目
[426] 内容
[427] 根因
[428] BITSVALIDP 里的 dat_val_o 被做成了电平（置起后再也不清零），下游无法判断字边界
[429] 解决
[430] 改成每输出一个字翻转一次的 wire_word_toggle，并且放在 if/else 之外；dat_nxt_o 清 0

[456] 六、一个必须知道的物理现象：不接电缆也能收
[457] AD9361 是收发一体芯片，TX 和 RX 在同一颗硅片 + 同一块 PCB 上，两边本振又都是 2400 MHz，因此 TX 输出会通过衬底/封装/PCB 耦合进 RX 输入端。结果是【不接任何电缆也能解出帧】。
[458] 这一点用三个实验证明（都是真实射频通路，不是数字串扰）：
[459] A) TX 静默                    峰值     +0 Hz     峰/底 17.4 dB
[460] B) TX 出 1 MHz 单音（TXLO 2400） 峰值 +1001250 Hz  峰/底 42.6 dB
[461] C) TX 本振挪到 2401 MHz          峰值 +1998750 Hz  峰/底 22.3 dB
[463] B -> C 峰位差 = +997500 Hz = +1 MHz
[464] 只动 TX 本振，接收峰就跟着挪  ->  信号真的走了
[465]   TX 基带 -> TX 本振上变频 -> 射频 -> RX 本振下变频 -> RX 基带
[466] 数字串扰不会受本振影响，所以这一条排除了数字串扰的可能。
[467] 因此：
[468] · 工具会按接收电平 RMS 自动判定路径（>100 判为直连电缆，否则判为内部泄漏），并显示在界面上

[527] 九、硬件连接与操作要点
[528] 9.1 接 CMU200 看频谱
[529] 射频中心频率 = 板子本振 + 基带中频偏移
[530]   本振 2400 MHz + 中频 0.200 MHz  ->  2400.200 MHz
[531]   占用带宽 = 250 ksym/s x (1 + 0.35) = 338 kHz
[533] CMU200 设置：Center 2400.200 MHz / Span 1 MHz / RBW 10 kHz / Ref -40 dBm
[534] 接板子的 TX1A
[535] 注意：CMU200 频率上限取决于选件（常见 2.2 或 2.7 GHz）。上不去就把板子本振改低。另外 CMU200 只能看频谱，它不认 CCSDS 调制，做不了误码率测量。
[536] 9.2 烧写自定义位流的操作纪律
[537] 必须先让板子停在 u-boot，再烧写：
[538]    tools\uboot_stop.ps1        （或断电重插，在串口出现 Pluto> 时按一下打断）
[540] 原因：Linux 一跑，ADI 驱动会去访问纯 PL 设计里不存在的 AXI 地址 -> 挂死 ->
[541]       Zynq 看门狗（cdns-wdt f8005000.watchdog，10 秒，nowayout）复位整板 ->
[542]       FSBL 重新加载原厂位流，我们的设计和 ILA 一起被冲掉。
[544] 现象提示：停在 u-boot 时三个灯常亮、看不到 Pluto 的 U 盘，这是正常的，不是故障。
[545] 恢复原厂：Pluto> 敲 boot，或断电重插。
[546] 9.3 安全提醒
[547] 接了 TX1A->RX1A 电缆时，TX 衰减必须 >= 20 dB。
[548] AD9361 接收端耐压约 +2.5 dBm，而 TX 在 0 dB 衰减时输出约 +7 dBm，直连可能损坏接收通道。当前默认 TX 衰减 40 dB（输出约 -33 dBm）是安全的。
