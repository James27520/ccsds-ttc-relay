[5] 一、重要：遥测发的是『固定格式的参数表』，不是自由文本
[6] 这一点很容易搞错，先说清楚：
[7] 遥测下行（星->地）：
[8]   · 发的是一组【事先定义好的工程参数】：每个参数在数据域里的字节偏移、
[9]     类型、量纲、比例因子都是任务书 / 接口文件里定死的
[10]   · 星上只负责把测量值填进对应位置，地面按同一张表解析
[11]   · 星上【不能】随便发一段文本 —— 地面根本不知道那串字节是什么意思
[13] 『想发什么就发什么』那是上行数据注入 / 遥控指令，属于另一条链路，
[14] 由地面站发给星上，不是遥测。
[16] 所以本工具界面是一张【只能改数值】的参数表（类似 IIO 的属性列表）：
[17] 偏移 / 类型 / 量纲都锁死，只让改数字，并做范围校验。
[18] 帧格式固定 40 字节：6 字节主头 + 32 字节数据域（16 个 16 位参数）+ 2 字节 FECF。
[19] 二、链路架构：CCSDS 帧里装的是什么
[20] 这一条最容易被搞错，先说清楚：
[21] 本系统的链路：
[22]   （信号源）--CCSDS 帧--> 遥控板接收 --> 遥控板解析出【转发控制参数】
[23]                                       --> 通过以太网下发给转发板
[24]                                       --> 转发板按参数工作
[25]                                           （转发到哪个频段、多大带宽、多少增益…）
[27] 所以帧的数据域里装的是【转发板的控制参数】，不是自由文本。
[28] 每个参数在数据域里的字节偏移、类型、量纲、比例因子都是事先定死的；
[29] 发端只填数值，收端按同一张表解析。
[31] 为什么不能随便发文本：地面/转发板不知道那串字节是什么意思。
[32] 『想发什么就发什么』那是数据注入，不是常规遥控/遥测。

[373] 6.2 接 CMU200 看频谱
[374] 射频中心频率 = 板子本振 + 基带中频偏移：
[375] TX 本振      = 2400 MHz
[376] 基带中频偏移 = 200 kHz   （cadu_to_iq 的 if_hz）
[377] => 射频中心   = 2400.200 MHz
[378]    占用带宽   = 250 ksym/s x (1 + 0.35) = 338 kHz
[380] CMU200 设置：
[381]    Center Frequency : 2400.200 MHz
[382]    Span             : 1 MHz
[383]    Reference Level  : -30 dBm  （TX 衰减 40 dB 时输出约 -33 dBm）
[384]    接板子的 TX1A（SMA 线）
[385] 注意：CMU200 的频率上限取决于选件（常见 2.2 GHz 或 2.7 GHz）。如果上不到 2400 MHz，把板子本振改低：
[386] iio_attr -u ip:localhost -c ad9361-phy altvoltage1 frequency 1000000000
[387] => 射频中心 = 1000.200 MHz
[388] 注意：CMU200 只能看频谱，它不认 CCSDS 调制，做不了误码率测量。
[389] 6.3 一个必须知道的现象：TX 和 RX 不接线也能通
[390] 实测：TX1A 和 RX1A 之间没有任何连接，B 模式仍然能零误码解出参数。原因是 AD9361 同一颗芯片内部 / PCB 的 TX->RX 泄漏。已用实验证明这是真实射频通路：
[391] A) TX 静默（DDS scale=0）       峰值     +0 Hz     峰/底 17.4 dB
[392] B) TX 出 1 MHz 单音（TXLO 2400） 峰值 +1001250 Hz  峰/底 42.6 dB
[393] C) TX 本振挪到 2401 MHz          峰值 +1998750 Hz  峰/底 22.3 dB
[395] B -> C 峰位差 = +997500 Hz = +1 MHz
[396] 只动 TX 本振，接收峰就跟着挪 -> 信号真的走了
[397]   TX 基带 -> TX 本振上变频 -> 射频 -> RX 本振下变频 -> RX 基带
[398] 数字串扰不会受本振影响，所以这一条排除了数字串扰的可能。
[399] 对演示的意义：
[400] · 不接 SMA 线：靠芯片内部泄漏自环，演示照常能做（本次零误码实测通过）
[401] · 接 SMA 线 TX1A->RX1A：是真正『出 SMA 口再回来』，演示更有说服力
[402] · 接转发板 / CMU200 / 频谱仪：必须接线，信号必须走出 SMA 口
[403] 6.4 模式 C 怎么演示
[404] 1. 板子停在 u-boot：  tools\uboot_stop.ps1
[405]    （或断电重插，在串口出现 Pluto> 时按一下打断）
[406]    必须先停 u-boot：Linux 一跑，ADI 驱动会去访问纯 PL 设计里不存在的
[407]    AXI 地址 -> 挂死 -> Zynq 看门狗 10 秒复位整板 -> 位流和 ILA 一起被冲掉
[409] 2. 烧写 + 抓取：
[410]      vivado -mode batch -source ccsds_pl\program_and_base.tcl
[412] 3. 在 ILA 里看（12 个探针）：
[413]      frame_match   = 1        40 字节与期望帧全部相等
[414]      rx_crc_ok     = 1        CRC 通过
[415]      rx_err_cnt    ~ 0        零误码
[416]      rx_frame_idx  = 0x28=40  收到整整 40 字节
[417]      rx_frame_byte = 0x63     期望帧的最后一字节
[419] 4. 恢复原厂：Pluto> 敲 boot，或断电重插
[420] 注意：模式 C 目前是『板上自带固定帧的自环链路』，PC 不下发参数。要做到『电脑填参数给 FPGA』，需要再给 FPGA 加一条串口注入通路。
[422] 七、常见问题
[423] 问：双击 .bat 报『不是内部或外部命令』
[424] 答：.bat 带了 UTF-8 BOM 或用了 LF 换行。cmd.exe 只认【纯 ASCII + CRLF】，中文注释也会出问题。本工程的 .bat 已按此格式重写。
[425] 问：界面里为什么没有可以随便输入文本的地方
[426] 答：设计如此。遥测发的是固定格式的参数表，只允许改数值。想发任意内容是上行数据注入，不属于遥测。
[427] 问：某个参数的数值填了但一发就变了
[428] 答：做了范围校验：超出该参数允许范围的输入会被夹到边界值。表格里的『允许范围』列就是界限。
[429] 问：点了 B 模式弹出错误
[430] 答：排查顺序：ping 192.168.2.1；板子本振是否同频；tools\verify_leakage.py 看射频通路；tools\tx_path_probe.py 看 TX 是否出信号。
[431] 问：B 模式解不出帧 / 有误码
[432] 答：先确认 TX 衰减与 RX 增益（默认 40 dB / 30 dB 已实测可用）。数据域固定 32 字节，短帧会因 Viterbi 尾比特余量不足差 1 bit，所以不要改帧长。
[433] 问：板子三个灯常亮、看不到 Pluto 的 U 盘
[434] 答：说明板子停在 u-boot（不是故障）。这是烧写自定义位流 + 抓 ILA 必需的状态。恢复原厂：Pluto> 敲 boot，或断电重插。
[435] 问：怎么确认板子在不在
[436] 答：Get-PnpDevice -PresentOnly | Where InstanceId -match 'VID_0403'（JTAG 口）和 'VID_0456'（OTG 口 gadget）。必须带 -PresentOnly，否则会读到 Windows 缓存的历史设备而误判。
