## 1. 项目简介

本项目实现一套**星上测控 + 变频转发**载荷。系统由两块 Zynq-7010 + AD9363 板卡组成：

- **遥控/遥测板**：接收 CCSDS 遥测帧，解析出转发控制参数（接收频段 / 转发频段 / 带宽 / 增益…）
- **转发板**：按参数把业务信号从 **f1 变频搬到 f2** 转发出去

**核心工作是把 CCSDS 131.0-B 的完整协议链（组帧、随机化、卷积编码、BPSK 调制、成形滤波、匹配滤波、帧同步、译码、CRC）全部用 RTL 实现在 FPGA 里**，并在真实硬件上闭环验证通过。

> 项目的价值在于**变频通信**：信号进 f1、出 f2，内容不变、频段改变。这正是 6G 星上再生载荷的核心能力。

## 2. 为什么 6G 必须走向卫星

| 事实 | 数字 | 含义 |
|---|---|---|
| 地面网络覆盖的陆地面积 | ≈ 20% | 沙漠、高山、森林、极地基本无覆盖 |
| 地面网络覆盖的地球表面积 | ≈ 6% | 海洋占 71%，完全没有地面基站 |
| LEO 时延 | 10~40 ms | 可满足 6G 大部分业务 |
| 6G 峰值速率目标 | 1 Tbps | 需卫星回传与广域覆盖配合 |

**卫星通信是 6G 的必要组成部分，而不是可选项。**

### 为什么 4G/5G 不够用

不是"快慢"问题，而是 **5G 的空口设计前提在卫星场景下不成立**：

| 设计前提 | 4G/5G 的假设 | 卫星场景现实 | 后果 |
|---|---|---|---|
| 功率 | 基站接市电，OFDM 高 PAPR（8~10 dB）可接受 | 星上靠太阳能+电池，功率极度受限 | 功放须大幅回退，效率骤降 |
| 时延 | HARQ RTT ≈ 1 ms | GEO 240 ms / LEO 10~40 ms | 现有重传机制失效 |
| 多普勒 | 终端慢速，kHz 量级 | LEO 7.5 km/s，Ka 段可达数百 kHz | 同步与频偏补偿需重做 |
| 覆盖规划 | 小区几十米~几公里 | 一个波束覆盖数百公里 | 调度与移动性模型不同 |
| 星上处理 | 不需要 | **6G 要求星上再生** | 4G/5G 卫星基本是弯管转发 |

- **4G（LTE）**：完全无卫星集成，纯地面标准
- **5G**：3GPP Rel-17 引入 NTN，但本质是把卫星塞进已有 NR 框架，做了大量妥协
- **6G**：从设计之初把卫星当作一等公民，**星上再生（解调—处理—再调制）成为标配**

## 4. 为什么 FPGA 是本项目的核心

![Why FPGA](https://cdn.jsdelivr.net/gh/James27520/ccsds-ttc-relay@main/docs/images/fig5_fpga.png)

| 维度 | 软件实现（ARM / PC） | FPGA 实现 |
|---|---|---|
| 执行 | 串行，一个样点算完才算下一个 | 并行，61 个乘法器同时工作 |
| 实时性 | 30.72 MSPS 需数十 GOPS，差两个数量级 | 全速实时，收发并行 |
| 定时 | 中断 + 调度 + 缓存 → 微秒级抖动 | 时钟周期计数 → 抖动为整数周期 |
| 延迟 | 内存搬运 → 毫秒级且不确定 | PL 内部仅几十个时钟周期 |
| 自主性 | 必须外接 PC，脱机失效 | 单板自主运行 |

**运算量估算：** SRRC 成形滤波 61 抽头 × 30.72 MSPS ≈ **1.87 G 次乘加/秒**

> **AD9361 只负责数模转换与变频；决定"这是不是 CCSDS 载荷"的调制解调器，全部在 FPGA 里。**
> **没有 FPGA，这块板子只是通用 SDR；有了 FPGA，它才是测控载荷。**

## 5. 已实现的功能

### 5.1 CCSDS 发射链（8 级流水）

| 级 | 功能 | 关键实现 |
|---|---|---|
| 1 | 帧组装 | 6B 主头（SCID/VCID/帧计数）+ 32B 数据域 + 2B FECF |
| 2 | CRC-16 | CCITT-FALSE，poly `0x1021`，init `0xFFFF`，MSB first |
| 3 | 随机化 | LFSR `x^8+x^7+x^5+x^3+1`，种子 `0xFF` |
| 4 | 卷积编码 | 1/2 码率，K=7，G1=`1111001`，G2=`1011011`，第二路取反 |
| 5 | 加同步字 | `0x1ACFFC1D` → 672 bit CADU |
| 6 | BPSK 映射 | 比特到符号，极性经实验定标 |
| 7 | 上采样 | 每符号插 9 个零（1:10 零插值） |
| 8 | SRRC 成形 | 61 抽头对称结构，β=0.35，全显式位宽 + 输出饱和 |

### 5.2 CCSDS 接收链（7 级）

| 级 | 功能 | 关键实现 |
|---|---|---|
| 1 | 匹配滤波 | 与发射端同一 SRRC 实体（SRRC×SRRC = 升余弦，符号点无 ISI） |
| 2 | 硬判决 | 取匹配滤波输出符号位 |
| 3 | 帧同步 | **10 个抽取相位并行搜 ASM**，先命中者锁定 |
| 4 | 译码 | K=7 卷积码，输出非法对计数用于评估误码 |
| 5 | 解随机化 | 同一 LFSR |
| 6 | CRC 校验 | 与发射端同算法 |
| 7 | 帧组装与比对 | 还原 40 字节，逐字节比对，给出 `frame_match` |

## 9. 关键技术问题与解决

### 9.1 SRRC 滤波器的"综合陷阱"（最难定位）

**现象：** 同一份 RTL，ModelSim 仿真完全正常，综合后失效。

```
板上实测：SRRC 输出 = {0, -128}  ← 只剩两个值，没有成形波形
仿真结果：-46 ~ +44（正常 SRRC 波形）
```

**三步定位过程：**

1. **怀疑幅度余量** → 滤波器前插入 ÷4 → 输入确实变成 ±31，输出仍 `{0,-128}` → 排除
2. **怀疑移位量** → 输出右移 7 改 9 → **板上输出完全没变** → 说明综合结果不是那条算式
3. **决定性实验** → 把滤波器改成直通 `sam_o <= sam_i` → **`frame_match = 1`，整链全通**

**根因：** 第三方库用 `variable` + `for` 循环做 61 级乘加累加。仿真语义正确，但综合工具推断结果完全不同。

**解决：** 改为"综合不可能有歧义"的写法

| 原写法 | 修改后 |
|---|---|
| `variable` 进程内累加 | **全程只用 `signal`** |
| 隐式截断的 `resize` | **每级加法显式 resize**（18/19/20/21/22 位） |
| 61 个乘法器 | **利用对称性减为 31 个** |
| 位宽靠推断 | **乘法两侧精确匹配**（9bit × 8bit = 17bit） |
| 输出直接切片 | **一次算术右移 + 显式饱和** |

**效果：** 仿真 7/10 → **10/10 相位**；寄存器 8776 → 6120；`frame_match = 1`。

### 9.2 组合门控时钟

```vhdl
-- 第三方库的写法（DIVIDER=1 时）
clk_o <= clk_i and (not rst_i);   -- 用时钟与异步使能 → 综合后有毛刺
```

**解决：** 直接透传 `clk_o <= clk_i`，复位交给各子模块的同步复位。

### 9.3 10 相位并行帧同步

收发两侧分频器初始相位在硬件上与仿真不一致，固定相位不可靠。改为 **10 个相位各跑一路 32 位 ASM 搜索，先命中者锁定**。

> ⚠️ 这段搜索**不能**放在"按锁定相位抽取"的条件分支里，否则死锁。

### 9.4 射频路径辨识方法

**问题：** AD9361 是收发一体芯片，TX 与 RX 同硅片同本振，**不接电缆也能解出帧**。怎样证明电缆真的有效？

**方法：改变发射本振，观察接收频点是否跟随。**

```
A) TX 静默                峰值     +0 Hz     峰/底 17.4 dB
B) TX 1 MHz 单音（LO 2400）峰值 +1001250 Hz  峰/底 42.6 dB
C) TX LO 挪到 2401 MHz    峰值 +1998750 Hz  峰/底 22.3 dB

B → C 峰位差 = +997500 Hz ≈ +1 MHz
→ 只改本振接收峰就跟着挪 ⇒ 真实射频通路，不是数字串扰
```

再用电平量化：**接电缆 RMS 2446.6 / 不接 10.9（差 47 dB）**。

## 11. 协议说明

### 11.1 CCSDS 传输帧（固定 40 字节）

```
偏移  长度  内容
----  ----  --------------------------------------------------
 0     2    主头：SCID(10b) + VCID(3b) + 保留 + 帧类型 + 版本
 2     2    主头：帧计数(8b) + 状态字
 4     2    主头：数据域长度等
 6    32    数据域 = 16 个 16 位参数（小端）
38     2    FECF：CRC-16/CCITT-FALSE
----  ----  --------------------------------------------------
合计 40 字节 / 320 bit
```

### 11.2 转发控制参数（数据域 32 字节）

| 偏移 | 参数 | 说明 |
|---|---|---|
| 0 | 转发使能 | 0=停 1=开 |
| 2 | 工作模式 | 0=透明 1=再生 2=解调-再调制 |
| 4 | 目标频段 | 0=L 1=S 2=C 3=X … |
| 6/8 | **目标频率（低/高 16 位）** | 实际频率 = 高×65536 + 低（MHz） |
| 10 | 转发带宽 | kHz |
| 12/14 | 发射/接收增益 | 0.1 dB/LSB |
| 16~22 | 通道/本振/极化/衰减 | |
| 24~30 | 增益控制/加密/指令序号/保留 | |

### 11.3 转发板 CLI

```bash
$ help
#  status | auto <0|1> | mode <0..3> | ddc <v> | duc <v>
#  off <hz> | xoff <hz> | gain <v> | dc <0|1>
#  rxgain <db> | txatt <db> | lo <rxMHz> <txMHz> | rate <MSPS>
#  mode: 0=bypass 1=relay 2=mute 3=duc_only

$ lo 900 1000
OK rxlo=900 txlo=1000          ← 900 MHz 进，1000 MHz 出
```

**变频关系：** `输出频率 = 输入频率 + (TX_LO − RX_LO)`
