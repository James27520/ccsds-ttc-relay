# NTN 验证地面站

## 当前三窗口入口与验证范围

2026-11-01更新：三个窗口分开管理本地终端与远端转发板。终端1、终端2均可独立输入发送／接收中心频率并“应用本机频率”；测控窗口只修改LDSDR转发配置。取消此前同进程自动同步本地频率的行为，测控结束恢复终端1原本的业务计划。此版完成离线界面和后台回归，未执行新的实板测试。见[本地调频界面说明](../../docs/local-frequency-ui.md)。

当前第二版入口已接入统一终端后台：每块本地终端板卡只有一个工作线程和一个串口owner，终端1通信与测控页面订阅同一个后台。默认启动仍是离线界面审阅，不连接设备、不发射。**10月31日晚已修正本机终端角色标签，通过实际GUI双向文本、真实测控及测控期间两条新文本按序自动发送和对端实收。USB长期稳定性、SD启动CRC及掉电自启动仍待解决，详见[最新验收范围](../../docs/unified-terminal-validation.md#gui收发恢复与角色核对)。**

实板操作请双击仓库根目录的 [start_station_v2.bat](../../start_station_v2.bat)。[review_ui_v2.bat](../../review_ui_v2.bat) 是离线布局预览，标题带“离线预览”，不能连接设备；对应命令为 `python -m sw.ground_station.ui_v2 --all --preview`。三个页面的职责如下：

| 页面 | 职责 |
| --- | --- |
| 终端1 · 双向通信 | 设置并应用本机收发中心，连接后自动接收，可发送文本，显示本机频率回读与双向记录 |
| 终端2 · 双向通信 | 独立设置并应用本机收发中心，独立解码板卡接收数据；不继承终端1计划 |
| 终端1 · 转发板测控 | 继承终端1连接作为测控载体，发送转发板改频、启停和查询指令，核对真实RF回报 |

通信页保留同时收发，没有发送/接收模式切换和手动开始接收。频率编辑区只控制本机：输入与回读分开显示，修改后须应用才能发送；本机改频停止旧TX、恢复RX，未发队列保留待手动重试。发送编辑区和实际接收区一直保留；“已发送”仅表示本地发射已启动且保护状态核验通过，“实收”来自本端接收数据的有效帧。业务协议尚无对端确认消息，因此发送记录不显示“对方已收到”。两个窗口不互填文本，不把发送正文当作接收结果。

离线审阅可编辑文本、在测控页编辑频率请求、展开设备参数、模拟回报和复核历史事务；连接与收发按钮禁用。编辑请求会清除当前模拟或历史回报，模拟记录明确标注“模拟”，超时表示结果未知，不写入实测证据。历史导入选择 `tc_roundtrip` 的 `result.json` 并保留同目录 `downlink` 报告，只复核保存的帧字节CRC与事务关联，不重新解调IQ，不表示本次执行成功。

设备列表显示角色与COM端口，过滤蓝牙和已登记的板端管理接口。本机历史角色位于用户目录 `CCSDSGroundStation/device_labels.json`，例如 `{"devices": [{"vid": 1027, "pid": 24592, "serial": "实际USB序号", "role": "sender"}]}`。角色可为 `sender`、`receiver`、`management`；缺少唯一身份时可用 `port` 限定历史接口。标签“上次识别”不能替代在线身份核验，未知或重复身份显示“未识别 USB 串口”。换电脑须重新登记，不能复制COM号充当设备认证。

## 当前在线操作

以下入口启动时只打开页面，不自动连接或发射：

| 入口 | 打开的窗口 |
| --- | --- |
| [start_sender_v2.bat](../../start_sender_v2.bat) | 终端1双向通信，可打开测控页 |
| [start_receiver_v2.bat](../../start_receiver_v2.bat) | 终端2双向通信 |
| [start_station_v2.bat](../../start_station_v2.bat) | 本机三个页面 |
| [start_control.bat](../../start_control.bat) | 测控页及终端1通信连接入口 |

命令行可使用 `--all --online-business --online-control`。单独运行 `--role control --online-control` 也会自动打开具备连接能力的终端1通信页，在该页连接板卡后测控页继承状态；无须先断开通信再连接测控。`--online-business` 启用通信页面；未带在线参数始终是离线审阅。

1. 保持固定六线接线，并按配套固件完成远端转发准备。正向为终端1 TX1A → LDSDR RX1/TX1 → 终端2 RX1A；反向为终端2 TX1A → LDSDR RX2/TX2 → 终端1 RX2A。测控上行为终端1 TX2A/JP3 → 遥控板ADC1/J5，下行为遥控板DAC1/J6 → 终端1 RX1A/JP2；遥控板与LDSDR以太网直连。见[六线表与历史验证](../../docs/six-line-validation.md#接线与运行方式)。本地连接成功不表示远端已经开启转发，业务页不代做远端准备。
2. 两个终端分别输入约定的本机发送／接收中心，选择自己的本地板卡并连接。连接核验身份、配置本地业务频率并启动板端常驻RX进程，无须点击“开始接收”。连接后改频须点击“应用本机频率”，等待回读完成；未应用的草稿不能用于发送。每个终端只打开自身串口，不打开遥控板或LDSDR管理串口。发送板USB序号不唯一时绑定本次USB、启动编号和IIO映射，不把COM标签当作永久身份；连接和运行中均核验会话。

   初次连接会等待Linux命令行，并处理配套Pluto固件的默认登录；不会将IIO查询发给登录提示。非默认登录会给出明确错误，不反复尝试口令。若出现U-Boot提示，应用不会自动启动、重刷或接管板卡。COM号变化时，本机历史标签可能失效，须重新核实当前端口；USB已枚举不代表Linux已启动。
3. 演示前先在测控页核对业务输入/输出中心频率；远端频率不符时先“设置频率”，随后选择“开启转发”，依次点击“生成指令”“发送指令”，等待当前真实回报显示mode1及有效剩余时间，并等业务RX恢复。连接成功、频率设置成功都不等于转发已开启。之后输入1–32个UTF-8字节并点击“发送文本”。后台装载、启动本次TX时保留原板端RX进程，发送文本不中断业务RX；发送回执不代表对端实收。每次TX最多30秒，不自动续期。“停止发送”只停止本端TX，保留RX。收到的正文、编号、CRC与记录均来自本端实际接收，不能用本地发送记录补齐。
4. 测控页生成请求后点击“发送指令”。因业务与100.5/90.5 MHz测控共用本振，终端1后台先停止业务TX并暂停业务RX，再执行有限测控事务。此时新提交的文本显示“排队中”；只有当前测控收到匹配成功回报、确认转发已开启且租期仍有效、业务RX恢复后，才顺序发送新队列。失败、取消、静音或租期未确认时保留“待重试”，选中记录后点击“重试选中”。**旧的已发送文本不会自动重发。**终端2保持自己的后台运行；页面切换无需移动同轴线。
5. 只关闭测控页会解除该页订阅，正在测控时先取消事务；闲置测控页关闭不改变业务TX/RX。关闭一个共享页面不会关闭仍被其他页面使用的后台，最后一个owner关闭后等待设备清理与工作线程结束。需要释放设备时在通信页显式断开。跨进程端口锁拒绝重复占用；USB失联、身份变化或接收异常走清理与显式断开流程，排查后重新连接，不静默接管正在发射的板卡或自动重连发射。

发送队列最多保留8条未完成任务，包含待重试记录。正常连续发送按提交顺序，每条在确认本地发射后至少驻留2秒，再装载下一条；期间板端接收继续运行。“停止发送”和断开会将未发任务保留为待重试，重新连接不会自动发出。待重试任务保留于当前后台会话，不等于退出应用后的持久发件箱。

### 频率请求、ACK与状态

测控页输入业务中心：输入 `1980.100–2009.900 MHz`、输出 `2170.100–2199.900 MHz`，步进 `0.001 MHz`（1 kHz），两个频率独立选择。两端预留100 kHz带宽余量；低于设置步进的精度直接报错，不取整。新协议用kHz偏移编码，旧MHz协议仍兼容。业务中心减0.5 MHz得到转发板本振；终端发送中心为TX LO+0.5 MHz，终端RX LO为目标业务中心+0.25 MHz。申请值、真实ACK与本地回读分别保留，1 kHz设置步进不代表绝对准确度。详见[频率接口与验收计划](../../docs/free-frequency-plan.md)。

操作顺序为“设置频率 → 生成指令 → 发送指令”，收到成功回报后再选择“开启转发 → 生成指令 → 发送指令”。改频后转发保持静音；开启使用固定双路RX增益30 dB、TX衰减50 dB和5分钟租期。停止、查询无需填写频率，频率输入框会禁用；它们不改频，查询不续期。两个终端都应在各自通信页单独应用约定的本机收发频率；无论同机还是双电脑运行，测控回报都不自动更改它们。

远端成功回报不再修改任一终端的本地计划。两端操作员应约定相同业务方案，在各自通信页设置发送中心为转发输入、接收中心为转发输出，再由测控页配置和开启转发板。单机与双电脑都使用这一显式配置流程。**跨端自动频率协商尚未实现；同机页面也不再通过内存联动自动改频。** 测控期间排队的新文本只有在回报确认转发开启、租期有效且频率与本机原业务计划一致时才自动发送；不符则保留待重试。

“改频成功”只表示当前射频回报频率核对通过，不表示转发已开启或业务已经到达。开启、停止、查询须配套[有限租期固件和ATM2协议](../../docs/remote-relay-control.md)：开启核对现有频率，固定双路增益30 dB、衰减50 dB、最多5分钟；停止恢复静音和双路0/89 dB；查询不改频、不续租。模式、电平和剩余时间来自实际ACK快照，剩余时间保守递减，过期后待重新查询，不显示为持续监控。

“取消本次”只取消本地测控并恢复可恢复的业务RX，不能撤销已到远端的指令；远端停发须另发“停止转发”。超时或取消表示本次执行结果未知，接收恢复不等于事务成功。2026-11-01常驻固件在链路就绪后自动监听遥控，不再因600秒或16笔期限停止。须加载带 `--service-standby` 的配套应用；旧 `service on`仍保留有限台架行为。GUI仍不连接远端管理口；板端启动、掉电恢复和UDP序号维护须先完成，见[常驻监听与接收恢复](../../docs/standby-recovery-validation.md)。

发送文本、发送测控指令前及后台轮询时，终端核对当前USB、Linux启动编号、接收进程身份和DMA。若仅本会话拥有的接收进程退出或DMA停止，会先结束本地TX、清理原RX并重建接收，不自动重发旧文本或重开远端转发。60秒内再次退出则停止恢复并报错，避免循环重启。USB掉线、身份变化、进程被替换、削顶及采样异常仍需明确排查，不当作“休眠”掩盖。恢复接收不改变转发板5分钟输出租期。

指令序号在进程内不复用，并在 `CCSDSGroundStation/tc_sequences.json` 跨进程预留600秒，持久保存轮转位置；损坏注册表拒绝发送，不自动清空。它不等于远端永久防重放，也不能还原其他电脑发送历史。首次连接等待旧自动回报窗口结束。原始IQ、报告、日志保存在 `CCSDSGroundStation/sessions/` 下对应会话目录。

### 当前接收实现与待验项

业务RX由板端常驻原生进程完成连续采样、流式解调和CRC检查，主机轮询帧及诊断状态，而不是靠反复下载短IQ快照实现接收。原生解码器已通过生成IQ及历史实采IQ的host测试，相关源码与测试见 [stream_rx](../../board/terminal/stream_rx/README.md)。ARM版本已完成2.5 MSPS采样速度核对及双向业务、测控恢复实测；早期脚本调用生产后台与晚间实际GUI验收分别记录。USB传输稳定性仍未通过，原始IQ没有硬件样点序号，零丢样未建立。不能把板端RX进程常驻本身等同于零漏帧或长期稳定性。

## 历史实板证据：与当前统一入口分开解释

以下链接记录各自版本、接线、频点和操作流程，保留原始成功与失败范围。历史文档中的手动切换、独立应用频率、先断开再测控和短IQ快照是当时实现，不是当前三窗口操作步骤。

- [独立双向并行台架](../../docs/duplex-business-validation.md)：1999.5→2189.5 MHz两方向实收，以及RX保持运行时开启TX已验证；原解调器逐窗漏检和USB失联仍有未完项。这是硬件能力证据，不是新统一GUI验收。
- [固定六线与逐方向GUI](../../docs/six-line-validation.md)：包含多个高频工作点和固定六线闭环；追加GUI在1990.5→2180.5 MHz先反向、再正向回复，两端保留已发/实收记录，120份IQ独立重解34个正确帧。这是逐方向操作，不能改称双向同时收发；切频瞬态、USB异常、持久化和双电脑迁移仍按原记录待验。
- [高频测控及后续业务](../../docs/sband-station-validation.md)：两笔GUI高频指令返回8/7个CRC正确帧，另行SPI核对一致；后续文本及199份IQ盲重解通过，第200次高速回传超时中止并独立确认停发/DMA空闲。该历史快照链不代表当前常驻接收实现稳定通过。
- [有限租期遥控验证](../../docs/remote-relay-validation.md)与[分时业务摘要](../../docs/validation/2026-10-29-remote-business.json)：软件、UDP、ADC_NORMAL/DAC射频启停查询及随后分时业务已有证据；ACK与独立SPI分别记录，不能将旧版分时通过解释为当前并发通过。
- [旧版真实ACK与发送计划联动](../../docs/business-v2-validation.md#真实遥控回报与发送计划联动)：901.5→1000.5 MHz恢复7个CRC正确回报帧；当时先断开测控、再连接发送页应用计划。随后“遥控联动 901.5MHz”在独立接收端实收，21个正确帧代表1条消息，停发8窗无帧。这个历史低频点和旧UI流程不扩展当前在线预设，也不验证本轮自动恢复/同进程终端2同步。
- [历史反向回信](../../docs/reverse-link-validation.md#三窗口回信操作)：901.5→1000.5 MHz两条GUI新文本共36个CRC正确帧。历史反向操作需要切换方向，当前通信页已统一双向。

## 第一版业务台架工具（历史）

浅色桌面界面分为两个独立进程：发送端控制业务发送板与 LDSDR 转发板，接收端只使用自己的接收板进行采集和解码。可以先在一台电脑同时打开两个窗口；迁移到另一台电脑时，只需在该电脑启动接收端并连接接收板的 DEBUG 串口。两个程序不共享发送文本、消息列表或解码结果，也不需要通过网络交换答案。

当前业务采用实验 BPSK 文本帧，符号率 100 ksym/s，外层 CRC16。它复用仓库的物理层实验实现，并增加 `G1:<session>:<sequence>:<text>` 应用信封；不据此宣称已经实现标准 NTN 空口或完整 CCSDS 业务协议。六线系统的范围与未完成功能见 [六线总体计划](../../docs/six-link-system-plan.md)。

## 环境与启动

需要 Python 3.10 或更高版本、Tkinter、NumPy 和 pyserial；运行桌面程序不需要 Vivado。Windows Python 安装应包含 Tcl/Tk。先在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r sw/ground_station/requirements.txt
```

在仓库根目录启动两个独立窗口：

```powershell
.\.venv\Scripts\python.exe -m sw.ground_station --role sender
.\.venv\Scripts\python.exe -m sw.ground_station --role receiver
```

也可分别双击根目录的 [start_sender.bat](../../start_sender.bat) 和 [start_receiver.bat](../../start_receiver.bat)。脚本会把工作目录切换到自身所在的仓库根目录，支持路径中含中文和空格；优先使用仓库 `.venv`，不存在时使用 PATH 中的 `python`。启动失败时保留错误提示。脚本不会安装依赖、自动连接设备或自动发送文本。

若使用其他虚拟环境，可先激活环境再直接运行模块命令。两台电脑分别安装依赖并保留完整仓库；接收电脑不需要启动发送进程。

| 转发板控制 | LDSDR DEBUG → 发送电脑另一 USB 串口 | 本地准备转发业务、启停及读回 |
| 接收板控制 | 独立接收板 DEBUG → 接收电脑 USB 串口 | 接收配置、I/Q 快照传输 |
| 测控状态监控 | ADDA / Z7ADDALite DEBUG → 发送电脑另一 USB 串口 | 可选的 TM1 只读状态回传；不占 RF 同轴 |
| RF测控下行 | Z7ADDALite DAC1/J6 → 原发送板 RX1A/JP2 | 第三根同轴；RF下行窗口协调有限发送和真实IQ采集 |

串口编号会随电脑和 USB 插口变化，应按本机设备列表及身份回读选择，不把历史 COM 编号写死。发送端必须选择两个不同的 DEBUG 串口；接收端只选择自己的接收板串口。启动窗口只枚举端口，连接动作也不会自动启动发射。

| 参数 | 默认值与当前界面限制 |
| --- | --- |
| 发送板 TX LO | 固定 `900 MHz` |
| 业务调制偏移 | `+500 kHz`，输入 RF 名义值 `900.5 MHz` |
| 发送衰减申请值 | 默认 `50 dB`，允许 `50–89 dB` |
| LDSDR 本地准备 | RX LO `900 MHz`，TX LO `1000 MHz` |
| 转发输出 RF | 当前默认名义值 `1000.5 MHz` |
| 接收板 RX LO | 固定 `1000.75 MHz` |
| 预期 RF 解码先验 | 默认 `1000.5 MHz`；可选 `1001.5 MHz` |
| 接收增益 | 默认 `30 dB`，允许 `0–30 dB` |
| 采样率 | `2.5 MSPS` |

`1001.5 MHz` 选项只是接收解码先验。当前发送 GUI 的转发准备仍固定为 LDSDR TX LO `1000 MHz`，选择该先验不会自动把转发输出改为 `1001.5 MHz`。

左侧“设置值”表示申请值，右侧“设备回读”表示已经返回的实际值；“未提供回读”或“尚未回读”不表示设置成功。预期 RF 是解码先验，不是设备 LO 回读。配置阶段保持静音，实际发射时的衰减以发送后回执为准。

## 一次正向业务演示

1. 按上表连接两根业务同轴及三块板的 DEBUG。发送端选择发送板与 LDSDR，接收端选择独立接收板，分别点击“连接设备”，核对身份。
2. 两个窗口分别点击“应用设置 / 读取回执”，检查本端 LO、衰减/增益及发送端转发板回读。发送端的转发板控制是本地业务准备，不是经 ADDA ADC 下发的遥控。
3. 接收端点击“开始接收”。发送端输入 `1–32` 个 UTF-8 字节并点击“发送文本”。字节数会随输入更新；中文常占多个字节，超限时不能发送。
4. 等待真实采样与 DEBUG 传输完成，在接收端查看已解码文本、消息编号、重复帧标记、本次有效帧数、CRC 拒绝数、RMS、频谱及最后有效帧时间。重复发送同一消息不等同于新消息，界面保留重复标记。
5. 点击“停止发射”使发送板与转发板联动静音；接收端可单独停止采样。正常停止保留窗口内历史。关闭窗口会等待控制器停止、清理与断开回执，耗时操作未结束时会给出等待提示。

发送端发射的是当前文本的循环波形；消息编号含发送实例的 session 和顺序号，用于接收端独立辨识重复帧。正文为严格 UTF-8 的 `1–32` 字节。新消息分配新编号；异常内容、CRC 不通过或应用信封不合法的帧不会作为有效文本展示。

发送板启用约 `45 秒`的板端续租保护，运行中的控制器定期续租。主机失联后租约到期会触发保护停发；正常停止与关闭仍应通过程序完成。静音与 guard 是当前实现行为，具体硬件结果须以本轮回读及验收记录为准。

## 测控状态窗口

发送端点击“测控状态”，在弹窗中选择 **ADDA / Z7ADDALite 的 DEBUG 串口**，再点击“连接监控”。该串口与发送板、LDSDR 的业务控制串口分别选择。连接后每 `2 秒`只读查询 TM1 状态帧，校验 CRC 后更新；也可点击“立即查询”。查询不发送 ARM、nettest 或射频指令，现有 RF 接线保持不变。

四张卡片分别展示最近的“已解码”“UDP 发送尝试”“匹配 ACK”和“独立 SPI 读回”。前三个阶段各自保留事件、序号与来源，可能对应不同历史事件，不能把一次解码直接当成已经执行成功。来源标签区分 `ADC_NORMAL`、`ADC_TEST`、`SYNTHETIC`、`UART_NETTEST` 和未知来源；UART 网络测试与合成记录不作为真实 ADC 指令证据。`valid=0` 的阶段显示未知。

“读取转发板 SPI”按钮借用主窗口已经连接的 LDSDR 控制器查询，不另开转发串口。正常查询只读已有状态与诊断；异常沿业务控制器的安全停止流程处理。ACK 携带的频率值与独立 SPI 回读分开显示，TM1 的 `spi_valid=0` 不提供独立 SPI 证明。

窗口显示最近更新时间；超过 `6 秒`会标记过期，断开后保留的数值明确作为历史状态。独立 SPI 读回有自己的时间标识。关闭弹窗会等待监控串口清理，关闭主窗口也会等待业务和监控两个控制器完成清理后退出。

此“测控状态”窗口实现的是 **USB DEBUG 管理状态回传**。后续匹配新PL的DAC/SMA下行已单独实收通过，旧`r4c`仍不包含DAC发送功能。详细字段与USB路径边界见[测控状态说明](../../docs/telemetry-status.md)；新下行结果见[实际接收验证](../../docs/telemetry-rf-validation.md)。

## RF测控下行窗口

发送端或接收端点击“RF测控下行”，打开浅色单次采集/文件解码窗口。打开时只枚举串口，不自动连接或发送；可在主窗口未连接设备时使用。

在线操作：

1. 先断开占用对应端口的业务连接或USB TM1监控。选择遥控板DEBUG及已接到DAC1/J6的下行接收SDR DEBUG；不能按历史COM号猜测板卡角色。
2. 点击“只读核验”，检查两个端口与固件信息。点击“绑定连接”后会重新检查身份和空闲状态，配置90MHz接收、20dB增益，保持SDR发射关闭；不会自动启动DAC。
3. 点击“发送并接收一次”，程序先准备接收窗口，再请求DAC发送一次33.6ms状态包。约17秒后显示真实IQ独立解码结果，正常情况下四个重复帧对应一份快照。每次需要重新点击，不自动续发。
4. “仅采样”用于停发对照，不请求DAC发送。“停止”、断开或关闭会取消排队任务，等待当前串口传输恢复并释放端口；停止后需重新核验。不要在清理期间另开同一串口。

在线工作点固定为DAC名义90.5MHz、接收LO90MHz、2.5MSPS、100ksym/s、带宽3MHz、增益20dB；下方参数栏只影响文件解码。每份IQ覆盖104.8576ms，完整流程约17秒，不能称为连续实时接收。原始IQ、解码JSON、采集元数据和事件日志自动保存到用户主目录的`CCSDSGroundStation/sessions/<时间>_rf_tm_<编号>/`。

绑定仅在当前进程和启动会话有效：检查USB、Linux boot ID、模型/IIO，以及遥控板uptime连续性。它不是永久设备认证；主业务程序对缺少稳定身份的设备仍会拒绝。此接收适配器不授权SDR发射，也不修改Flash/SD或设备身份。当前所有相关串口由一个worker串行使用，与主业务或USB监控互斥。

离线查看：

1. 点击“选择IQ文件并解码”，选择接收设备实际采集的int16小端交错I/Q文件（12位符号扩展）。当前实测参数为采样率2500000Hz、符号率100000、预期偏移+500000Hz、搜索范围±20000Hz。
2. 长记录由后台滑窗解调，重叠窗口对同一个物理帧的检测合并，四份实际重复发送帧仍保留。表格展示快照序号、板端uptime、采样位置和载波偏移；下方分别显示解码、UDP发送与ACK记录。
3. “导入已有解码JSON”读取ATM1/ATM2射频解码报告，并重新检查帧字节及CRC。可选择每2秒刷新同一JSON文件，但刷新文件不代表自动进行了新采集。

IQ模式显示实际文件SHA256；JSON中的路径/哈希明确作为报告声明。文件修改时间不代表RF接收时间，CRC仅检查内容完整性，不能证明文件来源或认证发送设备。窗口不会使用USB TM1、发送清单或报告中的预期状态填充结果。

前一阶段实测为3次发送、12个CRC正确帧、3份不同快照，详见[实收报告](../../docs/telemetry-rf-validation.md)。在线控制器和GUI随后各恢复一份快照，共8个CRC正确帧，静默对照和采集中关闭均通过，见[GUI采集验证](../../docs/telemetry-live-validation.md)。该阶段返回已有UART_NETTEST状态。

后续[真实测控闭环](../../docs/telecontrol-roundtrip-validation.md)通过两条新ADC_NORMAL指令及对应的八个下行帧，历史入口为`python -m sw.ground_station.tc_roundtrip`。最新[自主测控版本](../../docs/telecontrol-autonomous-validation.md)已将整笔事务接入第二版改频窗口。该测试将发送板TX1A改接遥控板ADC1/J5；恢复业务演示前需停发并按业务接线表恢复第一根线。

## 如何解释接收结果

接收端每次采集 `32768` 个复数样本，在 `2.5 MSPS` 下覆盖 `13.1072 ms` 的射频时间。当前上传、下载使用临时 `921600` 波特 raw 二进制传输，校验长度和 SHA；完成或取消后恢复 `115200` 波特控制台。旧 `115200` legacy 传输仍保留为显式兼容入口：`Console.upload(..., mode='legacy')` 和 `Console.download(..., mode='legacy')`；高速传输失败不会静默降级。

本轮完整 capture 周期实测为 `2.87–2.91 秒`，旧流程约 `24 秒`，见 [提速验证](../../docs/station-speed-telemetry-validation.md)。这仍是分段快照，两个快照之间存在采样空档；界面周期标签反映本次完整操作耗时。新文本从提交到独立接收端显示的端到端总时间另行记录，不能用 capture 周期代替。

频谱只在真实快照返回后更新，未采集时保持空白。载波估计使用板卡时钟作为参考，不等同于经校准仪器测得的绝对频率。界面不会用发送窗口的文本填充接收记录。

“本次有效帧”与“本次 CRC 拒绝”只描述该快照。有效帧出现、多个离散窗口通过或重复文本可解码，都不能推出连续无漏帧、零误码率、实时连续接收或长期稳定性。发送端“已发送”也不代表接收端已经成功收到。

## 日志与验证

底部可展开诊断日志。默认会话目录位于用户主目录：

```text
CCSDSGroundStation/sessions/<时间>_<角色>_<session>/
```

事件日志、接收快照及对应分析文件用于追溯本次操作；可通过 `--log-dir <新目录>` 指定独立会话目录。该目录须尚不存在，避免覆盖已有证据。发送与接收应各自使用不同目录。窗口最多保留 500 行消息；磁盘会话保留全部快照，结束演示后可按需归档或删除自己的旧会话。

不接硬件的测试命令，从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s sw/ground_station -t . -v
```

软件测试与实板结果分别记录，见 [双端桌面站验证](../../docs/ground-station-validation.md) 及 [提速与测控状态验证](../../docs/station-speed-telemetry-validation.md)。测试桩结果不能代替射频链路验证。
