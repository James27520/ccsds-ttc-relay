# 协议规范

两层协议，各管各的：

| 层 | 走什么介质 | 格式 | 谁实现 |
|---|---|---|---|
| **CCSDS 层** | 地面 ↔ RK3588（网络、空口、文件） | 二进制空间包 | `ccsds.py` |
| **载荷 CLI 层** | RK3588 ↔ LDSDR（USB 串口） | 行式 ASCII | 固件 `relay_cli.h` |

RK3588 是两层的翻译器。

# 一、CCSDS 空间包（简化版）

基于 **CCSDS 133.0-B-2**，用到什么实现什么。

## 1.1 包结构

```
┌──────────────────────────────────────────────────────────┐
│ 传输帧同步头  0x1ACFFC1D                    (4 字节，可选) │
├──────────────────────────────────────────────────────────┤
│ 空间包主头                                   (6 字节)     │
│   版本(3) 类型(1) 副头标志(1) APID(11)                    │
│   序列标志(2) 序列计数(14)                                │
│   包数据长度(16) = 数据域字节数 − 1                        │
├──────────────────────────────────────────────────────────┤
│ 数据域                                       (n 字节)     │
├──────────────────────────────────────────────────────────┤
│ CRC-16/CCITT                                 (2 字节可选) │
└──────────────────────────────────────────────────────────┘
```

**字段取值：**

| 字段 | 值 | 说明 |
|---|---|---|
| 版本 | `000` | CCSDS 1.0 |
| 类型 | `0` = 遥控 TC，`1` = 遥测 TM | |
| 副头标志 | `0` | 不用副头 |
| 序列标志 | `11` = 独立包 | 不做分段 |
| 包数据长度 | 数据域字节数 − 1 | 注意是 **n−1** |

> ⚠️ **空数据域无法表示**（长度字段定义就是 n−1 且 n≥1）。
> 所以"请求状态"这个无参数命令也带 1 字节数据域（`0x00` = 请求全部）。

## 1.2 CRC-16/CCITT

- 多项式 `0x1021`
- 初值 `0xFFFF`
- 输入/输出**不反转**，**不异或**
- 覆盖范围：**主头 + 数据域**（不含同步头），大端追加在包尾

```python
from ccsds import crc16_ccitt
crc16_ccitt(b"\x01\x02\xc0\x00\x00\x00\x01")   # -> 0xE176
```

单比特翻转一定能检出，实测：

```
单比特翻转被正确检出: CRC mismatch (got 0x1020, want 0x5580)
```

## 1.3 字节序

**全部大端（网络序）**。这是 CCSDS 的规定。

## 1.4 流式同步

接收端不需要知道包边界。`PacketDecoder` 会：

1. 在字节流里搜索同步头 `1ACFFC1D`
2. 读到主头，按长度字段算出整包大小
3. 校验 CRC
4. **CRC 错就滑动一个字节重新搜索**（而不是丢一大段）

所以数据流中间插入垃圾字节不会影响后续包的解码，实测：

```
流长度 144 字节，内含 3 处垃圾（都插在包边界上）
解出 7 个包（应为 7）
```

# 二、APID 分配表

| APID | 名称 | 方向 | 数据域长度 | 用途 |
|---|---|---|---|---|
| `0x100` | `RELAY_SET` | TC | 12 | 转发参数整体设置 |
| `0x101` | `RF_SET` | TC | 18 | 射频参数设置 |
| `0x102` | `RELAY_MODE` | TC | 1 | 只切工作模式 |
| `0x103` | `FREQ_OFFSET` | TC | 8 | 只设频偏（Hz） |
| `0x104` | `DIG_GAIN` | TC | 3 | 数字增益 + 隔直 |
| `0x110` | `REQ_STATUS` | TC | 1 | 请求状态 |
| `0x200` | `STATUS_TM` | TM | 27 | 状态遥测 |
| `0x201` | `SPECTRUM_TM` | TM | 10+n | 频谱监测遥测（GPU 输出） |
| `0x202` | `ACK_TM` | TM | 3+n | 命令应答 |

预留：
- `0x100–0x1FF` 遥控
- `0x200–0x2FF` 遥测
- `0x300+` 留作扩展

# 三、数据域编码

## 3.1 `RELAY_SET` (0x100)，12 字节

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `mode` | 0=旁路 1=转发 2=静音 3=仅上变频 |
| 1 | 4 | `duc_word` | DUC 相位增量（32 位） |
| 5 | 4 | `ddc_word` | DDC 相位增量（32 位） |
| 9 | 2 | `gain` | 数字增益 Q1.11（`0x800` = 1.0） |
| 11 | 1 | `dc_en` | 隔直 0/1 |

```
+--------+----------------+----------------+-------+-------+
| mode 1 |  duc_word 4    |  ddc_word 4    | gain 2| dc 1  |
+--------+----------------+----------------+-------+-------+
```

**频率字换算：**

```
duc_word = round(频偏Hz / fs × 2³²)        二补码 32 位
```

fs = 30.72 MHz 时：

| 频偏 | 频率字 |
|---|---|
| +100 kHz | `0x00D55555` |
| −100 kHz | `0xFF2AAAAB` |
| +480 kHz | `0x04000000` |
| −480 kHz | `0xFC000000` |

> ⚠️ 负值必须用二补码。早期固件里"负数 double 转无符号"是未定义行为，
> ARM GCC 上饱和成 0，导致所有负频偏静默失效。**已修复**，
> 实测 −100 kHz 读回正确。

## 3.2 `RF_SET` (0x101)，18 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 8 | `rx_lo_hz`（64 位无符号） |
| 8 | 8 | `tx_lo_hz`（64 位无符号） |
| 16 | 1 | `rx_gain_db`（0~76） |
| 17 | 1 | `tx_att_db`（0~89，**越大输出越小**） |

## 3.3 `RELAY_MODE` (0x102)，1 字节

`mode`，取值同 3.1。

**为什么单独设一个只改模式的 APID**：切静音是安全操作，
不应该被迫连带改频率字（万一带的参数是错的，静音反而变成乱动）。

## 3.4 `FREQ_OFFSET` (0x103)，8 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | `duc_hz`（**有符号** 32 位） |
| 4 | 4 | `ddc_hz`（**有符号** 32 位） |

用 Hz 而不是频率字，让地面端不必知道载荷的采样率。

## 3.5 `DIG_GAIN` (0x104)，3 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 2 | `gain`（Q1.11） |
| 2 | 1 | `dc_en` |

## 3.6 `REQ_STATUS` (0x110)，1 字节

`0x00` = 请求全部状态。

## 3.7 `STATUS_TM` (0x200)，27 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | `in_cnt` 收样点 |
| 4 | 4 | `out_cnt` 发样点 |
| 8 | 4 | `clip_cnt` 饱和计数 |
| 12 | 4 | `rc`（**有符号**，0=正常，−1=无 ADC 数据，−2=无 DAC 输出） |
| 16 | 1 | `mode` |
| 17 | 4 | `ddc` |
| 21 | 4 | `duc` |
| 25 | 2 | `gain` |

**丢样判据**：连续两次读数，`Δin_cnt` 必须**逐位等于** `Δout_cnt`。

## 3.8 `SPECTRUM_TM` (0x201)，10+n 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | `timestamp`（Unix 秒，32 位） |
| 4 | 4 | `fs_hz` 采样率 |
| 8 | 2 | `n_bins` 频点数 |
| 10 | n | `bins_db`，每点 **int8**，量化到 1 dB |

用 int8 是为了压缩。20 MHz 带宽做 1024 点 FFT 也只有 1 KB。

## 3.9 `ACK_TM` (0x202)，3+n 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 2 | 被应答的 APID |
| 2 | 1 | 结果码：0=成功，1=未知 APID，2=执行失败 |
| 3 | n | 文本说明（UTF-8，最多 60 字节） |

# 四、载荷 CLI 协议（RK3588 ↔ LDSDR）

行式 ASCII，`\r\n` 结尾，115200 8N1。

## 4.1 命令

| 命令 | 参数 | 说明 |
|---|---|---|
| `help` | | 命令列表 |
| `status` | | 返回一行 `STAT ...` |
| `auto` | `0\|1` | 周期上报开关（RK3588 用 `auto 0` 关掉自己轮询） |
| `mode` | `0..3` | 工作模式 |
| `ddc` | 数值 | DDC 频率字（支持 `0x` 十六进制） |
| `duc` | 数值 | DUC 频率字 |
| `off` | Hz | 按 Hz 设 DUC 频偏（用载荷当前 fs 换算） |
| `xoff` | Hz | 按 Hz 设 DDC 频偏 |
| `gain` | `0..0xFFF` | 数字增益 Q1.11 |
| `dc` | `0\|1` | 隔直 |
| `rxgain` | dB | AD9361 RX 增益 0~76 |
| `txatt` | dB | TX 衰减 0~89 |
| `lo` | `rxMHz txMHz` | 改收发本振 |
| `rate` | MSPS | 改采样率（**见下方警告**） |

## 4.2 回执

| 前缀 | 含义 |
|---|---|
| `OK ...` | 成功，后面回显生效值 |
| `ERR ...` | 失败（未知命令） |
| `STAT ...` | 状态行 |

## 4.3 状态行格式

```
STAT mode=1 ddc=00000000 duc=00000000 gain=800 dc=0 rxgain=0 txatt=30 \
     rxlo=900 txlo=1000 fs=30720000 in=3134275583 out=3134275578 clip=178051 rc=0
```

> ⚠️ **`ddc` / `duc` / `gain` 是十六进制**，其余是十进制。
> 解析时要注意（`relay_link.py` 的 `HEX_KEYS` 就是干这个的）。

## 4.4 `rate` 命令的警告

`DATA_CLK` 周期由采样率推导：

```
period_ns = 4000 / sample_rate_in_MSPS        (2R2T 模式)
```

只改软件而不重新综合匹配的约束，**可能损坏 AD9361 的 LVDS 接口**。
生产环境应把 `rate` 从遥控命令表里去掉。

# 五、典型时序

## 5.1 一次参数下发

```
RK3588                                      LDSDR 载荷
  │                                              │
  │  构造 SpacePacket(0x103, enc_freq_offset(100000, 0))
  │  pack(with_crc=True, sync=True)
  │                                              │
  │  ── 串口 "off 100000\r\n" ──────────────────► │
  │                                    写 RELAY_DUC_FREQ 寄存器
  │  ◄──────────── "OK duc=00D55555\r\n" ──────── │
  │                                              │
  │  ── 串口 "status\r\n" ──────────────────────► │
  │  ◄── "STAT mode=1 ddc=00000000 duc=00D55555..." │
  │                                              │
  │  校验读回值 → 生成 ACK_TM 空间包              │
```

**每一步都读回校验**，而不是发完就算成功。这是 `relay_link.py` 里
`set_duc_hz()` 之后还会 `status()` 一次的原因。

## 5.2 丢样监测

```
RK3588                                      LDSDR 载荷
  │  ── status ──►  in=1000000 out=999988      │
  │       ... 2 秒 ...                          │
  │  ── status ──►  in=62440000 out=62439988    │
  │                                             │
  │  Δin = 61440000   Δout = 61440000           │
  │  → 逐位相等 → 零丢样                        │
  │                                             │
  │  61440000 / 2.0 s = 30.72 MSPS  ✓           │
```

`in − out` 的**恒定小差值不是丢样**，它等于 PL 流水线里在途的样点数。

# 六、和真实 CCSDS 的差距

本实现是**教学/验证用的简化子集**。要用到真实航天任务上还需要：

| 缺什么 | 标准 | 影响 |
|---|---|---|
| 传输帧（TM/TC Transfer Frame） | CCSDS 132.0-B / 232.0-B | 没有帧头、虚拟信道、帧计数 |
| 遥控段（CLTU）+ BCH 编码 | CCSDS 231.0-B | 空口误码保护不足，只有 CRC 检错没有纠错 |
| 空间包分段 | 序列标志 01/00/10 | 大数据（如频谱）无法跨包 |
| 时间码 | CCSDS 301.0-B | 没有统一时基，多普勒与遥测时间戳不可审计 |
| 加密/认证 | SDLS | 任何人都能发遥控 |
| 命令鉴权与回滚 | — | 错误参数会直接生效 |

**要演示"简化版 CCSDS"够用；要声称"符合 CCSDS"就需要补齐传输帧和 CLTU。**
